## 왜
사용자가 게임 저장소를 공개로 돌리고 싶어 한다. 이력에 개인정보가 남으면 안 된다.

## 10-18 조사 결과 (git log -p --all, LFS 제외 5.9MB)
- API 키 · 토큰 · 사설 IP · 비밀번호 : 0건. 키는 환경변수 규칙이 지켜졌다.
- 윈도 계정 이름이 든 절대 경로 : 61줄. Docs/Reference/Art 의 build_screens 스크립트 3개와 점검 JSON 7개, 옛 문서 몇 개.
- 미니PC ssh 별칭 : 6줄 (로컬 LLM 접근 설명).
- 참고 자료에서 따온 남의 메일 주소 : 1줄.
- commit-prep 훅이 잡는 186건은 게임 낱말(찹쌀이·mozzi…)이다. 그 목록은 툴 저장소용이라 게임 저장소 공개와 무관하다.

## 하기로 한 길 (3안)
1. 사용자가 GitHub 에 빈 새 저장소를 비공개로 만든다 (README 없이).
2. python -m git_filter_repo 로 위 셋을 바꾼다. git 서브커맨드 filter-repo 는 PATH 에 없고 pip 모듈만 있다.
3. 새 저장소로 push 하고 훅으로 다시 훑은 뒤 공개로 돌린다. 옛 저장소는 비공개로 두거나 지운다.
4. 옛 커밋 해시를 적은 문서(변천사 영상 문서의 v12~v16 해시 등)는 filter-repo 대응표로 고친다.
