왜 : 09-18 가결 때 AI 가 64 초안을 48 로 권해 48 로 정했는데, 09-20 에 찹쌀이 원본 픽셀판(Docs/Reference/Art/찹쌀이/Front.png 등 4방향)이 64×64 인 것을 확인했다. 참고 그림과 크기를 맞추는 쪽이 낫다고 사용자가 판단했다. 이 기억은 20260918-87c39e6e 를 덮으며 그 건의 나머지 값을 그대로 옮겨 담는다.
무엇 : 2026-09-20 사용자 결정 — 찹쌀이 64×64 (64 캔버스에 꽉 채워 그린다). 게임 안에서 더 작게 보여야 하면 코드에서 줄여 찍는다 (지금 LayoutConst.cs 는 단계별 40/48/56px). 그림을 다시 그리지 않는다.
09-18 에서 그대로 가는 값 : 기준 해상도 360×640 (같은 폰을 ×3 으로 채움) · 타일 32 (Unity PPU 32) · 외곽선 없음 + 명암 평면 · 빛 왼쪽 위. 그림 갈래 픽셀아트 · 낮은 탑다운(3/4) · 베이스는 AI(PixelLab) 도 09-13 가결 그대로다.
정수 배율 예외 : 아트 규칙의 「배율은 정수 배만」에서 찹쌀이만 예외가 된다. 64 를 40/48/56 으로 줄이면 배율이 0.625/0.75/0.875 다. AI 가 「정수 아닌 배율은 Point 필터에서 픽셀이 뭉개질 수 있다」고 짚었으나 사용자가 「그렇게까지 안 뭉개질 것 같다 — 보고 문제 있으면 그때 고친다」로 정했다.
뒤집는 조건 : 첫 한 마리를 Unity 에 넣어 40/48/56px 로 줄인 모습을 눈으로 보고 다시 판단한다. 뭉개 보이면 그때 고친다. 외곽선은 09-18 조건 그대로 — 360×640 폰 시뮬 위 밝은 바닥에서 배경과 붙어 보이면 색 1px 외곽선으로 바꾼다.
곁들여 : 사용자가 원본 이모티콘 시트 Docs/Reference/Art/찹쌀이/찹쌀이이모티콘.jpg 를 넣었다. 찹쌀이는 가로로 살짝 넓은 흰 떡 덩어리 · 양쪽 큰 노란 볼 · 오른쪽 위 비스듬한 작은 노란 왕관(뿔 3) · 점 눈 · 팔다리 없음. 64px 4방향 픽셀판이 그 특징을 옮긴 것이다 (외곽선 없음).
남은 것 : 팔레트 · 방향 수 · 애니 최소는 기획 뒤로 미룬 상태 그대로다. 찹쌀이 원본 색값 뽑기(todo 20260909-ddb748e2)도 아직이다. ArtTool 프로필의 canvas.frame 은 48 로 적힌 초안이라 프로필을 실제로 만들 때 64 기준으로 다시 잡는다.
