왜 : 스프레드시트를 안 쓰기로 해서 수치·밸런스를 어디에 담고 어떻게 볼지 정해야 했다.

무엇을 : 데이터 형식(JSON·TOML·CSV·SQLite), 기존 편집 툴(CastleDB·Game Balance Editor·LDtk·Machinations), 그래프 라이브러리(Chart.js·uPlot·Vega-Lite·Plotly), 브라우저에서 파일 고치기의 제약, 밸런스 자동 검증 방법을 훑었다. 출처 44개.

정한 방향 : 데이터는 Data 폴더의 JSON 여러 파일 + JSON Schema. 곡선은 값 대신 식과 검산점으로 적는다. Unity 는 Newtonsoft 로 읽는다. 보기는 CLI 가 굽는 자기완결 HTML 한 장(Chart.js). 고치기는 웹에서 안 하고 AI 가 JSON 을 직접 고친다 — File System Access API 는 Firefox·Safari 에서 막히고 file:// 에서는 아예 안 된다. 잃는 즉시 재계산 손맛은 대시보드의 읽기 전용 슬라이더 미리보기로 메운다.

다음에 : 실제 수치가 생기는 기획 8단계(04-수치표) 전에는 툴을 안 만든다. 툴은 총 3일을 넘기면 멈춘다. 프로토타입 갤러리·단계 대시보드와 HTML 굽는 뼈대가 같으니 툴 하나에 페이지 셋으로 합칠지는 그쪽 조사가 끝난 뒤 정한다. DiagramTool 과는 입력이 문서냐 데이터냐로 갈리니 안 합친다.
