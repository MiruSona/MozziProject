왜 : 사용자가 게임 기획을 해 본 적이 없어서, 코드의 디자인 패턴처럼 기획에도 정해진 순서·구조·기법이 있는지 알고 싶어 했다.

무엇을 : 출처 20여 곳을 보고 Docs/Research/2026-09-06-기획순서와기법조사.md 를 썼다 (263줄). 담은 것 — 기획 순서(컨셉 → 기둥 → 코어 루프 → 종이·거친 프로토타입 → 검증 → 세로 조각 → 확장), 문서 구조(두꺼운 GDD 대신 한 장 기획 → 열 장 → 살아 있는 문서), 프레임워크(MDA, 코어/메타 루프, Schell 의 렌즈와 엘리멘탈 테트라드, Theory of Fun, Flow, Bartle, Quantic Foundry, Machinations), 패턴·기법(Bjork & Holopainen 의 게임 디자인 패턴, 원천-변환-배수구 경제와 Lost Garden 의 가치 사슬, 진행 곡선과 보상 표, 난이도 곡선, 튜토리얼), 규모 자르기(MoSCoW·최소 재미 단위·시간 상자), 농장·수집·합성 장르의 하루 주기와 뽑기 천장 규칙.

다음에 : 문서 마지막의 뼈대 제안대로 Docs/Design/00-컨셉.md 부터 쓴다. 1~3번 문서(컨셉·코어 루프·기능 목록)를 합쳐 A4 두 쪽을 넘기지 않는다.

못 찾은 것 : 시스템 상호작용 표의 정식 이름, 코어/메타 루프의 학술 정의, Rami Ismail 글 원문(403), Quantic Foundry 의 12개 동기 이름(403).
