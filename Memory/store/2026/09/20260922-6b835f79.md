effort estimate 의 본줄 예상에 서브에이전트가 도는 시간을 약 2~5배(한 판 10~20분)로 따로 어림해 공수 표에 둘 다 적는다. (2026-10-03 에 옛 눈금 「5~10배」를 고쳤다)
왜 : 2026-09-22 진열대 칸 판에서 예상 합 15분 대 본줄 실제 4분, 서브 참고 18분이었다. 본줄만 적으면 표가 안 맞는다.
왜 고쳤나 : 2026-10-03 반복 02 에서 10배로 잡았더니 예상 50·50·40·60·40분 대 서브 실제 21·11·15·21·15분이었다. 첫 판에서 컴파일·그림이 바로 통과한 것도 한몫했다.
1. 'Tools/EffortTool/bin/effort.exe estimate 조사:M 구현:L …' 로 본줄 예상을 뽑는다.
2. 소단계마다 서브 참고값을 조사 4~7분 · 설계서 5분 · 그림 한 묶음 약 10분 · 정리+APK 빌드 약 15분 · 새 화면 코드 약 20분 눈금으로 어림해 「본줄 N분 · 서브 약 M분」 으로 적는다.
3. 서브에이전트는 'effort mark start/stop' 으로 자기 판을 재고 그 기록 구간을 실제 칸에 쓴다 (서브 벽시계보다 1~2분 짧게 나온다). mark 가 없으면 'effort scan' 뒤 'effort show ‹id›' 의 서브 칸으로 채운다.
