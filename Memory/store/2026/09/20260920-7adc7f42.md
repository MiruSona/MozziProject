왜 : 09-20 에 같은 에디터를 두 세션이 나눠 쓰며 WebGL 빌드를 다섯 번 돌렸다. 같은 자리에서 여러 번 헛돌았다.
무엇을 : 하나. eval 과 eval_file 은 메인 스레드 5초 상한이라 긴 작업은 exit 6 으로 돌아오지만 에디터 안에서는 계속 돈다. Editor.log 로 끝을 본다. 둘. 전역 옵션 format 과 timeout 은 명령 이름 앞에 둔다. 셋. capture_game_view 는 프로젝트 밖 경로를 거절하고 Assets/Temp 로 조용히 바꿔 저장해 meta 찌꺼기가 생긴다. 넷. get_console_logs 는 1000건에서 잘려 폭주 건수를 못 센다. Editor.log 바이트 구간으로 센다. 다섯. 빌드가 도는 4~8분 동안 다른 세션의 명령이 30초 시간 초과된다.
다음에 : 빌드 전에 isBuildingPlayer 와 Play 상태를 eval 로 읽고 다른 세션에 알린다. Play 중 찹쌀이를 SetActive false 로 숨기지 않는다. 상태를 바꾸는 eval 은 Debug.Log 한 줄을 남긴다.
