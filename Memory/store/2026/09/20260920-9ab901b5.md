왜 : 폰에서 받는 시간이 병목이라 런타임 속도보다 받는 양이 급하다고 사용자가 정했다. 기억 20260920-a6b63d57 이 DiskSize 가 실은 wasm 을 0.39MB 줄이고 있었다고 적어 둔 대로 되돌렸다.

무엇을 : WebGlBuild.ApplySettings 의 codeOptimization 한 줄을 RuntimeSpeed 에서 DiskSize 로 바꿨다. 다른 설정은 그대로 두고 같은 판에서 다시 빌드했다.

결과 : 받는 양 합계가 13,575,250 에서 13,178,054 바이트(12.57MB)로 397,196 바이트 줄었다. 파일별로는 wasm 9,176,987 → 8,780,874, 자료 4,211,322 → 4,210,186, framework 76,597 → 76,650, loader 110,344 그대로다. 빌드는 Succeeded · 오류 0 · 경고 1 이고 ProjectSettings 는 webGLDataCaching 한 줄만 바뀐 채다. 기억 20260920-1a227be9 의 합계 13,575,250 은 이제 옛 값이다.

다음에 : 폰에서 실제로 느려지는지 본 다음 정한다. 런타임 속도가 문제되면 그 한 줄만 RuntimeSpeed 로 되돌린다. 남은 큰 것은 엔진 wasm 8.78MB 와 Unity 스플래시다.
