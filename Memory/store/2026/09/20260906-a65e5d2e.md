웹 게임 라이브러리 8종·숫자 프로토타입 방식·묶음 구조·AI 사례·Unity 연결·만들까 살까를 훑었다.

- 우리 물음(합성 확률·골드·시간)은 숫자라 그림 엔진이 필요 없다. 단일 HTML 파일 + 순수 JS 가 기본이고, 네모가 움직여야 할 때만 LittleJS 를 CDN 한 줄로 얹는다. Kaplay 는 로컬 파일로 못 열고 Phaser 는 버릴 코드에 과하다.
- 프로토타입마다 물음·판정 기준을 proto-meta JSON 덩이로 파일 안에 박고, 기록은 localStorage 에 모아 JSON 으로 내보낸다. 목록은 Prototypes/index.html 하나.
- 새 툴(ProtoTool)은 안 만든다. 템플릿 한 장과 목록 페이지까지가 이번 몫이고, 같은 일을 세 번 손으로 한 뒤에 Go CLI 로 승격한다.
- 위험 셋 : 손맛·조작감 물음은 웹으로 답이 안 나니 Unity 버릴 씬으로 간다. 여러 개를 한꺼번에 만들면 LLM 이 같은 데로 모이니(모드 붕괴) 물음 축을 사용자가 먼저 다르게 못 박고 프로토타입마다 서브에이전트를 따로 쓴다. 툴 만들기가 게임을 잡아먹는 것도 흔한 실패다.

다음 : 기획절차 4단계에서 물음을 적을 때 「답이 숫자인가 손끝인가」 칸을 하나 더 둔다.
