폰(LTE)에서 아티팩트에 올린 WebGL 빌드가 받는 도중 자꾸 멈췄다. v5~v10 열 판을 돌려 풀었다.

**푼 방법 (Version 10 에서 통했다)** : 받는 일을 Unity 로더에 맡기지 않고 페이지가 직접 한다. 파일을 **한 개씩 순서대로** 받고, **30초 동안 한 바이트도 안 늘면 끊어 그 파일만 다시** 받는다 (최대 6번). 그렇게 브라우저 캐시를 채운 뒤 로더에게는 **같은 주소를 그대로** 준다. 로더는 캐시에서 집어간다.

**올라간 파일은 멀쩡했다.** 아티팩트에서 도로 받아 SHA-256 을 로컬 빌드와 대조해 세 파일 모두 일치를 확인했다. 게시 과정이 깨뜨리는 것이 아니다.

**Unity 로더에는 재시도가 없다.** 큰 파일 셋을 동시에 받다가 하나가 끊기면 그대로 영영 멈춘다. 이것이 진짜 원인이었다. 회선이 약하면 8MB 급이 자주 끊긴다.

**받은 것을 `blob:` 주소로 Unity 에 넘기는 길은 막혀 있다.** 아티팩트 보안 정책의 `connect-src` 가 blob 을 거부한다. Unity 는 「파일이 깨졌다」고 말하지만 파일 문제가 아니다. 그래서 blob 이 아니라 캐시를 채우는 방식으로 돌아갔다.

**진행률 30% · 60% 는 바이트가 아니라 파일 개수다.** 로더 계산식이 `0.9 × (파일수 − 길이를_모르는_미완료_파일수) / 파일수` 라서, 서버가 Content-Length 를 안 주면 0 / 30 / 60 / 90% 네 값만 나온다. 30% 는 「셋 중 하나만 받아졌다」는 뜻이다.

**받은 양은 파일 주소가 아니라 설정 키 이름으로 담긴다.** `config.downloadProgress` 의 열쇠가 `"dataUrl"` · `"codeUrl"` · `"frameworkUrl"` 이다. 주소로 찾으면 영영 0 이 나온다.

**파일 이름을 바꿔 올릴 때는 페이지 안의 주소를 전부 바꿔야 한다.** 다섯 군데(로더 src · dataUrl · frameworkUrl · codeUrl · 진행표시)다. 한 곳에 상수로 모아 둔다 — 세 군데만 고쳐 한 판을 버렸다.
