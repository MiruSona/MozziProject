왜 : 가판대 설계 물음 8개를 다 푼 뒤, 손님 주문·떡메 치기 과정·첫 방치 셋을 사람 손으로 재려고 5단계 3판 프로토를 만들었다. 결정 9건(재료·레시피·판매·떡 값·제작·눈금·설비·화면·부드러운 안)의 임시 눈금을 그대로 코드에 옮겼다.

무엇을 : HTML 한 파일(568줄)이다. 세로 400px 안에 가판대 화면 하나(진열대·손님 줄·만들기·실험·도감·농장 뼈대·설비)를 담았다. 부재료 6종·레시피 10개(1개짜리 6·2개짜리 3·3개짜리 1)로 24칸 결정의 비율만 줄여 넣었다. 화면 위에 「과정 있음/없음」 스위치와 「2분 재기」 버튼을 두어 q3-2 의 두 판을 한 파일에서 잰다. 자동 판정 표와 JSON 내보내기는 q2 프로토 꼴을 그대로 이었다.

함정 하나를 고쳤다 : q2 의 「자리 비우기」가 실제 시간 기준이라 배속 10 에서 뜻이 없었는데(20260909-b590599c), 이번엔 게임 시간 5분을 건너뛰는 것으로 셈한다. 봇으로 게임 20분을 돌려 코어를 확인했다 — 레시피 10개 다 찾음, 주문 맞춤 62%, 점원 5분 18초, 힌트로 2개 발견. 점원 없이 자리를 비우면 줄 5명이 차고 판매 0 으로 멈춘다(q3-3 이 재려는 바로 그 장면).

다음 : 사용자가 「10분 판 → 과정 없음 2분 → 과정 있음 2분 → 점원 없이 자리 비우기 → 점원 사고 자리 비우기」 순서로 놀고 결과.md 를 채운다. stage 에 q3-1·q3-2·q3-3 을 등록했다.
