# 진열대 떡 묶음 칸 설계 (2026-09-22)

가판대 화면의 진열대를 **글자 한 줄에서 떡 그림이 든 묶음 칸**으로 바꾸는 설계다.
사용자가 2026-09-22 에 정한 것(mem `20260922-ec7fcb9b`)을 그대로 따르고, 여기서는 치수·셈법·코드 자리만 정한다.
코드는 아직 안 고쳤다.

## 한 줄 결론

- 칸 **40×40 · 사이 3px · 한 줄 8칸 × 3줄**을 지금 `ShelfText` 자리(8, -60)에 놓는다. 구역 높이는 **126px**.
- 「진열대 N/상한」 머리글은 칸 위에 따로 두지 않고 **`StatusText` 한 줄 끝에 붙인다** (`오늘 손님 3/10 · 열림 · 진열 12/30`).
  따로 두면 아래 위젯이 `ButtonStrip` 을 2px 넘친다.
- 아래 위젯(`QueueCell_*` 부터 `ExpMakeButton` 까지)은 **86px** 내린다. `ButtonStrip` 은 그대로. 내리고도 16px 남는다.
- 묶음 단위는 **`unit = ceil(ShelfMax / 6)`** = `(ShelfMax + 5) / 6`. 30→5 · 50→9 · 80→14 · 120→20.
  종류 11 최악 칸 수는 **16** 이라 24칸 자리에 든다.
- 만드는 방식은 손님 칸과 같은 세 겹 : `UiNames` → `LayoutConstUi` → `ShelfCellSetup` 메뉴(멱등) → `StallScreen` 배선.

## 1. 왜 바꾸나

지금 진열대는 `StallScreen.RefreshShelf()` 가 `"진열대 12/30\n팥떡×3  콩떡×9"` 한 줄 글자를
`ShelfText` 에 넣는 것이 전부다. 종류와 수는 읽히지만 **쌓인 양이 눈에 안 보인다.**
떡 그림 11장이 09-21 에 들어왔으니 진열대도 그림으로 보여 준다.

### 사용자가 정한 것 (바꾸지 않는다)

| 물음 | 정한 것 |
| --- | --- |
| 칸의 뜻 | 떡 (진열 상한 ÷ 6)개 묶음 하나. 상한 30 이면 5개, 120 이면 20개. 종류마다 묶음 칸이 이어 뜬다 (팥떡 12개 → 5·5·2 세 칸) |
| 칸 배치 | 40×40 · 한 줄 8칸 × 3줄 = 24칸 자리를 프리팹에 만들고, 있는 칸만 켠다 |
| 칸 표시 | 떡 그림 32px 원본 + 그 칸의 개수 (×5, ×2) 오른쪽 아래 작은 글자 |
| 순서 | 레시피표(`Recipe.json`) 순서, 평범한 떡은 맨 뒤 |
| 버리기/비우기 · 상한 업그레이드 | 이번엔 제외 (API·기획서 반영이 먼저) |
| 만드는 방식 | 손님 칸과 같은 세 겹 : UiNames 상수 → LayoutConstUi 치수 → Editor Setup 메뉴(멱등) → StallScreen 코드 배선 |

## 2. 화면 설계

기준 화면 360×640, 프리팹 `Resources/Prefabs/UI/StallScreen.prefab`, 좌상단 기준(y 음수가 아래).

### 2-1. 진열대 구역

| 항목 | 값 | 까닭 |
| --- | --- | --- |
| 칸 크기 | 40×40 | 정한 것 |
| 칸 사이 | 3px (가로·세로 같음) | 8칸 × 40 + 7 × 3 = **341** ≤ 344 (`ShelfText` 폭). 4px 면 348 이라 오른쪽 여백 8 을 깬다 |
| 열 · 줄 | 8 × 3 = 24칸 | 정한 것 |
| 구역 왼쪽 위 | (8, -60) | 지금 `ShelfText` 자리 |
| 구역 폭 · 높이 | 341 × **126** | 3 × 40 + 2 × 3 = 126 |
| 줄 y | -60 · -103 · -146 | 40 + 3 씩 |
| 구역 아래 끝 | -186 | -146 - 40 |
| 칸 뿌리 | `Image` (옅은 판 색, raycast 끔) | 손님 칸처럼 칸 테두리가 보이게. 누르는 일은 이번에 없어 `Button` 은 안 붙인다 |
| 떡 그림 | `Icon` 32×32, 칸 왼쪽 위 (4, -4) | 원본 32px 그대로 (×1). 40 안에 넣으면 사방 4px 남는다 |
| 개수 글자 | `CountText` 22×12, 칸 오른쪽 아래 구석 (-1, 1), 글자 10, 오른쪽 맞춤 | 「×5」 두세 글자. 떡 그림 오른쪽 아래를 살짝 덮는 것이 의도다 |
| 형제 순서 | `Icon` → `CountText` | 뒤가 위로 온다. 글자가 그림 위에 보여야 한다 |

칸 하나의 위치 식 : `x = 8 + (i % 8) × 43`, `y = -60 - (i / 8) × 43` (i 는 0~23).

### 2-2. 머리글 「진열대 N/상한」 — StatusText 끝에 붙인다

둘을 비교했다.

| 안 | 자리 | 아래로 내릴 px | ExpInfoText 아래 끝 | 판정 |
| --- | --- | --- | --- | --- |

②로 간다. `StatusText` 는 344×20 이라 스무 글자 남짓은 넉넉히 든다.
`ShelfText` 는 지우지 않고 **꺼 둔다** — 칸이 없는 옛 프리팹에서 글자판으로 돌아가는 길을 남기려는 것이다.

## 3. 묶음 셈법

### 3-1. 단위

`unit = ceil(ShelfMax / 6)`. 정수로는 `(ShelfMax + 5) / 6`.

| 상한 | 내림 `ShelfMax / 6` | **올림 `(ShelfMax + 5) / 6`** |
| --- | --- | --- |
| 30 | 5 | **5** |
| 50 | 8 | **9** |
| 80 | 13 | **14** |
| 120 | 20 | **20** |

**올림을 고른다.** 사용자가 든 보기(30→5 · 120→20)는 둘 다 맞지만, 올림이라야 한 종류를 상한까지 채워도
칸이 **꼭 6개 이하**가 된다 (내림이면 50 → 8 × 6 = 48 이라 7칸이 필요하다).

종류 하나가 k 개면 칸 수는 `ceil(k / unit)`, 마지막 칸 개수는 `k - (칸 수 - 1) × unit` 이다. 팥떡 12개, unit 5 → 5 · 5 · 2.

### 3-2. 최악 칸 수 (종류 11 = 레시피 10 + 평범한 떡)

칸이 가장 많아지는 배치는 **종류마다 1개씩 먼저 놓고(11칸), 남은 떡을 한 종류에 unit 개씩 더 얹는** 것이다.
`최악 = 11 + floor((ShelfMax - 11) / unit)`.

| 상한 | unit | 남은 떡 | 더 생기는 칸 | **최악 칸 수** | 24칸에 드나 |
| --- | --- | --- | --- | --- | --- |
| 30 | 5 | 19 | 3 | **14** | 든다 |
| 50 | 9 | 39 | 4 | **15** | 든다 |
| 80 | 14 | 69 | 4 | **15** | 든다 |
| 120 | 20 | 109 | 5 | **16** | 든다 |

상한이 얼마든 `ShelfMax / unit ≤ 6` 이라 더 생기는 칸은 5 를 못 넘고, 종류 11 이면 **최악 16** 이다.
그래도 코드는 24 를 넘으면 그 뒤는 그리지 않고 경고만 남긴다 (종류가 늘어도 안 터지게).

개수 글자는 `StallShelfCountText = "CountText"` 로 새로 둔다 — 값은 도감·보관함의 `CountText` 와 같지만

### 4-3. `ShelfCellSetup` (Editor)

- 메뉴 `Mozzi/진열대 칸 만들기`, `ShelfCellSetup.Apply()`. 꼴은 `CustomerLayerSetup` 을 그대로 따른다.
- **멱등 판정 : `ShelfCell_0` 이 이미 있으면 「이미 만든 프리팹」** 이라 아래 위젯을 또 내리지 않는다.
  칸 24개는 있으면 자리만 다시 맞추고 없으면 만든다 (find-or-create). 두 번 돌려도 같은 자리.
- 칸은 `ShelfText` 와 같은 부모 아래, `ShelfText` **바로 다음 형제**로 넣는다. `ShelfText` 는 `SetActive(false)`.
- 이동 목록 = `CustomerLayerSetup.ShiftNames` + `MakeRow_*` + `ExpToggle_*` **+ `QueueCell_0~4`** (손님 Setup 이 빠뜨린 것).
  `ButtonStrip` 은 안 건드린다.
- 실행 순서 : `CakeIconSetup` → `CustomerLayerSetup` → **`ShelfCellSetup`**. 내리는 값은 상대값이라 앞 둘과 순서가
  섞여도 자리는 같지만, 손님 칸이 다 된 프리팹 위에 도는 것이 확인하기 쉽다.
  `CakeIconSetup` 은 진열대 칸을 만지지 않는다 — 떡 `Icon` 은 `ShelfCellSetup` 이 직접 만든다 (두 Setup 이 한 물건을 만지지 않게).

```text
static void Apply()                                        // 메뉴 진입
static void MakeCell(Transform parent, int index)          // 칸 뿌리 + Icon + CountText, find-or-create
static void ShiftLowerWidgets(Transform root)              // QueueCell 포함
```

### 4-4. `ShelfCellView` (Game/Ui)

```text
public sealed class ShelfCellView
{
    public readonly bool HasParts;                         // Icon 과 CountText 둘 다 있나
    public ShelfCellView(Transform cellRoot);
    public void Set(Sprite sprite, int count);             // 그림 끼우고 「×count」 쓰고 켠다
    public void Hide();                                    // 칸 뿌리를 끈다
}
```

`CustomerCellView` 와 같은 꼴이다. 스프라이트가 `null` 이면(아직 안 구운 그림) `Icon` 만 꺼지고 개수는 남는다.

### 4-5. `StallScreen`

```text
private readonly List<ShelfCellView> _shelfCells;          // 0개면 옛 글자판
private static int ShelfUnit(int shelfMax);                // (shelfMax + 5) / 6
private void RefreshShelf();                               // 칸이 있으면 RefreshShelfCells, 없으면 옛 글자 그대로
private void RefreshShelfCells(IReadOnlyList<RecipeRow> rows, Dictionary<string, int> counts, int plain);
private int FillCells(int cellIndex, Sprite sprite, int count, int unit);   // 한 종류를 묶음 칸으로 펼치고 다음 index 를 돌려준다
```

- `BindChildren` : `UiBindUtil.TryFind` 로 `ShelfCell_0~23` 을 찾아 `_shelfCells` 에 담는다. 하나도 없으면 비워 두고
  **옛 글자판(`ShelfText`) 으로 돌아간다** — `QueueCell` 과 같은 되돌림 규칙이다.
- `RefreshShelf` 의 세는 부분(종류별 `counts`, `plain`)은 그대로 두고, 그리는 부분만 갈라 낸다.
  레시피표 순서로 `FillCells` 를 부르고 평범한 떡은 맨 뒤 (`SpriteKeys.CakePlain`). 남은 칸은 `Hide`.
- `RefreshStatus` 끝에 `" · 진열 " + Shelf.Count + "/" + ShelfMax` 를 붙인다. `Refresh()` 가 둘을 잇달아 부르니 따로 잇지 않는다.
- 24칸을 넘기면 `Debug.LogWarning` 하고 멈춘다.

## 5. 확인 방법

| 무엇 | 어떻게 | 기대 |
| --- | --- | --- |
| 멱등 | 메뉴를 두 번 돌리고 `QueueCell_0` · `ExpMakeButton` y 를 본다 | -190 · -506 그대로 |
| 칸이 는다 | Play 에서 떡 하나 만든다 | 칸 하나에 그림 + ×1 |
| 묶음이 갈린다 | 같은 떡 12개 (디버그 채우기 뒤 수 맞추기) | 5 · 5 · 2 세 칸 |
| 팔면 준다 | 손님에게 판다 | 마지막 칸 수가 하나 줄고 0 이면 칸이 꺼진다 |
| 순서 | 여러 종류 + 평범한 떡 | 레시피표 순서, 평범한 떡 맨 뒤 |
| 최악 배치 | 종류 11 을 1개씩 + 한 종류 19개 (상한 30) | 14칸, 두 번째 줄까지. 넘침 경고 없음 |
| 겹침 | 아래 위젯과 `ButtonStrip` | `ExpInfoText` 아래 16px 남음, 글자판 fallback 없이 칸이 보임 |
| 옛 프리팹 | 칸 없는 프리팹으로 Play | 글자판이 그대로 뜨고 오류 없음 |

## 6. 못 정한 것 · 나중 일

- **버리기 / 비우기** — `IStallHub` 에 API 가 없다. 기획서 반영(①-1) 뒤에 따로 설계한다.
- **상한 업그레이드** (30 → 50 → 80 → 120) — `04-수치표.md` 임시값, 1판 제외. 되면 unit 이 자동으로 바뀌므로 칸 코드는 그대로다.
- **칸을 누르면 무엇이 되나** — 정하지 않았다. 지금은 `Button` 을 안 붙인다. 버리기가 들어오면 그때 함께.
- **기획서 반영할 것** — `03-시스템-가판대.md` 「진열대」 절에 「묶음 칸 · unit = ceil(상한 ÷ 6) · 8×3 자리 · 진열 수는 상태 줄에」 를 더한다. 이번 설계서에서는 안 고쳤다.
- 개수 글자 10px 가 폰에서 읽히나는 실측으로 본다. 안 읽히면 `CountText` 를 12px 로 키우고 폭 26 으로.
