## 0. 결론 먼저

**켜면 쌓인 재료를 줍고, 합성 결과를 받아 농장에 놓고, 재료로 떡을 만들어 가게를 열어 손님 10명에게 팔면 밤이 되고, 골드를 쓰고 「다음날로」를 누르면 한 바퀴다.** 이것을 Unity 씬 하나 · CodeTool 7층 뼈대 · JSON 데이터로 만들고, 사용자가 직접 켜서 끝까지 해 본 뒤 아래 표에 답을 적는다.

| 판정 | 무엇을 보나 | 통과 기준 |
| --- | --- | --- |
| 한 바퀴 | 첫 켜기 → 「다음날로」까지 설명 없이 간다 | 막힌 곳 0 (막히면 어디서 · 왜 한 줄) |
| Q16 화면 알아보기 | 농장에 20마리일 때 원하는 한 마리를 찾는다 | 3번 시켜서 3번 다 **3초 안** |
| Q17 손맛 | 재료 줍기 · 합성 완료 받기가 기분 좋은가 | 예/아니오 + 근거 한 줄 |
| 새 떡 발견 연출 (기능목록 38) | 떡메 마지막 타격 → 도감 칸이 열리는 순간 | 예/아니오 + 근거 한 줄 |

통과가 아니면 본 제작(9단계)으로 안 넘어간다. 되돌아가는 것이 손해가 아니다 (`Docs/Guide/기획절차.md` 8단계 함정).

## 2. 하루 한 바퀴 흐름

첫 켜기부터 「다음날로」까지. 오프라인 계산은 **0단계(켜기)에서 한 번만** 돈다.

| # | 사용자 행동 | 화면 | 걸리는 시스템 | 걸리는 값 (수치표 열 이름) |
| --- | --- | --- | --- | --- |
| 0 | 켠다 | 농장 화면. 세이브가 있으면 「돌아왔어요」 팝업(쌓인 재료 · 끝난 합성 · 태어난 마릿수 · 팔린 떡) | `SaveManager` 읽기 → `ClockManager` 가 안 켠 초를 계산 → 농장 · 합성소 · 가판대가 각자 그만큼 진행 | `Farm.producePeriodSec` · `Farm.breedPeriodSec` · `SynthesisRule.waitSec` · `Stall.clerkSpeedSec` |
| 0' | (첫 켜기) | 흰찹쌀이 2마리 · 골드 0 · 합성소 열림 | `FarmManager` 시작 상태 | `Farm.startSpeciesId` · `Farm.startCount` |
| 1 | 바닥에 쌓인 재료 더미를 탭해 줍는다 | 농장 화면 — 더미가 창고로 날아가고 자원바 숫자가 오른다 | `FarmManager` → `InventoryManager` | `Ingredient.cap` (100) |
| 2 | 합성소 건물 위 알림을 눌러 결과를 받는다 | 합성소 화면 — 결과 연출 → 새 찹쌀이가 보관함으로 | `SynthesisManager` → `StorageManager` · `CodexManager`(처음이면 도감 열림) | `SynthesisRule.pFixed/pOtherFamily/pShiny` |
| 3 | 보관함에서 농장에 놓는다 (담장 20 안) | 보관함 화면 → 농장 화면 | `StorageManager` → `FarmManager` | `Farm.fenceMax` |
| 4 | 가판대 건물을 눌러 떡을 만든다 · 새 조합을 실험한다 (떡메 3탭) | 가판대 화면 — 만들기 · 실험 · 발견 연출 | `StallManager`(제작) → `CodexManager`(레시피 도감) | `Recipe.*` · `Stall.poundTaps` · `Stall.shelfMax` |
| 5 | 「열기」 | 가판대 화면 — 손님이 5초마다 줄에 선다 | `StallManager` | `Stall.customerGapSec` · `Stall.queueMax` · `Stall.customersPerDay`(10) |
| 6 | 손님을 탭해 판다 (점원이 있으면 자동) · 사이사이 만들기 | 가판대 화면 — 주문 맞으면 ×1.5 · 5명 중 1명은 못 찾은 떡 주문(힌트) | `StallManager` → `WalletManager` | `Stall.orderMult` · `Stall.hintEvery` · `Ingredient.value` · `Stall.countMult` |

| 8 | 골드를 쓴다 — 합성 걸기 · 칸 · 영구 단축 · 짝 구매 · 점원 | 합성소 · 도감 · 가판대 화면 | `SynthesisManager` · `CodexManager` · `StallManager` → `WalletManager` | `SynthesisRule.gold` · `Growth.slotPrice` · `Growth.shortcutPrice` · `Growth.pairPrice` · `Stall.clerkPrice` |

- 오프라인 계산 순서는 **농장(생산 · 번식) → 합성소 → 가판대(점원 판매)** 다. 가판대는 「열려 있고 점원이 있을 때」만 진행하고, N명이 차면 그 자리에서 밤이 된다 (방치 수입이 N 에 묶이는 문제는 알고 두는 것, 진행상황 46줄).
- 밤은 **연출과 상태**다. 농장 · 합성 · 번식 시계는 안 건드린다 (`03-시스템-가판대.md` 6절, 첫 판).
- 「다음날」은 실제 시간에 안 묶인다. 연타해도 떡이 없으면 팔 게 없다.

## 3. 화면 — 세로 9:16 한 화면

기준 해상도 **360×640** (mem `20260918-87c39e6e`). Game 뷰는 9:16 고정. 단위는 그 기준의 px 다.

### 3-1. 화면 전환 규칙

| 규칙 | 내용 |
| --- | --- |
| 바탕 | **농장 화면이 바탕**이다. 항상 밑에 있다 |
| 덮개 | 합성소 · 가판대 · 도감 둘 · 보관함은 **농장 위에 덮이는 전체 화면 패널**이다. 한 번에 하나만 열린다 |
| 여는 법 | 합성소 · 가판대는 농장의 **건물을 누르면** 열린다. 도감 · 보관함은 아래 띠의 버튼. 레시피 도감은 가판대 화면의 「레시피 도감」 버튼으로도 연다 |
| 닫는 법 | 패널 위쪽 「닫기」 → 농장으로. 패널끼리 바로 옮겨 다니지 않는다. 예외 하나 : 가판대 → 레시피 도감은 가판대를 닫고 바로 연다 (구현에서 정함, 2026-09-23 판정 뒤 반영) |
| 열림/닫힘 | 가게의 열림 · 닫힘 · 밤은 **화면이 아니라 상태**다. 가판대 화면을 닫고 나가도 손님은 계속 온다 (점원 없으면 줄 5명에서 멈춤) |
| 시계 | 어느 화면이 열려 있어도 생산 · 합성 · 손님 시계는 돈다 |

- Q16 을 위해 **한 화면에 20마리가 겹치지 않게** 둔다. 찹쌀이 48px 이면 424px 높이에 20마리는 넉넉하다. 겹치면 서로 밀어낸다.
- 플레이스홀더 : 종은 **계열 색(잔디 초록 · 물 파랑 · 용암 주황) + 단계는 밝기 · 크기(40/48/56)** · 변종은 테두리 반짝임. 흰찹쌀이만 임시 그림.
- 줍기 반응 : 더미가 자원바로 날아가는 짧은 이동 + 숫자 튀기 (Q17).

## 4. 씬 · 코드 구조

### 4-1. 씬은 하나

**씬 하나(`Farm.unity`) + 화면은 UI 패널 켜고 끄기**로 간다.

| 고른 까닭 | 내용 |
| --- | --- |
| 시계가 하나 | 어느 화면에서도 생산 · 합성 · 손님 시계가 돌아야 한다. 씬을 나누면 Manager 를 옮기거나 DontDestroyOnLoad 로 빼야 한다 |
| 전환이 잦다 | 농장 ↔ 합성소 ↔ 가판대를 한 접속에 여러 번 오간다. 씬 로드는 느리고 상태를 잃기 쉽다 |
| Hub 규칙 | 2차 설계 5장 「두 Hub 걸치기 금지」. 씬 하나면 `InGameHub` 하나로 끝난다 |
| 씬 · 프리팹 충돌 | 병렬 갈래가 씬을 나눠 만지면 합칠 때 깨진다. 씬 파일에 든 것을 최소로 둔다 |

씬 안에 두는 것은 **셋뿐**이다 : `Main Camera`(직교 · size 10 = 640 ÷ 32 ÷ 2 · 9:16) · `EventSystem` · `InGameMaster`(빈 GameObject 에 컴포넌트). 나머지는 코드가 만들거나 **프리팹을 빌려** 붙인다. 씬 · 프리팹은 `unity command` CLI 로 만든다.

**UI 는 프리팹 + 코드 배선**이다 (사용자 09-18, mem `20260918-027b9301`). 둘의 몫을 나눈다 :

| 몫 | 누가 | 무엇 |
| --- | --- | --- |
| 모양 | 프리팹 (`Assets/_Project/Prefabs/UI/<화면>.prefab`, 화면마다 하나) | 레이아웃 · 위치 · 크기 · 색 · 자식 이름 |
| 배선 | 코드 (`UiManager` · `ScreenObject`) | 버튼 → Manager 호출 · 값 넣기 · 이벤트 받아 갱신 |

- 프리팹에 **Manager 참조 · UnityEvent 인스펙터 연결은 넣지 않는다.** `AGENTS.md` 10절이 막는 것은 「인스펙터에서만 알 수 있는 배선」이지 프리팹이 아니다.
- 코드가 찾는 자식 이름은 **`UiNames` 상수 한 곳**에 둔다. 프리팹의 자식 이름과 상수가 어긋나면 켤 때 바로 로그로 알린다.
- `UiManager` 가 `ResourceService` 로 화면 프리팹을 빌려 Canvas 에 붙이고, `UiNames` 로 자식을 찾아 배선한다.

- **화면 → Manager 는 Hub 로 직접 부른다** (`InGameHub.Get<IFarmHub>()` 같은 인터페이스). **Manager → 화면은 EventBus** 다. 방향을 하나로 못 박는다.
- Manager 끼리도 EventBus 로만 알린다. 단 **오프라인 진행은 이벤트가 아니라 `PostInit` 에서 `ClockManager.OfflineSeconds` 를 읽어 각자 진행**한다 — `PostInit` 때는 구독이 아직 다 안 붙었고, 핸들러 안 `Publish` 가 금지라서다. 결과는 `ClockManager.OfflineReport` 에 적고 `UiManager` 가 맨 뒤에서 읽어 팝업을 띄운다.
- 각 Manager 가 Hub 에 등록하는 인터페이스 : `IStaticDataHub` · `ISaveHub` · `IClockHub` · `IWalletHub` · `IInventoryHub` · `IFarmHub` · `IStorageHub` · `ICodexHub` · `ISynthesisHub` · `IStallHub` · `IUiHub`. 화면은 이것만 본다.
- 이벤트는 전부 `readonly struct`, 동기 즉시 호출, 구독은 `PostInit` · 해제는 `Dispose` (2차 설계 7장).

## 5. 데이터 (JSON) 설계

- 자리 : `Assets/_Project/Resources/Data/<표>.json`, 표 하나에 파일 하나 (사용자 확인 09-18). **JSON 이 정본**, `04-수치표.md` 는 근거.
- 꼴 : `JsonUtility` 가 맨 바깥 배열을 못 읽으므로 `{ "rows": [ {...}, {...} ] }` 로 감싼다. 행 클래스는 `[Serializable]` 순수 C# 이고 `id` 는 문자열이다.
- `StaticDataManager` 는 `Get<TRow>(id)` · `All<TRow>()` 둘뿐이다. 값 해석은 각 Manager 가 한다.
- **값은 전부 `04-수치표.md` 를 따른다.** 아래는 열 이름만이다. 괄호 안은 어느 결정에서 온 값인지다.

| 표 | 열 | 비고 |

## 6. 판정 방법

### 6-1. 어떻게 노나

1. 세이브 없이 켠다. **디버그 패널 없이** 첫 한 바퀴(0 → 9)를 돈다. 막히면 그 자리와 까닭을 적고 계속한다.
2. 한 바퀴 뒤 디버그 패널로 배속 ×5 · 20마리 채우기를 써서 Q16 · 합성 완료 · 새 떡 발견을 본다.
3. 끄고 5분 이상 두었다가 다시 켜서 「돌아왔어요」 팝업이 맞는지 본다.
4. 다 하고 아래 결과 파일을 쓴다. 놀이는 30분 안이 목표다.

### 6-2. 결과 파일

자리는 **`Docs/History/2026-MM-DD-세로조각1판판정.md`** (프로토의 `결과.md` 와 같은 꼴 · 끝난 일 기록은 History). 담는 표 :

| 판정 | 기준 | 답 | 근거 한 줄 |
| --- | --- | --- | --- |
| 한 바퀴 | 첫 켜기 → 다음날로. 막힌 곳 0 | 예/아니오 | 막힌 자리 · 까닭 |
| Q16 | AI 가 종 이름 셋을 부르고(예 「파도찹쌀이」) 사용자가 화면에서 찾아 탭. 각 3초 안, 3/3 | 예/아니오 | 걸린 초 셋 |
| Q17-줍기 | 더미를 탭해 줍는 것이 기분 좋은가 | 예/아니오 | 느낌 + 무엇 때문에 |
| Q17-합성 | 「받기」 → 결과 연출이 기분 좋은가 | 예/아니오 | 느낌 + 무엇 때문에 |
| 발견 연출 | 떡메 마지막 타격 → 칸 열림에 「오」 했나 | 예/아니오 | 느낌 + 무엇 때문에 |
| 돌아왔어요 | 안 켠 시간만큼 쌓였고 팝업 숫자가 맞나 | 예/아니오 | 안 켠 분 · 쌓인 것 |

- 손맛 · 연출은 재기 어려우니 **「느낌」으로 적되 근거 한 줄**(무엇이 좋았나 · 무엇이 걸렸나)을 꼭 붙인다.
- 같이 적는 기록 : 놀이 시간(분) · 다음날로 누른 횟수 · 도감 열린 칸 수 · 골드 · 「한 바퀴 더 하고 싶나」.
- 판정 뒤 `stage next` 는 **사용자가 정한다**.

## 7. 만들기 순서 (소단계)

예상 시간은 적지 않는다 — 메인 세션이 EffortTool 로 잰다. 소단계마다 「끝났다고 보는 기준」 한 줄.

- 코드는 `CodeTool:code-conventions` 스킬을 열고 쓴다.
