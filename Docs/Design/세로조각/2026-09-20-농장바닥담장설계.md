## 한 줄 결론

- 바닥은 **가로 12칸 · 세로 13칸 (384×416px)** 이다. 좌우 12px 씩은 화면 밖으로 나간다.
- `LayoutConst.FarmBottomPx` 를 **560 → 552** 로 한 줄 고치면 세로가 13칸에 딱 떨어진다. 아래 UI 띠(560~640)는 안 먹는다.
- 그림은 **8장**이다 — 바닥 3장(기본+변종 2) · 담장 5장(위·아래·옆·위모서리·아래모서리). 오른쪽은 `flipX` 로 뒤집어 쓴다.
- Tilemap **층 셋** : 바닥(-10) · 담장 뒤(-5) · 담장 앞(600). **양옆 담장·위 모서리는 「담장 앞」 층**에 둔다 (사용자 판정 2026-09-20).
- 그림은 **PixelLab 으로 뽑으려 했으나 안 됐다.** AI 에서는 **색·꽃·돌 무늬만** 받고, 실제 8장은 **PIL 스크립트로 직접 짰다** (4-5 절).
- 그림은 **세 판**을 거쳐 2026-09-20 에 사용자가 「오 좋아」로 확정했다 (4-5 절).

## 2. 바닥 자리 — 확정 수치

### 2-1. 검증 결과 : 사용자 안(384×416) 이 맞다

`LayoutConst.cs` 를 읽고 푼 값이다. 32px = 1유닛 · 카메라 직교 size 10 · 화면 360×640.

| 무엇 | 화면 px (위에서) | 월드 y | 칸 |
| --- | --- | --- | --- |
| 자원바 | 0~56 | — | — |
| 건물 띠 | 56~136 | — | — |
| **농장 (바닥 타일)** | **136~552** | **5.75 ~ -7.25** | **세로 13칸** |
| 빈 8px | 552~560 | -7.25 ~ -7.5 | — |
| 아래 띠 (UI 버튼) | 560~640 | — | — |

- 세로 : `552 - 136 = 416 = 32 × 13` ✔
- 가로 : `32 × 12 = 384`. 화면 360 보다 24px 크니 **좌우 12px 씩 화면 밖**이다 ✔
- **448(14칸)은 못 쓴다** — 바닥이 584px 까지 내려와 아래 띠(560~)를 24px 먹는다. 사용자 판단이 맞다.
- 바뀌는 상수는 **`FarmBottomPx` 하나뿐**이다 (560 → 552). 농장이 8px 짧아지고 아래 UI 띠는 그대로다.

### 2-2. `LayoutConst` 에서 바뀌거나 더해지는 것

| 상수 | 지금 | 바뀜 | 영향 |
| --- | --- | --- | --- |
| `FarmBottomPx` | 560 | **552** | `FarmRect.yMin` 이 -7.35 → **-6.85** (8px 위로) |
| `FarmTileCols` | 없음 | **12** 더한다 | 바닥·담장 가로 칸 수 |
| `FarmTileRows` | 없음 | **13** 더한다 | 세로 칸 수 |
| `FenceUnits` | 없음 | **1f** 더한다 | 담장 두께 = 타일 한 칸 |
| `FarmGroundSeed` | 없음 | **20260920** 더한다 | 변종 섞기 고정 시드 |
| `GroundSortOrder` · `FenceBackSortOrder` · `FenceFrontSortOrder` | 없음 | **-10 · -5 · 600** 더한다 | 층 정렬 |

**`FarmRect` 의 `margin = 0.4f` 는 안 건드린다.** 걷는 범위는 `FarmViewManager` 쪽에서 담장만큼 더 좁힌다 (3-2).

### 2-3. 영향받는 자리 넷

| 자리 | 지금 | 이번에 | 까닭 |
| --- | --- | --- | --- |
| **바닥 그리기** (`FarmViewManager.CreateGround`) | 흰 네모 1개 + 색 + `FarmRect + 0.8` | **통째로 지우고** `IFarmGroundPainter` 호출로 바꾼다 | 타일맵이 대신한다 |
| **걷는 범위** (`FarmViewManager.WanderRect`) | `FarmRect` 아래만 1.3 뺀다 | 좌·우·위 **0.5유닛**, 아래 **1+1.3유닛** 뺀다 | 찹쌀이가 담장을 넘어가 보이면 안 된다 |

| **건물 띠** | 56~136 | **안 건드린다** | 위쪽 경계는 그대로다 |

## 3. 코드 구조

3년차 눈높이로 적는다. 컨벤션은 `Tools/CodeTool/Docs/Guide/코딩컨벤션.md` 를 따른다.

### 3-1. 새 파일 셋 + 고치는 파일 셋

| 파일 | 무엇 |

### 3-2. 이음매 — 나중에 자체 타일맵으로 갈아 끼우려고

```csharp
public interface IFarmGroundPainter
{
    void Paint(Transform parent, IResourceHub resource);
    void Clear();
}
```

- `FarmViewManager` 는 **인터페이스만 안다.** 구현체를 `Init()` 에서 한 줄로 고른다
  (`_groundPainter = new TilemapFarmGroundPainter();`).
- 자체 타일맵을 만들 때는 `MozziTilemapFarmGroundPainter` 를 새로 쓰고 그 한 줄만 바꾼다.
  **Unity 의 `Grid`·`Tilemap`·`Tile` 타입이 `TilemapFarmGroundPainter.cs` 밖으로 안 새게 한다** — 그게 이음매의 전부다.
- 칸 수·원점·정렬 수치는 `LayoutConst` 에 있으므로 구현체가 바뀌어도 자리가 안 흔들린다.
- 이 할 일은 mem `--type todo --scope code` 에도 남겼다 (7절).

`FarmViewManager` 쪽 바뀌는 메서드 둘 :

```csharp
// 걷는 범위는 담장 안에서 담장 두께와 더미 줄을 뺀 자리다.
private static Rect WanderRect()
{
    Rect area = LayoutConst.FarmRect;
    float side = LayoutConst.FenceUnits * 0.75f;
    float top = LayoutConst.FenceUnits * 0.5f;
    return Rect.MinMaxRect(
        area.xMin + side,
        area.yMin + LayoutConst.FenceUnits + 1.3f,
        area.xMax - side,
        area.yMax - top);
}
```

- 좌·우는 **3/4 칸(24px)** 을 뺀다. 옆 담장이 찹쌀이 **앞**이라, 반 칸이면 가장 큰 3단계(56px)가 몸 18px 을 가린다.
- 위는 **반 칸(16px)** 만 뺀다. 위 담장은 뒤 층이라 찹쌀이가 반쯤 겹쳐 서야 「담장 안에 있다」로 읽힌다.
- 아래는 **한 칸을 다 뺀다.** 아래 담장은 찹쌀이 **앞**에 그려지므로, 겹치면 발이 잘린 것처럼 보인다.
- 더미 줄은 `area.yMin + 1.3f` 로 올린다 (`LayoutPileSpots`).

### 3-3. Tilemap 층 셋과 `sortingOrder`

**찹쌀이 정렬 범위를 코드에서 재서 정했다.** `MozziObject.ApplySort()` 는
`MozziSortBase(300) - round(y × 32)` 이고, y 는 위 `WanderRect` 안에서만 움직인다 (`Nudge` 가 clamp 한다).

| 무엇 | 월드 y | `sortingOrder` |
| --- | --- | --- |
| 찹쌀이 가장 위 | 4.85 | **145** |
| 찹쌀이 가장 아래 | -4.55 | **446** |

그래서 층은 이렇게 둔다.

| 층 (GameObject 이름) | `sortingOrder` | 무엇이 들어가나 |
| --- | --- | --- |
| `FarmGround` | **-10** | 바닥 타일 12×13 = 156칸 전부 |
| `FarmFenceBack` | **-5** | 위 담장 10칸 |
| `FarmFenceFront` | **600** | 아래 담장 10칸 + 아래 모서리 2칸 + **좌우 담장 22칸 + 위 모서리 2칸** |

- 담장 뒤(-5)는 더미(2)·건물(0·5)보다도 뒤다. 위 담장과 더미·건물은 자리가 안 겹치니 문제없다.
- 담장 앞(600)은 더미 숫자(20)보다 앞이지만, 더미 줄을 1.3유닛으로 올려 **자리가 안 겹친다.**
- 「어느 종류가 앞 층인가」는 코드의 `TilemapFarmGroundPainter.IsFrontLayer` 한 자리에 있다. 위 담장도 앞으로 옮기고 싶으면 거기만 고친다.
- 여유가 150 이상씩 있어 찹쌀이 범위가 조금 바뀌어도 안 뒤집힌다.

### 3-4. 양옆 담장을 어느 층에 — 선택지와 추천

| 안 | 어떻게 | 장점 | 단점 |
| --- | --- | --- | --- |
| 가. 담장 뒤 | 좌우 22칸을 `FarmFenceBack` 에 | 층이 셋으로 끝난다 · 위쪽에 선 찹쌀이가 옆 담장에 안 가린다 | 가장자리에 붙은 찹쌀이가 옆 담장을 살짝 덮는다 |
| **나. 담장 앞 (정해짐)** | 좌우를 `FarmFenceFront` 에 | 찹쌀이가 담장 밖으로 안 새 보인다 | 위쪽 찹쌀이까지 옆 담장에 가린다 |
| 다. 칸마다 y 로 정렬 | 옆 담장만 따로 오브젝트로 | 제일 정확하다 | Tilemap 한 층은 `sortingOrder` 가 하나라 **「담장도 Tilemap」 결정과 어긋난다** |
| 라. 위/아래 반씩 두 층에 | 좌우를 세로 절반으로 갈라 뒤·앞에 | Tilemap 만으로 된다 | 경계에서 찹쌀이가 툭 튄다 |

**첫 판 캡처를 보고 사용자가 「나」로 정했다 (2026-09-20).** 가장자리 찹쌀이가 옆 담장을 덮는 것이 어색했다.
대신 찹쌀이가 담장에 너무 가리지 않게 `WanderRect` 의 좌우를 반 칸에서 **3/4 칸**으로 넓혔다.
위 담장만 뒤 층에 남아, 위쪽에 선 찹쌀이는 예전처럼 담장 앞에 보인다.

### 3-5. Tile 에셋 — 런타임에 만든다

```csharp
Tile tile = ScriptableObject.CreateInstance<Tile>();
tile.sprite = sprite;
tile.colliderType = Tile.ColliderType.None;
tile.flags = TileFlags.None;   // 칸마다 flipX 를 주려면 잠금을 풀어야 한다
```

- **에셋 파일로 두지 않는다.** `.asset` + `.meta` 가 8개 늘고, 그림을 바꾸면 에셋도 같이 고쳐야 한다.
  런타임 생성이면 정본이 그림 한 벌뿐이다.
- `flags = TileFlags.None` 이 없으면 `SetTransformMatrix` 가 먹히지 않는다. **오른쪽 담장의 `flipX` 가 여기 걸린다.**
- 만든 `Tile` 은 에셋이 아니라서 `Clear()` 에서 `Object.Destroy(tile)` 로 같이 지운다.
- 오른쪽 뒤집기 :
  `tilemap.SetTransformMatrix(pos, Matrix4x4.Scale(new Vector3(-1f, 1f, 1f)));`
  타일 앵커가 (0.5, 0.5) 라 칸 가운데를 축으로 뒤집힌다.

### 3-6. Grid 를 코드로 만들까 프리팹으로 둘까 — 추천 : 코드

| 길 | 장점 | 단점 |
| --- | --- | --- |
| **코드 (추천)** | 칸 수·원점·정렬이 `LayoutConst` **한자리**에만 있다 · diff 로 읽힌다 · 프리팹 충돌이 없다 | 30줄쯤 늘어난다 |
| 프리팹 | 인스펙터에서 층을 눈으로 본다 | 같은 수치가 **두 벌**이 된다 (`LayoutConst` 와 프리팹) — 어긋나면 찾기 어렵다 |

사용자가 「모든 것을 코드로 풀 필요 없다」고 했지만, AGENTS 10절의 갈림은 **「모양이냐 배선이냐」**다.
`Grid` 위치와 `sortingOrder` 는 **모양이 아니라 자리·정렬 수치**이고 `LayoutConst` 가 이미 정본이다.
그래서 **코드**로 간다. 나중에 담장에 흔들림 애니 같은 「모양」이 붙으면 그때 프리팹을 본다.

Grid 만드는 값 :

| 무엇 | 값 |
| --- | --- |
| `Grid.cellSize` | `(1, 1, 0)` — 1유닛 = 32px |
| `Grid` 위치 | `(-6.0, -7.25, 0)` = `(-FarmTileCols × 0.5, YFromTop(FarmBottomPx), 0)` |
| 칸 채우는 범위 | `x = 0..11` · `y = 0..12` |
| 타일 pivot | 가운데 — `MozziArtImport` 가 `SpriteAlignment.Center` 로 넣어 주고, Tilemap 기본 앵커 (0.5, 0.5) 와 딱 맞는다 |

### 3-7. 변종 섞는 규칙

```csharp
System.Random rng = new System.Random(LayoutConst.FarmGroundSeed);
```

- **시드를 고정한다.** 그래야 캡처 판정을 되풀이해도 같은 화면이 나오고, 「어제 화면과 다르다」가 안 생긴다.

- 담장이 덮는 바깥 테두리 칸에도 바닥을 깐다. 담장 그림에 투명한 자리가 있어도 풀이 비치게.

### 7-1. 닫혔다 (전부 2026-09-20 사용자 판정)

| 항목 | 정해진 것 |
| --- | --- |
| 외곽선 없음으로 갈까 · 40/48/56 을 그대로 둘까 | **둘 다 그대로.** 풀밭 타일 위 캡처를 보고 |
| 32px 무늬에 찹쌀이가 묻히나 | **안 묻힌다** |
| 옆 담장을 어느 층에 | **앞 층**(`FarmFenceFront` 600) |
| 변종 비율 82/10/8 | **그대로.** 무늬 세기는 2판 것으로 |

| 풀밭 결 | **차분한 바탕 + 옅은 풀 포기.** 2판의 야생 풀밭은 물렀다 |
| 위 담장 위로 풀 띠가 보이는 것 | **괜찮다** |
| 위/아래 담장이 비슷해 보이는 것 | **당장은 괜찮다** |
| PixelLab 이 「안쪽 20px」을 지키나 | **못 지킨다.** 자리·방향 지시를 하나도 안 따른다 (4-3) |
| `create_tiles_pro` 크레딧 | **20 generations · 약 8분 · 16장** (4-2) |
