# 세로 조각 1판 — 그림 요청 목록 (2026-09-20)

아트 작업 세션에 넘기는 문서다. **「그림으로 넣으면 좋을 것」을 눈에 자주 띄는 순으로** 적고,
그림을 꽂을 자리(훅)가 지금 어디까지 돼 있는지 같이 적는다.

## 한 줄 결론

- **2번(농장 바닥·담장)과 4번(재료 아이콘 6종)은 끝났다 (09-20).** 1번은 흰 몸 한 벌(레이어·표정 10·점프)만 됐다. 지금 9종은 **그 한 벌에 색만 곱해** 구분한다.
- **3번(건물 2채)도 끝났다 (09-21 · 그림 + 배선).** `BuildingObject` 가 그림을 받아 그리고 이름은 아래 띠에 앉는다. Play 모드 화면으로 확인했다.
- **5번(떡)도 끝났다 (09-21 · 그림 + 배선).** 10종이 아니라 **11장**이고(조합 실패로 나오는 「평범한 떡」을 더했다), 크기는 48 이 아니라 **32×32** 다. 도감 · 발견 연출 · 만들기 줄 · 손님 주문 칸 네 군데에 뜬다.
- 1번에서 종마다 다른 몸을 넣으려면 **32장(8종 × 점프 4프레임) + `MozziSpecies.json` 고치기**가 든다. 그림만 넣어서는 안 뜬다.
- 남은 5~8번은 **그림보다 배선이 먼저**다. 배선은 그림 없이도 먼저 해 둘 수 있다.
- **다음 아트 일은 사용자가 고른다.** 후보는 손님 얼굴(6번) · 찹쌀이 종별 몸(1번) · **진열대 떡 칸**(새로 — 지금은 글자 한 줄이라 칸 UI 를 새로 짜야 한다)이다.
- 방향 수·애니 최소는 아직 못 정했다. **1방향 정지 그림부터** 받는다.

## 왜 쓰나

세로 조각 1판은 전부 색 네모다. 사용자가 「사람이 하기엔 아무것도 없다」고 했다.
판정을 하려면 최소한 자주 보이는 것부터 그림이 들어가야 한다.

### 1번 — 찹쌀이 id 와 이름

**지금 (09-20 코드에서 확인)**

- `Resources/Data/MozziSpecies.json` 의 24종이 전부 `"spriteKey": "Mozzi/body"` 다. 몸 그림은 흰 몸 한 벌(`body_hop0`~`body_hop3`)뿐이다.
- 종 구분은 코드가 표의 `colorHex` 를 몸에 곱해서 한다 (`MozziObject.cs`). 흰찹쌀이만 그림 색이 그대로 나온다.
- 몸 그림은 한 장이 아니라 **점프 4프레임**이다. `MozziArtKeys.BodyHop()` 이 spriteKey 뒤에 `_hop0`~`_hop3` 을 붙여 찾는다.

**종마다 다른 몸을 넣으려면**

1. 종마다 4장을 그린다. 8종 × 4프레임 = **32장**. 파일 이름은 `<spriteKey>_hop0.png` ~ `_hop3.png` 다. (예: `Resources/Art/Mozzi/water1_hop0.png`)
2. `MozziSpecies.json` 에서 그 종의 spriteKey 를 바꾼다. (예: `"Mozzi/water1"`) 변종(`_shiny`) 줄도 같은 몸을 쓸지 같이 정한다.
3. 몸을 색으로 그렸으면 `colorHex` 곱하기가 그림 색을 덮는다. 그 종은 곱하기를 빼야 하는데 **이건 코드 일**이다.

`Resources/Art/Mozzi/<id>.png` 한 장만 넣어서는 **안 뜬다.**

| 계열 | 1단 | 2단 | 3단 |
| --- | --- | --- | --- |
| 풀 | grass1 흰찹쌀이 **(이미 있음)** | grass2 풀찹쌀이 | grass3 나무찹쌀이 |
| 물 | water1 물찹쌀이 | water2 파도찹쌀이 | water3 상어찹쌀이 |
| 용암 | lava1 불찹쌀이 | lava2 용암찹쌀이 | lava3 화산찹쌀이 |

### 3번 — 건물 2채

**상태 — 끝 (09-21 · 그림 + 배선).**

확정 모양은 이렇다. 1판에서 「기와 지붕 + 가마솥」과 「줄무늬 천막 좌판」으로 그린 전통풍을 사용자가 둘 다 물렸다.

- **합성소** : 떡 2개를 넣고 돌리는 **귀여운 기계**다. 크림색 몸통에 분홍 테, 앞면 유리 투입구 안에 흰 떡이 보이고, 옆으로 놋쇠 파이프가 흐른다. 받침 띠는 모자색(`#393651`).
- **가판대** : 옛날 좌판이 아니라 **현대 카페풍 떡 가게** 앞면이다. 어닝 · 유리창 · 나무 카운터로 쌓았다.
- 둘 다 **B안** — 이름 글자를 그림 정중앙이 아니라 **아래쪽 띠**에 얹는 꼴로 그렸다. 가운데를 비워야 알맹이(기계·유리창)를 크게 그릴 수 있었다.

#### 배선 — 끝 (09-21)

넘겼던 다섯을 모두 했다. 프리팹은 안 건드렸고 전부 코드다.

| 넘겼던 것 | 어떻게 됐나 |
| --- | --- |
| ① 이름표를 아래 18px 띠 가운데로 | `LayoutConst.BuildingLabelBelowPx`(23px = 0.72유닛)만큼 내린다. 글자 크기는 `BuildingLabelPx`(12px)로 코드에서 준다. 네모로 떨어질 때는 예전처럼 한가운데다 |
| ② `SpriteKeys` 에 건물 상수 둘 | `BuildingSynthesis` · `BuildingStall` 두 줄을 더했다 (`"Building/synthesis"` · `"Building/stall"`) |
| ③ `Setup` 이 sprite 를 받게 | `Setup(BuildingKind, Sprite, Vector2)` 다. 그림이 있으면 `localScale` 이 1, 없으면 예전처럼 흰 네모를 (4.375, 2.0) 으로 늘린다 |
| ④ 알림 점은 오른쪽 위 구석 | 몸 크기를 local 단위로 바꿔 두 경우 모두 14px · 오른쪽 위에 앉는다 |

**상태 — 끝 (09-21 · 그림 + 배선).** 그림은 **11장**(위 10 + 평범한 떡)이다.

**크기는 32×32 로 확정했다.** 요청 표의 48×48 을 사용자가 물렸다 — 24 로 시작했다가 자리가 빠듯해 32 로 올렸다.
찹쌀이 몸·타일과 같은 32 라 크기 계통이 하나로 맞는다. 한 장을 네 군데에서 배율만 바꿔 쓴다.

| 쓰는 곳 | 크기 |
| --- | --- |
| 도감 칸 | 64px (×2) |
| 새 떡 발견 연출 | 96px (×3) |
| 손님 주문 칸 | 32px (×1) |
| 만들기 줄 | 24px (0.75배) |

**그림 규칙** — 재료 아이콘 D벌과 같은 화풍이다. 외곽선 없음 · 그늘 한 단계 · 하이라이트 점 · 빛은 왼쪽 위 · 장당 3~6색.
AI 는 안 쓰고 PIL 스크립트로 직접 그렸다.

**구도 (사용자가 정함)** — **같은 크기 떡 두 알**이다. 뒤에 온전한 알을 한 톤 어둡게 깔고,
앞 오른쪽에 반 갈라 **단면이 정면을 보는** 알을 놓는다. 겉 · 속 · 고물을 한 그림에 다 보여 주려는 것이다.

**재료가 앉는 자리는 고정이다.** 한 재료는 어느 떡에서나 같은 자리 · 같은 색으로 나온다.

- WebGL v9 는 09-21 에 구워 아티팩트 판 12 로 올렸고, **사용자가 「떡이랑 건물 잘 작동한다」고 확인했다** (mem `20260921-361fa0f0`).

## 훅 현황

**훅**은 「그림을 꽂는 자리」다. 표에 적힌 키로 그림을 찾아 화면에 붙여 준다.

- 스프라이트 훅(`ISpriteSource` · `SpriteKeys` · `ResourcesSpriteSource` · `ResourceService.GetSprite`)은
  09-20 에 아트 세션이 만들었다.
- **찹쌀이 · 농장 바닥·담장 · 재료 · 건물 · 떡 다섯 갈래에 이어져 있다** (건물 · 떡은 09-21).
  바닥·담장은 `FarmViewManager` → `IFarmGroundPainter` → `TilemapFarmGroundPainter` 가 `SpriteKeys.Farm*` 키로 받는다.
  재료는 `Ingredient.json` 의 `spriteKey` 를 `PileObject`(바닥 더미) · `FarmScreen`(자원바) · `StallScreen`(실험 토글) 이 받는다.
- 건물은 `FarmViewManager` 가 `SpriteKeys.BuildingSynthesis` · `BuildingStall` 로 찾아 `BuildingObject.Setup` 에 넘긴다 (09-21).
- 떡은 `Recipe.json` 의 `spriteKey` 를 도감 · 발견 연출 · 만들기 줄 · 손님 주문 칸 넷이 받는다. 표에 없는 평범한 떡만 `SpriteKeys.CakePlain` 이다 (09-21).
- 나머지(손님 · UI 틀 · 진열대 칸)는 아직 배선이 없다.
- 키는 이렇게 붙는다 : `SpriteKeys.Root`(`"Art/"`) + 표의 spriteKey(`"Mozzi/body"`) + `_hop0` → `Resources/Art/Mozzi/body_hop0`.
  `MozziSpecies.json` 의 24종은 지금 모두 같은 키(`Mozzi/body`)다.
- 그림이 없으면 null 을 돌려 **네모로 그리고, 키마다 경고를 한 번** 찍는다. 게임이 멈추지 않는다.

### 남은 배선

**3번 · 5번 배선은 09-21 에 끝났다.** 6~8번은 그림도 배선도 없다.

1. ~~`Recipe.json` 에 spriteKey 열을 더한다.~~ **끝 (09-21)** (`Ingredient.json` 은 09-20 에 했다)
2. UI 화면의 Bind 가 sprite 를 받게 한다. (`PileObject` 는 09-20, `BuildingObject` 와 떡 쓰는 네 화면은 09-21 에 했다)
3. 바닥·건물처럼 표가 없는 것은 `SpriteKeys` 에 상수를 둔다. (건물 상수 둘 · `CakePlain` 은 09-21 에 넣었다)
4. **진열대(`ShelfText`)는 아직이다.** 글자 한 줄이라 그림을 넣으려면 칸 UI 를 새로 짠다.

배선은 **그림 없이 먼저 해 둘 수 있다.** 그림이 없으면 지금처럼 네모로 나온다.

### 누가 하나 — 아트 세션 (09-21 에 정함)

- **그림을 넣은 아트 세션이 배선까지 끝낸다.** 떡 11장이 그렇게 갔다.
- **세로 조각 세션은 사용자가 알려 주면 그 결과를 검사한다.** 검사에서 나온 고칠 것은 사용자가 시킬 때 고친다.
- 근거는 mem `20260921-0c702c1c`.

**같은 파일을 두 세션이 동시에 고치지 않는다.**

## 같이 알릴 것 (세로 조각 세션 → 아트 세션)

- **글씨를 전부 TextMeshPro 로 옮겼다 (09-20).** Text 365 · TextMesh 2 를 바꿨고,
  UI 코드 13 · `PileObject` · `BuildingObject`, 프리팹 10, asmdef 2 가 고쳐졌다.
  폰트는 임시로 ONE Mobile POP 이고 나중에 바뀐다. 그 파일들을 고칠 때는 `Text` 가 아니라 **`TMP_Text`** 다.
- **WebGL 빌드는 약 8분 걸린다.** 그동안 같은 에디터로 보내는 Unity CLI 명령이 30초 시간 초과로 실패한다
  (09-20 07:02~07:10 에 4건). 그때 실패한 명령은 다시 돌리면 된다.
- **그림 적용이 끝나면 사용자가 알려 주기로 했다.** 그 뒤 세로 조각 세션이 WebGL 을 다시 빌드해 아티팩트에 올린다.
- **커밋은 아직 양쪽 다 없다.** 같은 폴더에 변경이 섞여 있으니 커밋은 세션별로 제 몫만 골라 한다.
