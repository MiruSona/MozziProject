## 1. 한 줄 요약

- **기준은 전용 화면 · 메인 v15 쪽**이다. 따뜻한 짙은 갈색 선 · 빛 왼쪽 위 · 1px 도트 · 명암 3단.
- **사람 선은 갈색으로, 아이콘은 선을 새로 넣는다.** 찹쌀이 선 색과 아이콘 24px 은 **시안을 먼저** 보고 고른다.
- **떡은 캔버스 바닥에 붙여 다시 굽는다.** 코드는 떡 찍는 자리 다섯의 좌표를 맞춘다.
- **서랍 찹쌀이는 ×1 「고개 내민」 꼴**로 먼저 해 본다. 다만 Unity 화면에서 서랍에는 찹쌀이가 아니라 **검은 그림자 + 「?」** 가 뜨고 자리도 12px 왼쪽이라, 배율과 자리를 같이 고친다. 그림자 + 「?」 는 그대로 둔다 (9-3, 사용자 답 「가」).
- **화면에서 가장 튀는 것은 그림 없는 단색 네모 둘**(합성 받기 · 찹쌀이 도감)이었다. **합성 받기 네모는 이번 D 갈래에서 찹쌀이 그림으로** 바꾸고, 도감 네모는 540 도감을 새로 지을 때 한다 (9-5).
- 범위 밖 후보 중 **가판대 지붕 빨간 알림 → 도트 표식, 메뉴 세움판 빼기** 둘만 이번에 넣는다 (13-1).
- **크레딧은 0** 으로 끝나는 것이 목표다. 모두 PIL · ArtTool 손질이고 PixelLab 은 안 부른다.
- 갈래는 **그림 셋 + 코드 하나 + 뒷정리**로 나눈다 (8절).

## 2-1. 화면에서 확인한 것 (Unity 캡처, 2026-10-05)

Play 화면을 540×1200 1배로 찍어 조사 결론을 다시 봤다. 판정 표 · 캡처 · 시안 대조는 `Docs/Reference/Art/점검/2026-10-05/unity/README.md` 에 있다. 여기에는 **설계가 바뀌는 점**만 적는다.

| 조사 결론 | 화면 판정 | 설계가 바뀌는 점 |
| --- | --- | --- |
| 진열장 떡이 뜬다 · 떡에 선이 없어 흐릿하다 | **맞다** — 접시 가운데보다 약 7~8px 위 | 없음. 9-1 셈과 맞는지 다시 셈했다 (맞음) |
| 말풍선 떡이 높다 | **약하다** — 약 3px 위 | 9-1 의 `BubbleIconBottom` 값을 다시 셈했다 |
| 서랍 찹쌀이가 작다 | **다르다 · 더 나쁨** — 결과 대신 검은 그림자 + 「?」, 서랍 가운데보다 약 12px 왼쪽 | 9-3 을 다시 썼다 (자리 고침 + 보이는 방식 두 안) |
| 손님 귀 · 볼 | **귀는 맞다 · 볼은 1배에서 약하다** | B-2 는 그대로 (귀가 먼저) |
| 가판대 선 색 섞임 | **약하다** — 선 색보다 **그림 밀도**(주인 잔 픽셀 애니풍 · 손님 단순 SD)가 먼저 보인다 | `reline` 만으로는 안 풀린다 → 13-1 범위 밖 후보 |
| 메뉴 세움판 순검정 · 48색 | **안 보인다** — 대신 계산대 밖 마루(약 x 460, y 680)에 홀로 선 자리가 튄다 | B-3 에서 세움판은 선 고치기보다 **자리 · 있을지**가 먼저 → 13-1 |
| 찹쌀이 회색 선 대 건물 갈색 | **약하다** — 샛노랑 큰 볼 · 면 칠뿐인 몸이 더 튄다 | C-1 시안에 「몸 칠 밀도」 를 같이 보이게 한다 (선 색만이 아니라) |
| 풀 장식이 칙칙하다 | **맞다** | 없음 |
| 말풍선 · 버튼 크림 잡색 | **안 보인다** | B-4 를 맨 뒤로 내렸다 (빼지는 않음) |
| (조사에 없던 것) 단색 네모 둘 | **가장 튄다** | 9-5 새로 |
| (조사에 없던 것) 옛 360 화면 남색 판 · 자원바 남색 띠 · 빨간 알림 네모 | 튄다 | 13-1 범위 밖 후보 |

**화면에서 다시 세운 튀는 순서** (README 4절) : ① 단색 네모 둘 → ② 진열장 떡 → ③ 서랍 그림자 → ④ 옛 360 화면 · 남색 자원바 → ⑤ 주인 대 손님 밀도 · 귀 → ⑥ 찹쌀이 볼 · 면 칠 → ⑦ 절구 · 떡메 대 마루 → ⑧ 풀 장식 → ⑨ 떡 0.75 배 · 위로 붙음 → ⑩ 메뉴 세움판 자리 → ⑪ 빨간 알림 네모 → ⑫ 말풍선 떡 3px.

- 이번 개편 범위(7절)는 ② · ③ · ⑤(귀) · ⑧ · ⑨ · ⑫ 를 고친다. ① 은 합성 받기 쪽만 이번에(9-5), ⑩ 세움판은 빼고, ⑪ 빨간 알림은 도트로 바꾼다. ④ · ⑤(밀도) · ⑥(칠) · ⑦ 과 도감 네모는 따로 판이다 (13-1, 2절 답 9~13).

### 4-1. 원작 색은 얼마나 가까운가 (잰 값)

게임 그림 111장의 모든 색 가운데 원작 색과 가장 가까운 색을 Lab 거리(ΔE, 2 아래면 눈으로 못 가름 · 10 넘으면 다른 색)로 쟀다. 스크립트 `점검/2026-10-05/measure/chabi.py`.

| 원작 색 | 지금 그림에서 가장 가까운 것 | ΔE | 읽기 |
| --- | --- | --- | --- |
| 머리 분홍 `#F8BBC0` | 계산대 `#FFBEC0` (792칸) · 칠판 장식 `#FBBEC8` | **2.7** | 이미 들어 있다. `pink` 램프 밝은 끝을 이 색으로 박는다 |
| 볼 다이아 `#FA6270` | 주인 `#EF6671` (34칸) · 도감 아이콘 `#D56172` | 5.9 · 16.6 | 가깝지만 넓게는 안 쓴다. **`accent` 의 기준점**으로 둔다 |
| 눈 보라 `#AE74DB` | 손님 보라 머리 `#9370BF` | **15.1** | 게임에 없는 색이다. `violet` 밝은 끝에 새로 더한다 |

## 5. ArtTool 프로필

### 5-1. 몇 벌로 나누나

**`src/arttool/profile.py` 를 읽어 확인했다 — 프로필 한 벌에 `style.outline` 은 값 하나다.**
고를 수 있는 값은 `unset · none · black · solid · selout · selout+light` 여섯이고, 맨 위 칸(`TOP_KEYS`)에 종류별 갈래 칸이 없다.
그래서 외곽선이 다른 종류마다 프로필을 나눈다. **여섯 벌**이다.

| 프로필 | 맡는 종류 (폴더) | `style.outline` | `palette.outline` | `check` 값 |
| --- | --- | --- | --- | --- |
| `mozzi_char` | 찹쌀이 몸 · 표정 · 악세 (`Mozzi/`) | `solid` | 시안 뒤 정한 색 (지금 `#6E6E6E`) | `max_colors 8` 은 몸만 — 표정은 1~3 이라 같이 둬도 된다 |
| `mozzi_people` | 손님 · 주인 (`Customer/` · `stall_owner`) | `selout` | `null` (selout 은 따로 쓰는 선 색이 없다) | `max_colors 40` · `color_cap` 표 `{128: 16, 256: 40}` |
| `mozzi_prop` | 건물 · 기계 · 화면 조각 · 소품 · UI · 농장 장식 | `selout` | `null` | `max_colors 48` · `color_cap` 표 `{32: 16, 64: 16, 128: 32, 256: 48}` |
| `mozzi_icon` | 떡 · 재료 (`Cake/` · `Ingredient/`) | `selout` | `null` | `max_colors 8` · `color_cap {32: 8}` |
| `mozzi_bg` | 화면 배경 · 하늘 · 길 · 잔디 바탕 | `none` | `null` | `background.max_colors 68` · `background.color_cap 68` |
| `mozzi_fx` | 연출 (`Fx/`) | `none` | `null` | `max_colors 1` |

**여섯 벌이 같이 갖는 칸**

| 칸 | 값 | 까닭 |
| --- | --- | --- |
| `style.light` | `top_left` | 3-1 |
| `style.scale` | `1` | 1px 도트 |
| `palette.ramps_file` | `palettes/mozzi_master.json` | 4절 |
| `palette.swap` | `runtime_lut` | 변종 12 = 팔레트 바꾸기 |
| `check.allow_alpha` | `binary` | 반투명 없음 |
| `tiles.size` | `32` | 06 문서 2절 6번 |
| `ui.ppu` · `ui.reference` | `32` · `[540, 1200]` | 540 기준 · 9:20 |
| `ui.scale_mode` · `ui.letterbox` | `integer` · `true` | 정수 배율 |

- `canvas.frame` 은 `mozzi_char` 만 `[64, 64]` · `pivot bottom_center` · `baseline_y 50` (몸 bbox 아래끝 y 50) · `center_x 31.5` 다. 나머지는 크기가 제각각이라 `canvas` 를 안 쓴다.
- 배경 모드의 색 수는 `check.background.max_colors` 칸으로 따로 연다 (기본 `None` 이면 위 `max_colors` 48 을 그대로 써서 지난 점검 때 배경이 실패했다).
- 만든 뒤 `arttool profile show --profile <yaml>` 로 통과를 본다.

## 14. 못 정한 것 · 확인 못 한 것

- 팔레트 색값은 **초안**이다. 파일로 만들 때 겹치는 색을 덜고 한 색 램프를 정리해야 한다.
- 손님 선을 갈색으로 바꾼 모습은 **아직 안 그려 봤다** — B-1 비교판이 처음이다.
- 9절 좌표 값(`BubbleIconBottom 20 · 21` · 서랍 `OutletX 97` · `OutletY 175`)은 코드 상수와 그림을 눈으로 잰 **셈한 값**이다. 지금 화면 캡처(1배)와는 맞췄지만(9-1 셈 검증), 고친 뒤 화면은 아직 없다.
- 도감 칸 `ColorBox` 를 짓는 코드는 이 저장소에서 못 찾았다 (옛 프리팹 안에만 있다고 봄 — 추측).
- 프로필의 `check` 칸 이름(`check.background.max_colors` 등)은 `profile.py` 의 기본값 표에서 읽었다. 실제 yaml 이 통과하는지는 0 단계에서 본다.
