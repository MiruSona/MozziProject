# 아트 규칙

> 찹쌀이 그림을 어떤 규격으로 그리고 굽는지를 못 박은 문서. 아트 바이블의 짧은 판이다.
> 날짜 2026-09-18 · 정한 사람 사용자 + AI · 상태 1차 가결 모음
> **새 결정을 만드는 문서가 아니다.** 이미 가결된 것을 한자리에 모아 놓은 것이다.

## 1. 한 줄 요약

**픽셀아트 · 낮은 탑다운(3/4) · 기준 해상도 360×640 · 찹쌀이 64×64 · 타일 32 · 외곽선 없음에 명암 평면 · 빛은 왼쪽 위.**
베이스 그림부터 AI(PixelLab)로 뽑고, 사람이 Aseprite 로 손본 뒤 ArtTool 로 검수·굽기한다.

- **이 문서는** 새 그림을 그릴 때 「이 값으로 맞춰라」 하고 가리키는 자리다.
- **이 문서가 아닌 것** : 무엇을 몇 장 그리는지(에셋 목록), 색표(팔레트 JSON), 절차 상세.
  절차 상세는 `Docs/Research/2026-09-08-아트작업절차조사.md` 를 본다.

## 4. 화면 규격이 뜻하는 것

**360×640 에 타일 32 를 깔면 가로 11.25칸 · 세로 20칸이다.**

- 세로는 딱 떨어지는데 **가로는 0.25칸(8px)이 남는다.** 농장 바닥을 짤 때 가로 11칸으로 잡고 남는 8px 은
  가장자리 여백이나 UI 밑으로 넣는 쪽이 낫다 (추측 — 첫 화면 목업에서 확인).
- 찹쌀이 64 이면 가로에 **5.6 마리**, 세로에 10 마리가 선다. 실제로는 UI 가 위아래를 먹으니 더 적다.
- 배율은 **정수 배만** 쓴다. 1080×1920 폰이면 ×3 으로 딱 맞는다. 남는 자리는 늘리지 말고 검게 둔다(레터박스).
- **찹쌀이만 예외다.** 64 로 그려 놓고 코드에서 40/48/56px 로 줄여 찍는다.
  AI 는 「정수 아닌 배율은 Point 필터에서 픽셀이 뭉개질 수 있다」고 짚었고, 사용자는 「그렇게까지 안 뭉개질 것 같다」로 정했다.
- **2026-09-20 에 첫 한 마리(흰찹쌀이)를 Unity 에 넣어 눈으로 보고 닫았다.**
  **사용자 판정 : 40/48/56 유지 · 「외곽선 없음」 유지.** 뭉개 보이지 않았다.
  **타일 바닥이 들어올 때 다시 판단한다** — 밝은 바닥 위에서 배경과 붙어 보이는지는 아직 못 봤다 (2절 7번의 뒤집는 조건이 그대로 살아 있다).
- **크기 40/48/56 은 캔버스가 아니라 몸 높이 기준이다.** 레이어로 나누면서 왕관이 몸 그림에서 빠져
  `body_hop0.png` 의 실제 몸(불투명 bbox)은 **42×35px**(x11~52 · y16~50)이 됐다.
  그래서 코드가 쓰는 실제 배율은 **1.143 / 1.371 / 1.600** 이다 (`LayoutConst.MozziBodyHeightPx = 35`).

### Unity 임포트 기본

| 항목 | 값 |
| --- | --- |
| Pixels Per Unit | **32** (타일 크기와 같게) |
| Filter Mode | **Point (no filter)** |
| Compression | **None** (무압축) |
| Generate Mip Maps | 끔 |
| 스프라이트 낱장 크기 | **2의 거듭제곱일 필요 없다.** 2의 거듭제곱이 필요한 것은 묶어 구운 아틀라스 쪽이다 |

- UI 쪽은 ArtTool `ui bake` 가 내는 `Editor/UiImportSettings.cs`(AssetPostprocessor)가 위 넷과 `border` 를
  한자리에서 넣어 준다. 사람이 Sprite Editor 를 열 일이 없다.
- **`PanelSettings` 의 Dynamic Atlas 에서 UI 아틀라스를 뺀다.** Point 텍스처가 Bilinear 동적 아틀라스에 들어가면 흐려진다.

## 5. 찹쌀이 레이어 규격

**찹쌀이는 한 장으로 그리지 않는다. 몸 · 볼터치 · 표정 · 악세사리 네 겹으로 나눠 그린다** (2026-09-20 사용자 결정).
나중에 표정이나 악세사리만 코드로 갈아 끼우려는 것이다. 종 색도 몸에만 곱하면 되니 12종이 그림 한 벌을 같이 쓴다.

자리는 모두 `ProjectMozziUnity/Assets/_Project/Resources/Art/Mozzi/` 다.

| 겹 | 파일 이름 | 캔버스 | 몇 장 | 그릴 때 지킬 것 |
| --- | --- | --- | --- | --- |
| 몸 | `body_hop0` ~ `body_hop3` | 64×64 | 4 | **흰색으로 그린다.** 종 색은 코드가 몸에만 곱한다. 왕관·볼·표정은 넣지 않는다 |
| 볼터치 | `cheek` | 11×11 | 1 | 한 장을 좌우에 쓴다 — 오른쪽은 코드가 `flipX` 로 뒤집는다 |
| 표정 | `face_01` ~ `face_10` | 64×64 | 10 | **64 캔버스에 표정 픽셀만** 그리고 나머지는 비운다 (몸과 겹쳐 올린다) |
| 악세사리 | `acc_crown` | 64×64 | 1 | 표정과 같게 64 캔버스에 왕관만 |

- 임포트 값은 손으로 안 건다. 에디터 스크립트 **`MozziArtImport`** 가 이 폴더에 들어온 그림에
  PPU 32 · Point · 무압축 · Mip 끔 · pivot 가운데를 자동으로 붙인다.
- **새 종을 그릴 때 그리는 것은 몸 4장뿐이다.** 새 표정은 `face_11` 처럼 번호를 이어 붙이고,
  새 악세사리는 `acc_<이름>` 으로 넣는다.

### 프리팹 짜임과 앵커

```
Mozzi (루트 : 콜라이더 · SortingGroup)
└─ Visual (Animator)
   ├─ Body
   ├─ 볼 앵커 L · R
   ├─ 표정 앵커
   └─ 악세 앵커
```

- **앵커는 두 겹이다.** `XxxAnchor` 는 코드가 잡는 기준 자리, `XxxOffset` 은 애니 클립이 움직이는 자리다.
  이렇게 나누면 애니가 움직여도 코드가 넣은 기준 자리가 안 지워진다.
- 볼 앵커는 몸 중심에서 **좌우 12.5px · 아래 7.5px** 이다.

**포물선 움직임은 코드가, 납작·길쭉한 모양은 그린 프레임 4장이, 재생은 Unity Animator 가 한다** (2026-09-20 사용자 결정).

| 프레임 | 모양 |
| --- | --- |

| `body_hop1` | 납작 (뛰기 직전 눌림) |
| `body_hop2` | 길쭉 (떠오름) |

- 값 : **뜀 0.35초 + 쉼 0.15초 · 높이 12px.** **걸을 때만** 뛴다.
- 클립·컨트롤러는 **12종이 한 벌을 같이 쓴다** — `Assets/_Project/Art/Anim/MozziIdle.anim` ·

## 6. 제작 흐름

**PixelLab → Aseprite → ArtTool → Unity** 네 자리다.

| 자리 | 무엇을 하나 |
| --- | --- |
| PixelLab | 베이스 그림을 뽑는다. 캐릭터·회전·애니·타일·배경. MCP 로 부른다 |
| Aseprite (손보기 — PIL·Aseprite 등, 필수 아님 · 8절) | 사람이 손본다. AI 가 약한 「여러 장 사이 일관성」과 중간 프레임을 여기서 잡는다 |
| ArtTool | 규격 맞추기(`normalize`) → 앵커(`anchors`) → 검수(`check`) → 굽기(`bake`) |
| Unity | 구워 나온 아틀라스·매니페스트를 `Assets/` 에 넣으면 임포터가 붙는다 |

자세한 경로는 `Docs/Research/2026-09-08-아트작업절차조사.md` **5절**(PixelLab 도구 목록·한계)과 **6절**(단계표 A·B·C)을 본다.

## 7. ArtTool 프로필 값 초안

`Tools/ArtTool/profiles/slime_demo.yaml` 을 본보기로 삼는다 (덩어리 캐릭터 · `rig blob` 이라 가장 가깝다).
아래는 **초안**이고, 프로필을 실제로 만들 때 `arttool profile show` 로 통과하는지 확인한다.

| 키 | 값 | 비고 |
| --- | --- | --- |
| `canvas.frame` | `[64, 64]` | 찹쌀이 캔버스 크기 (2절 5번) |
| `canvas.pivot` | `bottom_center` | 바닥에 세운다 |
| `canvas.baseline_y` · `canvas.center_x` | **프로필 만들 때 확인** | 64 프레임에 맞춘 값을 첫 한 마리로 잰다 |
| `palette.outline` | **프로필 만들 때 확인** | 「외곽선 없음」은 PixelLab 쪽에서 안 그리게 하고(`outline` 인자), ArtTool 검수에서 이 키를 어떻게 두는지는 프로필 만들 때 확인한다. `slime_demo` 는 색값(`#000000`)만 들어 있다 |
| `palette.ramps_file` | **미정** | 팔레트가 아직 없다 (3절) |
| `palette.swap` | `runtime_lut` | 변종 12 = 팔레트 바꾸기라 이 방식이 맞다 |
| `palette.ramp_len` · `palette.exact_match` | **프로필 만들 때 확인** | 팔레트가 정해진 뒤 |
| `anim` | **미정** | 애니 최소를 안 정했다 (3절) |
| `rigs.blob.anchors` | `[head_top, ground]` | 왕관을 얹을 자리 + 바닥 |
| `rigs.blob.marker_colors` | **프로필 만들 때 확인** | 마커 색 두 개가 찹쌀이 팔레트와 안 겹쳐야 한다 |
| `tiles.size` | `32` | |
| `tiles.blob` | `47` | `tile blob` 이 템플릿 6장에서 47장을 뽑는다 |
| `ui.ppu` | `32` | 타일 크기와 같게 |
| `ui.reference` | `[360, 640]` | 기준 해상도 |
| `ui.scale_mode` · `ui.letterbox` | `integer` · `true` | 정수 배율 · 남는 자리는 검게 |
| `check.max_colors` 등 | **프로필 만들 때 확인** | 팔레트 색 수가 정해진 뒤 |

- **외곽선 없음 · 명암 평면 · 빛 방향은 ArtTool 프로필이 아니라 PixelLab 생성 인자(`outline` · `shading`)로 넣는다** (조사 문서 5절 확인). 빛 방향을 따로 받는 인자가 있는지는 써 봐야 안다 (추측).
- 위 표에 없는 키를 지어내지 않는다. 모르면 `slime_demo.yaml` 과 `Tools/ArtTool/README.md` 를 다시 본다.

## 8. B 단계 끝 기준과 준비

**끝 기준 : 흰찹쌀이 한 마리가 PixelLab → (손보기) → ArtTool → Unity 를 끝까지 통과한다.**
규칙 문서만으로는 끝나지 않는다. 한 마리를 통과시켜야 프로필 값(크기·baseline·마커)이 진짜 맞는지 안다.

| 준비 | 상태 |
| --- | --- |
| PixelLab 계정 · API 토큰 | **있음 (09-20).** 구독 Tier 2 이고 MCP 로 부른다. 토큰은 환경변수 `PIXELLAB_API_KEY` 로만 둔다 — 파일·요청 JSON·로그 어디에도 안 적는다 |
| Aseprite 설치 | **필수 아님 (09-20 결론).** 이 PC 에 없어도 된다. 농장 타일은 AI 에서 색·무늬만 받고 PIL(파이썬 그림 라이브러리)로 직접 짰다 |

## 9. 아이콘 규칙 (재료 · 떡)

아이콘은 찹쌀이와 달리 **한 장을 여러 크기로 줄여 쓴다.** 그래서 가장 작게 쓰는 자리에서 알아보이는 것이 기준이다.
**둘 다 AI 를 안 쓰고 PIL 스크립트로 직접 그렸다.** 작은 그림은 AI 보다 손으로 찍는 쪽이 빨랐다.

| 갈래 | 캔버스 | 몇 장 | 자리 | 쓰는 크기 |
| --- | --- | --- | --- | --- |
| 재료 아이콘 | **28×28** | 6 | `Resources/Art/Ingredient/<id>.png` | 바닥 더미 · 자원바(약 18px) · 가판대 실험 토글 |
| 떡 아이콘 | **32×32** | 11 | `Resources/Art/Cake/<id>.png` | 도감 64px(×2) · 발견 연출 96px(×3) · 손님 주문 칸 32px(×1) · 만들기 줄 24px(0.75배) |

- **화풍은 둘이 같다 (재료 D벌 · 2026-09-20 확정).** 외곽선 없음 · 그늘 한 단계 · 하이라이트 점 · 빛은 왼쪽 위 · 장당 3~6색.
  2절 7번·8번(외곽선 없음 · 빛 왼쪽 위)을 그대로 따른 것이다.
- **떡 크기 32 는 2026-09-21 에 사용자가 정했다.** 24 로 시작했다가 자리가 빠듯해 32 로 올렸다.
  찹쌀이 몸·타일과 같은 눈금이라 크기 계통이 하나로 맞는다.
- 임포트 값은 4절 표 그대로다 (PPU 32 · Point · 무압축 · Mip 끔).

### 떡 아이콘 구도

**같은 크기 떡 두 알**을 그린다 (2026-09-21 사용자 결정).

- 뒤에 **온전한 알**을 한 톤 어둡게 깐다.
- 앞 오른쪽에 **반 갈라 단면이 정면을 보는 알**을 놓는다.
- 겉 · 속 · 고물을 한 그림에 다 보여 주려는 구도다. 기울이거나 돌린 판은 멜론 · 조롱박 · 버섯으로 보여 물렸다.

### 재료가 앉는 자리

**한 재료는 어느 떡에서나 같은 자리 · 같은 색이다.** 이 규칙이 있어야 떡 11장을 나란히 놓고 구별할 수 있다.

| 자리 | 재료 | 어떻게 보이나 |
| --- | --- | --- |
| 속(소) | 팥 · 잣 | 단면 가운데 |
| 겉(피 색) | 쑥 · 대추 | 떡 몸 색이 바뀐다 |
| 고물 | 콩 · 깨 | 콩은 겉이 통째로 노랗고, 깨는 갈색(`#8A5A2C`) 점 |

세 재료 떡(팥쑥깨떡)만 세 자리를 다 쓴다.

**아직 못 본 것** : 만들기 줄 24px 에서 흰 떡 셋(평범 · 깨 · 잣)이 서로 비슷하다. 사람이 보고 판정할 자리다.
