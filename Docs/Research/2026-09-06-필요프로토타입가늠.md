# 필요한 프로토타입과 ProtoTool 부품 가늠

> 지금 기획을 훑어 「무엇을 프로토타입으로 확인해야 하나」를 뽑고, 거기서 거꾸로 ProtoTool 에 필요한 부품을 가늠한 문서.
> 날짜 2026-09-06 · 상태 가늠(제안) — 물음 묶음 확정은 기획절차 4단계에서 사용자가 한다.

## 한 줄 결론

물음 17개 가운데 15개가 **숫자·시간·확률**이라 웹으로 답이 나고, 프로토타입 종류는 **넷(경제 시뮬 · 방치 시계 · 뽑기 시뮬 · 배치 격자)**이면 다 덮인다. 그래서 ProtoTool 1판은 **「틱이 도는 HTML 한 장 뼈대 + 기록/내보내기 + 목록」** 세 개면 시작할 수 있다.

## 부품 차례 (요약)

| 판 | 부품 | 왜 지금 |
| --- | --- | --- |
| **1판** | ① HTML 뼈대 한 장 (meta 덩이 · 상수 덩이 · 화면 그리기) | 모든 프로토타입이 여기서 시작한다 |
| **1판** | ② 틱 엔진 + 빨리 감기 | 우리 물음의 절반이 「시간」이다 |
| **1판** | ③ 기록(클릭·멈춤·논 시간) + JSON 내보내기 | 안 재면 판정 기준을 못 채운다 |
| **1판** | ④ 목록 페이지 `Prototypes/index.html` | 주말에 몰아서 보려면 입구가 하나여야 한다 |
| **2판** | ⑤ 자동 플레이 봇 뼈대 · ⑥ 꺾은선 그래프 하나 · ⑦ 뽑기 시뮬 헬퍼 · ⑧ 값 슬라이더 | 「30일 돌리면?」 「평균 몇 번?」 물음이 2판에 온다 |
| **나중** | ⑨ 격자 캔버스 헬퍼 · ⑩ 판정 표 출력 · ⑪ 저장/이어하기 · ⑫ Go CLI 승격 | 세 번 아쉬우면 그때 |

부품 상세와 공수 눈금은 4장에 있다.

## 3. 프로토타입 종류로 묶기

물음 15개를 넷으로 묶었다. **하나의 프로토타입은 물음 하나에 답한다**는 규칙은 그대로다 — 아래는 「같은 뼈대를 쓰는 무리」다.

### (가) 숫자만 도는 경제 시뮬

| 칸 | 내용 |
| --- | --- |
| 물음 | Q1 · Q5 · Q10 · Q11 |
| 화면 | 자원 숫자 줄(골드·재료·마릿수) · 버튼 몇 개(합성/설비/확장) · 상태 표 하나 |
| 자동 플레이 봇 | 「골드가 모이면 가장 싼 것을 산다」 같은 단순 규칙으로 N일 돌린다 |
| 기록 | 분마다 골드·마릿수, 멈춘 구간, 버튼별 누른 횟수 |

### (나) 시간이 흐르는 방치 화면

| 칸 | 내용 |
| --- | --- |
| 물음 | Q2 · Q4 · Q7 · Q8 · Q9 |
| 화면 | 진행 막대 여러 개(생산·합성·수집) · 「지금 줍기」 버튼 · 빨리 감기 ×1/×10/×60 |
| 자동 플레이 봇 | 없음 또는 「차면 바로 줍는다」 하나. 사람이 노는 것이 물음이다 |
| 기록 | 3초 넘게 아무것도 안 누른 구간의 수와 길이, 총 논 시간, 껐다 켠 시각 |

### (다) 확률·뽑기 시뮬

| 칸 | 내용 |
| --- | --- |
| 물음 | Q3 · Q6 · Q12 · Q13 |
| 화면 | 레시피 표 · 「합성 1회」 버튼 · 「1000회 돌리기」 버튼 · 결과 분포 표 · 도감 24칸 격자 |
| 자동 플레이 봇 | 정해진 목표(3단계 도달·도감 채우기)까지 반복하고 횟수를 센다 |
| 기록 | 목표까지 걸린 횟수의 평균·최소·최대, 갈래별 나온 비율 |

### (라) 배치 격자

| 칸 | 내용 |
| --- | --- |
| 물음 | Q14 · Q15 (그리고 나중에 Q16 의 절반) |
| 화면 | 농장 여러 칸을 세로로 쌓은 목록 · 칸마다 바닥 색과 마릿수 · 보관함 줄 · 끌어 옮기기 |
| 자동 플레이 봇 | 없음 |
| 기록 | 옮기기 횟수, 「바닥이 없어요」 안내가 뜬 횟수, 보관함 최대치 |

- (가)와 (나)는 **같은 틱 엔진**을 쓴다. 차이는 화면에 시계를 보여 주느냐다.
- (다)는 시간이 없어도 되고, **씨앗 난수**만 있으면 된다. 가장 만들기 싸다.
- (라)만 캔버스·끌기가 필요해 값이 비싸다. 그래서 뒤로 미룬다.

## 4. ProtoTool 부품 목록과 차례

3장의 종류에서 거꾸로 뽑았다. **공수는 전부 의견**이다 — 실측하면 고친다.

| 순 | 부품 | 무엇을 하나 | 어느 종류가 쓰나 | 판 | 공수(의견) |
| --- | --- | --- | --- | --- | --- |
| ① | **HTML 뼈대 한 장** | 파일 하나에 meta 덩이 · 수치 상수 덩이 · 화면 그리기 자리 · 기록이 미리 박힌 템플릿 | 전부 | 1판 | 2~3시간 |
| ② | **틱 엔진 + 빨리 감기** | 0.1초마다 도는 고리, ×1/×10/×60 버튼, 「N분 건너뛰기」 | 가·나·라 | 1판 | 1~2시간 |
| ③ | **기록 + JSON 내보내기** | 클릭 수·버튼별 횟수·3초 이상 멈춤·총 논 시간을 모아 파일로 저장 | 전부 | 1판 | 1~2시간 |
| ④ | **목록 페이지** | `Prototypes/index.html` — 하위 폴더의 meta 를 읽어 카드로 뿌림(제목·물음·기준·통과/불통) | 전부 | 1판 | 1~2시간 |
| ⑤ | **자동 플레이 봇 뼈대** | 「규칙 함수 하나만 채우면 N일을 빨리 돌려 준다」 | 가·다 | 2판 | 2~3시간 |
| ⑥ | **꺾은선 그래프 하나** | 시간축 값 하나를 그린다. 라이브러리 없이 캔버스 30줄 | 가 | 2판 | 1~2시간 |
| ⑦ | **뽑기 시뮬 헬퍼** | 씨앗 난수 · 「N회 돌려 평균·최소·최대」 · 분포 표 출력 | 다 | 2판 | 1~2시간 |
| ⑧ | **값 슬라이더** | 상수 덩이의 숫자를 화면 위 슬라이더로 빼서 놀면서 바꾼다 | 가·나·다 | 2판 | 1시간 |
| ⑨ | **격자 캔버스 헬퍼** | 칸 격자 그리기 · 칸 누르기 · 끌어 옮기기 | 라 | 나중 | 3~5시간 |
| ⑩ | **판정 표 출력** | 내보낸 기록 JSON 들을 모아 「물음 / 기준 / 통과·불통」 마크다운 표로 | 전부 | 나중 | 1~2시간 |
| ⑪ | **저장 · 이어하기** | localStorage 에 상태를 두고 껐다 켜면 그동안의 시간을 준다 | 나 | 나중 | 1~2시간 |
| ⑫ | **Go CLI 승격** | `proto new / list / report` 로 툴킷에 편입 | — | 나중 | 미정 |

- **1판 합계 눈금은 5~9시간**(의견)이다. 프로토타입 하나 만드는 값과 비슷하니 「툴이 게임을 잡아먹는」 위험은 낮다.
- ⑨는 값이 제일 비싼데 물음은 2개뿐이다. **Q14·Q15 는 (가) 안에서 숫자로 대신 재 보고**, 그래도 답이 안 나면 그때 만든다.
- ⑫ **저장소는 처음부터 따로 둔다** — `officina-game-prototype-tool` 을 만들어 `Tools/ProtoTool` 서브모듈로 붙인다 (2026-09-06 확정).
  다만 **1판은 Go 없이** HTML 템플릿 + 목록 생성 스크립트로 시작하고, **Go CLI 로 굽는 것은 부품을 세 번 이상 쓴 뒤에** 한다 (조사 6장 결론).

### 규약 (조사 3장 그대로 씀)

```
Prototypes/
  index.html            ← 목록
  2026-09-13-합성확률/
    index.html          ← 본체 한 파일 (CSS·JS 인라인)
    결과.md             ← 사용자가 논 뒤 한 줄씩
```

- **한 프로토타입은 한 파일이다.** 쪼개지 않는다.
- 파일 맨 위에 `proto-meta` JSON 덩이(물음·기준·만든날)를 둔다. 사람도 읽고 목록도 읽는다.

## 5. 첫 판 묶음 제안

**이건 제안이다. 4단계에서 사용자가 정한다.**

코어 루프에 가장 가까운 것 셋을 골랐다. 셋 다 (가)·(나)·(다) 종류를 하나씩 써서 **1판 부품이 다 맞는지도 같이 확인**된다.

| 프로토타입 | 답하는 물음 | 종류 | 필요한 부품 |
| --- | --- | --- | --- |
| 「고리가 닫히나」 | Q1 — 재료 → 골드 → 합성 → 재료 | 가 | ①②③④ |
| 「5분 기다림」 | Q2 — 1단계 대기 5분이 지루한가 | 나 | ①②③④ |
| 「3단계까지 몇 번」 | Q3 — 다른 계열 20% 로 평균 몇 번 | 다 | ①③④ (+⑦이면 편함) |

- 넷째를 넣는다면 **Q4(손으로 줍기)**가 후보다. (나) 뼈대를 그대로 쓰니 싸다.
- Q1 은 **가판대 눈금이 없으면 못 만든다.** 가판대 설계(진행상황 ④)가 먼저다. 그 전에 하려면 골드 수입을 임시 숫자로 박고 「구조만」 본다.
