# 떡 제작 과정(미니게임) 조사

> 「떡 만들기가 버튼 한 번이 아니라 과정이 있으면 좋겠다」를 풀기 위한 웹 조사다.
> 2026-09-12 · 조사 AI · 상태 조사 끝, 안 3개는 사용자 판단 대기
> 관련 결정 : mem `20260912-990981a2`(재료) · `20260912-bd560aa1`(레시피 24칸) · `20260912-00b020e4`(손님 판매) · `20260912-7151c951`(떡 값)

## 결론 먼저

- **틀은 이미 정해졌다** — 사용자가 고른 방식이다. **처음 시도하는 조합(미발견)만 제작 과정을 거치고, 한 번 찾은 레시피는 도감에서 탭 한 번에 즉시 만든다. 자동화 설비는 찾은 레시피만 만든다.** 이 틀은 조사한 게임 하나가 실제로 쓰고 있고(레시피 책 저장 → 한 번에 5개 일괄 제작), 리뷰에서 반복 지루함을 푸는 장치로 평가받는다.
- **권장은 안 1 「떡메 치기」** — 세로 한 손 엄지로 3~4번 탭, 한 번에 약 3초, 실패 개념 없음. 까닭은 3절 끝에 있다.
- **가장 큰 위험은 실험 속도**다. q1-2 프로토는 2분에 29번(≈4초/회) 만들었다. 3초짜리 과정을 붙이면 회당 7초가 되어 2분에 약 17번으로 **약 40% 느려진다**. 대책은 4절.

## 1. 자세히 본 둘

### 1-1. 붕어빵 타이쿤 (모바일·피처폰)

| 물음 | 답 |
| --- | --- |
| 손이 뭘 하나 | 아래쪽 붕어빵 틀 12개가 키패드 12버튼에 하나씩 대응한다. 반죽 넣기 → 알맞은 때 뒤집기 → 꺼내기를 버튼으로 한다. 위쪽 손님에게는 1~3번 버튼으로 개수를 준다 |
| 한 번에 몇 초 | 자료에 정확한 값이 없다. 틀 하나가 익는 데 몇 초 수준으로 **추측**한다. 여러 틀이 동시에 돌아가 손이 계속 바쁘다 |
| 지루함 막기 | 자동화는 없다. 대신 ① 틀이 반짝일 때 꺼내면 2개로 치는 황금붕어빵 ② OK 버튼으로 불을 잠깐 세게 해 빨리 굽기 ③ 요구가 다른 손님 종류로 변주한다 |
| 실패 | 있다. 덜 익거나 탄 것을 주거나, 손님을 그냥 보내면 **생명 게이지가 준다** |
| 레시피 발견 | 없다. 굽기 솜씨 게임이지 조합 게임이 아니다 |
| 이 게임에 맞나 | **과정 아이디어만** 쓸 수 있다(때 맞춰 꺼내기). 생명 게이지·시간 압박은 기둥 3(힐링)과 정면으로 부딪히니 안 가져온다 |

### 1-2. Potion Craft (PC) — 이 틀의 본보기

| 물음 | 답 |
| --- | --- |
| 손이 뭘 하나 | ① 재료를 절구에 넣고 **문질러 간다**(마우스를 끌어 회전) ② 솥에 넣고 **젓는다** ③ 물을 붓는다 ④ 풀무로 **가열해 효과를 굳힌다**. 메뉴 클릭이 아니라 도구를 직접 만지는 손맛이 핵심이다 |
| 간 정도의 뜻 | 곱게 갈수록 지도 위에서 그 재료가 **더 멀리 움직인다.** 「얼마나 하느냐」가 결과를 바꾸는 조절 손잡이다 |
| 한 번에 몇 초 | 정확한 값 자료 없음. 여러 재료를 갈고 젓고 가열하는 **분 단위 작업**이다(리뷰가 「가볍게 못 끝내는, 품이 드는 일」이라 표현). **추측** |
| 찾은 레시피 재제작 | **레시피 책에 저장하면 책에서 한 번에 5개까지 클릭 한 번으로 만든다.** 지도를 다시 짚을 필요가 없다. 저장 지점부터 이어 만들기(「여기서부터 계속」)도 된다. 재료가 모자라면 그때만 손으로 만든다 |
| 그게 지루함을 얼마나 줄이나 | 리뷰는 「손으로 가는 것이 지치고 짜증날까 봐 걱정했지만 촉감 설계로 살아남았다」고 하고, 레시피 책은 **반복을 기계적으로 없애 주는 동시에 「내 연구 노트」 역할**을 해 몰입을 더한다고 평가한다. 즉 **재미는 처음 한 번에, 반복은 책에** 둔 것이 통했다 |
| 실패 | 벌칙성 실패는 없다. 엉뚱한 자리에서 끝나면 값싼 물약이 될 뿐이다 |
| 레시피 발견과의 얽힘 | 발견 그 자체가 게임이다. 지도 위 미지의 자리를 더듬어 효과 표식에 닿는 과정이 곧 제작 과정이다 |
| 이 게임에 맞나 | **틀은 그대로 맞는다.** 다만 분 단위 정밀 조작은 모바일 세로·힐링에 무겁다. **과정을 초 단위로 줄여** 가져온다 |

## 3. 이 게임에 맞는 제작 과정 안 셋

셋 다 **미발견 조합에만** 나오는 과정이다. 찾은 레시피는 도감에서 탭 한 번, 자동화 설비는 찾은 레시피만 만든다.

| | 안 1 떡메 치기 | 안 2 손으로 빚기 | 안 3 찜기에서 꺼내기 |
| --- | --- | --- | --- |
| 손이 하는 것 | 반죽을 3~4번 리듬에 맞춰 탭 | 화면의 반죽을 엄지로 한 번 둥글게 문지른다 | 김이 오르는 찜기를 보다가 알맞은 때 한 번 탭 |
| 한 번에 몇 초 | 약 3초 | 약 2~3초 | 약 2~4초(기다리는 시간이 있다) |
| 실패 조합이면 | 다 치면 밋밋한 흰 떡이 나온다. 「평범한 떡」 표시만 | 같다. 모양은 나와도 속이 안 찼다는 연출 | 같다 |
| 발견 연출과 잇기 | 마지막 타격에서 화면이 번쩍 → 도감 칸 열림 | 문지르기가 끝나는 순간 떡이 뽀얗게 부풀며 열림 | 뚜껑을 여는 순간 김과 함께 열림 |
| 레시피 실험과 | 탭 3번이 곧 「해 볼래?」의 무게. 난사는 줄고 고르는 맛이 는다 | 가장 가볍다. 실험 속도를 거의 안 깎는다 | **기다림이 끼어 실험이 가장 느려진다** |
| 설비가 생기면 | 설비가 대신 친다(연출만 짧게). 미발견 조합은 여전히 손 | 같다 | 같다 |
| 기둥 1 방치 | ○ 3초라 짧고, 미발견 조합에만 나온다 | ◎ 가장 짧다 | △ 기다림이 붙으면 방치형에서 제일 미움받는 꼴 |
| 기둥 2 발견 | ◎ 타격의 마지막이 발견 순간과 딱 맞물린다 | ○ 부푸는 연출이 곱다 | ○ 뚜껑 열기는 「열어 보는」 맛이 있다 |
| 기둥 3 힐링 | ◎ 두드리는 촉감·소리가 편안하다 | ◎ 문지르는 촉감이 편안하다 | △ 「때를 놓치면 어쩌지」가 조급함을 만든다 |
| 기둥 4 원작 | ◎ 찹쌀떡을 만드는 그림 그대로다 | ○ 찹쌀이가 동글동글해지는 그림 | ○ |
| 걸리는 점 | 탭 3번이 24칸 채우는 동안 수백 번이 된다 | 과정이 너무 가벼워 「과정이 있다」는 느낌이 옅을 수 있다 | 기다림·때 맞추기가 기둥 1·3 둘 다를 건드린다 |

**AI 권장 : 안 1 「떡메 치기」.** 까닭 셋이다.
1. **기둥 셋(1·2·3)에 모두 ○ 이상**인 유일한 안이다. 안 3은 기둥 1·3을 깎고, 안 2는 사용자의 원래 바람(「과정이 있었으면」)을 가장 약하게 채운다.
2. **마지막 타격 = 발견 순간**이라 기능목록 38 「떡 만들기·새 떡 발견 연출」이 따로 붙는 장식이 아니라 과정의 끝에 저절로 얹힌다.
3. **탭 수를 조절해 시간을 조율할 수 있다.** 실험이 느리면 3번을 2번으로 줄이면 되고, 밋밋하면 늘리면 된다. 붙였다 뗐다가 쉬운 손잡이다.
   (안 2를 「가벼운 판」으로 남겨 두면 좋다 — 안 1이 무겁다고 판정되면 그대로 갈아 끼운다.)

**공통 못**
- **탭 결과가 떡 값·품질을 바꾸지 않는다.** 값 규칙(mem `20260912-7151c951`)은 재료·개수·특제·주문 넷으로 이미 닫혀 있다. 여기에 솜씨를 끼우면 벌칙이 되어 기둥 3과 부딪히고, 실험이 노동이 된다.
- **탭 도중 아무 데나 누르면 바로 끝난다(건너뛰기).** 24칸을 다 채운 뒤에도 새 조합을 시험할 수 있어야 한다.

## 4. 위험

| 위험 | 얼마나 | 대책 |
| --- | --- | --- |
| **미니게임 ↔ 방치 기둥** | 손이 바빠지면 방치가 아니다. 특히 손님 판매(mem `20260912-00b020e4`)와 겹쳐 「굽고 팔고」가 이어지면 붕어빵 타이쿤이 된다 | 과정은 **미발견 조합에만** 둔다. 찾은 떡은 탭 한 번, 설비는 자동. 방치 중에는 과정이 아예 안 돈다 |
| **실험 속도가 느려진다** | q1-2 프로토는 2분에 29번(≈4.1초/회)이었다. 3초 과정을 붙이면 **회당 약 7초 → 2분에 약 17번(-41%)**. 안 3(기다림 포함 4초)이면 -49%까지 간다 | ① 조합 공간이 이미 손으로 24칸에 묶여 있어(mem `20260912-bd560aa1`) **다 돌려 보는 게임이 아니다.** 찾는 재미는 2·3개짜리 10개에 몰려 있다 ② Should 인 「해 본 조합 표시」·「3재료 힌트」·「손님 주문 힌트」가 **난사 대신 추리**로 바꿔 준다 — 시도 수 자체가 줄면 회당 3초는 안 아프다 ③ 건너뛰기 탭을 둔다 ④ **탭 3번이 정말 아프면 2번으로 줄인다** |
| **q1-2 의 「빠른 실험이 재미였다」가 죽는다** | 실측으로 확인 안 된 위험이다. 프로토 없이는 모른다 | 가판대 프로토(손님 주문 판정 판)에 **「과정 있음 / 없음」 두 판**을 같이 재도록 붙인다. 재는 값은 2분간 시도 수와 「지루한가」 한 줄 |
| **개발 공수** | 안 1 기준 : 탭 판정·연출 만들기 반나절~하루, 떡 그림이 부푸는 스프라이트·소리 별도. 안 3은 타이밍 창·실패 처리가 붙어 1.5~2배. **추측이다 — EffortTool 실측이 아니다** | 8단계 세로 조각에서는 **판정 없는 3탭 연출**만 넣고, 촉감·소리는 마무리 품질 자리(기능목록 38)로 미룬다 |
| **탭 반복 자체의 지루함** | 24칸 × 여러 번 시도면 탭 수백 번이다 | 결과에 영향이 없으니 **길게 누르면 3탭이 한 번에** 나가는 대체 조작을 둔다 |
