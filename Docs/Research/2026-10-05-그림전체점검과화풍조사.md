## 1. 한 줄 결론

- **도트 굵기는 111장 모두 1px 로 맞다.** 반투명 칸도 0 이다. 흔들리는 것은 **외곽선 색 · 아이콘의 빈 여백 · 코드가 줄여 찍는 배율** 셋이다.
- **v16 피드백 셋 중 둘은 그림 + 코드 문제, 하나는 코드 문제다.**
  떡은 32 캔버스 아래 **9px 가 비어** 떠 보이고, 손님 귀는 **머리 외곽선(검정)과 다른 붉은 갈색 선**으로 그려져 겉돌고, 서랍 찹쌀이는 코드가 **×0.5** 로 줄여 찍는다.
- **화풍의 기준은 「전용 화면 · 메인 v15」 쪽(어두운 따뜻한 갈색 선 · 빛 위쪽 · 1px)으로 모으는 것이 가장 덜 고친다.** 그쪽 그림이 장수도 많고 사용자가 이미 좋다고 했다.
- **ArtTool 템플릿은 우리 크기의 절반만 받는다.** 손님 120×240 · 찹쌀이 덩어리 몸 · 진열장 176×123 · 말풍선 54×29 등은 템플릿이 없다.
- **06-아트규칙 문서가 낡았다.** 360×640 · 「외곽선 없음 기본」이 그대로인데, 10-03 결정(mem `20261003-83b852e7` : 540 통일 · 순검정 아닌 어두운 선 1px · 명암 3단)과 다르다.

## 5. v16 피드백 셋의 원인

### 5-1. 「진열대 떡이 공중에 떠 있고 말풍선 떡도 위로 붙은 느낌」 → **그림 + 코드 둘 다**

- **그림** : 떡 11장이 모두 bbox `(0, 5) ~ (30, 23)` 이다. 32 캔버스의 **아래 9줄 · 위 5줄 · 오른쪽 2줄이 비어 있다.** 아래 바닥 그림자도 없다.
- **진열장** : 코드는 캔버스 아래끝을 접시 줄(`StallLayout.PlateCakeBottom` 45 · 83)에 맞춘다. 그래서 떡이 실제로 닿는 줄은 **36 · 74** 다.
  진열장 그림의 접시는 눈으로 재면 y 약 33~49 · 71~87 이라, 떡 밑면이 접시 **뒤쪽 테두리** 높이에 걸린다 → 접시 위에 안 앉고 떠 보인다.
  비교 그림 `feedback/cake_on_case_x4_left_canvas_right_trimmed.png` 왼쪽(지금)과 오른쪽(bbox 바닥을 접시 줄에 맞춤)을 보면 오른쪽이 접시에 앉는다.
- **진열장 유리 칸이 투명**이라 떡 뒤가 배경 벽이다. 떡에 외곽선이 없어(진열장은 갈색 선) 붙여 놓은 느낌이 더해진다 (눈으로 본 것).
- **말풍선** : 9-slice `ui_bubble` 높이 54 · 테두리 위 12 · 아래 20(꼬리). 안쪽은 아래에서 20~42 줄이다.
  떡 캔버스는 아래 16 에 놓여 실제 떡이 **25~43 줄** — 위 테두리에 1줄 걸치고, 안쪽 가운데(31)보다 **3줄 높다.** 「위로 붙은 느낌」 그대로다.
- **고치는 길 두 가지** (정하지 않음) : ① 그림을 아래로 붙여 다시 굽기 (bbox 바닥 = 캔버스 바닥 − 1, 가로 가운데). PIL 로 크레딧 0 · 몇 분. 다른 자리(도감 · 발견 연출 · 만들기 줄)도 같이 내려간다. ② 코드에서 떡마다 아래 여백 9 만큼 내려 찍기. 그림을 안 건드린다.

## 12. 못 본 것

- **Unity 화면 · 폰에서는 안 봤다.** 떡 · 서랍 · 말풍선의 화면 좌표는 코드 상수와 그림을 셈해 낸 값이다. 진열장 접시 높이는 눈으로 잰 값이다.
- 찹쌀이에 **종 색을 곱한 모습**은 안 봤다 (`body_hop3` 얼룩이 보이는지 모름).
- 화면 배경 셋은 `sheet` 1배 판만 만들고 **열어 보지 않았다** (턴을 줄였다). 배경 · UI 는 숫자로만 적었다.
- `template render --over` 는 셋만 했다 (기계 · 찹쌀이 · 떡).
- `check` 는 프로필 없이 돌려 `outline` · `ramp_shape` · `loop_seam` 경고가 안 나왔다. 게임 프로필을 만든 뒤 다시 돌려야 한다.
- 빛 방향 판정은 「위 · 모름」 이 많아 왼쪽 위인지 숫자로 가르지 못했다. 눈으로는 건물 · 기계 · 손님이 왼쪽 위로 보였다.
- 크레딧 · 공수 어림은 지난 README 판당 값에서 셈한 것이다 — 실제로 뽑아 보지 않았다.
