# 아트 생성 AI 와 오픈소스 조사

> PixelLab 말고 다른 AI 가 더 나은 자리가 있는지, 우리 게임의 베이스·템플릿·배경·UI 기반 이미지를
> 무엇으로 만들지, AI 가 아닌 오픈소스·CC0 로 되는 곳은 어디인지, ArtTool 을 보충하는 쪽이 나은 자리는
> 어디인지, AI 가 직접 조작할 수 있는 픽셀아트 편집 툴은 무엇인지를 네 갈래로 나눠 조사해 합친 문서.
> 날짜 2026-09-09 · 쓴 사람 AI (사용자 확인 전) · 상태 조사 1판

## 1. 결론 먼저

- **PixelLab 을 바꿀 이유가 없다.** 캐릭터·회전·애니·타일셋을 한 곳에서 하고 API·MCP 가 있다.
- **그런데 ArtTool 코드에서 PixelLab 을 아직 못 부른다.** `pixellab` 제공자가 껍데기다. 새 AI 를 더 찾기 전에 이걸 먼저 붙여야 한다.
- **UI 와 지형 타일은 AI 가 필요 없다.** ArtTool 이 이미 9-slice 패널·버튼·바를 그리고, 타일 6장에서 47장을 뽑는다.
- **아이콘·폰트는 CC0·OFL 기성품으로 닫는다.** AI 로 60~100개를 뽑으면 톤이 흔들린다.
- **AI 가 꼭 필요한 자리는 둘뿐이다** — 캐릭터 베이스 12종의 새 실루엣, 배경 한 장 그림·패럴랙스.
- **UI·배경도 PixelLab MCP 로 먼저 시험한다.** 공식 MCP 에 `create_ui_asset`·`create_font`·`create_map_object`·`create_image_*` 가 다 있다 (확인함). **부족할 때 SpriteCook 을 2차로 본다.**
- **「사람이 Aseprite 로 손보는 자리」도 AI 가 일부 대신할 길이 있다.** Aseprite MCP 서버가 픽셀 단위까지 열려 있어, 팔레트·규격·태그 같은 규칙 있는 손질은 AI 가 맡길 수 있다. 「예쁜가」 판단만 사람 몫이다.
- **에테르AI 는 돈 내고 써 본 독립 후기가 0건이다.** 공식 홈 후기 5개는 광고문이다. 1차로 삼지 말고 **₩4,900 첫 팩으로 소액 시험**만 한다.
- **Aseprite 는 스팀판이어도 CLI·Lua·MCP 가 다 된다.** 바이너리가 같고 DRM 이 없다. `-b --noinapp` 이면 스팀도 안 뜬다.
- **값은 판정에 넣지 않았다.** 필요하면 결제한다는 전제라, 판정은 **① 진짜 픽셀 격자 ② 우리 용도(베이스·배경·UI) 커버 ③ API/MCP ④ 상업 이용 약관** 넷으로만 매겼다. 값은 참고 열이다.

| 용도 | 가장 나은 수단 | 왜 |
| --- | --- | --- |
| 캐릭터 베이스 12종 | **PixelLab** | 새 실루엣은 코드가 못 만든다. 오픈소스에도 우리 슬라임은 없다 |
| 템플릿(변종 12) | **ArtTool 코드 — 보충 필요** | 팔레트 스냅·LUT 는 있는데 12벌 한 번에 도는 명령이 없다 |
| 지형 타일 | **ArtTool 코드 — 이미 됨** | `tile blob` 이 6장 → 47장. AI 는 이음새를 못 맞춘다 |
| 배경 한 장·패럴랙스 | **PixelLab (`create_image_*` + `image_to_pixelart`)** | 툴에 자리 자체가 없고 코드 생성기는 「프로그래머 아트」가 된다. MCP 에 배경용 이미지 생성·픽셀화 도구가 있다 |
| UI 패널·버튼 | **ArtTool 코드 — 이미 됨** | `ui frame` 이 9-slice 3상태를 결정적으로 찍는다 |

| 폰트 | **오픈소스 OFL (물마루 · 갈무리)** | AI 폰트는 한글 글자 수에서 무너진다 |

### 2-1. 에테르AI 심층 — 사용법·후기·값

**한 줄 : 1차로 삼기엔 근거가 모자란다. 실사용 후기가 0건이다.**

**작업 흐름** — 이미지 생성 → 편집 → 스프라이트 애니 → 리스킨 → 내보내기.

| 이미지 생성 | 글·그림으로 원본 생성. **GPT·Gemini·Grok 등 남의 모델 API 를 골라 쓴다** (확인함). 기획서 TXT 를 올리면 에셋 목록·프롬프트를 뽑는 「AI 오케스트레이션」도 있다 | — |
| 편집 | 화질 올리기(1K·2K·4K) · 배경 제거 · 부분 다시 그리기 · **픽셀화** · 레이어 분리(3~5조각) | — |

| 내보내기 | 스프라이트 시트 · GIF (확인함). 홈 소개문엔 Lottie·JSON 도 (3자). **픽셀 크기는 32·48px** | — |

**「오른쪽 보기 권장」은 8방향 회전을 기대하기 어렵다는 신호다** (추측). 우리 슬라임처럼 단순한 놈에겐
V1 조건(단색 배경·물체 하나)이 잘 맞는다.

**값** — 첫 구매 70토큰 **₩4,900 / $3.49** (첫 1회 한정, 확인함). **정가 토큰표와 약관은 로그인 벽이라 못 봤다.**
GPU 구독 월 35만/55만원은 3자 근거다. **토큰 1개로 무엇이 몇 개 나오는지도 못 찾았다 — 이게 가장 큰 구멍이다.**
전용 모델 학습(그림 20~80장)은 값이 비공개인 **B2B 상담 상품**이다.

**자동화** — **API·MCP·Unity/Aseprite 플러그인이 전부 없다.** 문의처는 회사 홈페이지의 메일 하나뿐이다.

### 3-3. VRAM 단계

- **8GB 이하** — SD1.5 추론·SD1.5 LoRA 학습·IP-Adapter·**PixelArt-Detector 후처리 전부** 된다. SDXL LoRA 학습·Flux 는 안 된다.
- **12GB** — SDXL 추론이 여유롭고 SDXL LoRA 학습이 최소선으로 들어간다. Flux 는 양자화 추론까지.
- **16GB 이상** — SDXL LoRA 편하게, Flux LoRA 학습까지 된다.

**GPU 가 약해도 UI·아이콘·후처리는 전부 된다.** 로컬 GPU 는 캐릭터·배경 생성 한 곳에만 필요하다.

### 3-4. 닭-달걀 — 로컬 SD 로 캐릭터 일관성은 지금 못 잡는다

**같은 톤의 슬라임 24종을 로컬로 맞추려면 LoRA 자체 학습이 필요한데, 학습하려면 「우리 스타일 그림
10~30장」이 이미 있어야 한다. 그 그림이 아직 없다.** 그래서 처음 12종에는 못 쓴다.
로컬 LoRA 가 값을 하는 때는 **PixelLab 으로 12종을 뽑은 다음** — 그걸 학습해 배경·프롭·추가 종을
같은 톤으로 계속 찍는 자리다.
또 로컬 SD 는 **그냥 뽑으면 픽셀 격자가 안 나온다.** pixel-art-xl 공식 안내가 「8배로 축소해야
픽셀 퍼펙트가 된다」이다 (확인함). 즉 생성 뒤 축소·팔레트 제한 후처리가 무조건 붙는다.

### 4-2. 가장 큰 함정

**`pixellab` 도 `local` 도 실제 호출이 안 붙어 있다. 둘 다 요청 JSON 만 쓰고 `--dry-run` 이 아니면
예외를 던진다** (`providers/pixellab.py:56`, `providers/local.py:38`).
즉 「PixelLab 을 쓰기로 했다」는 결정이 **코드에는 아직 없다.** Pro 결제까지 했는데 코드에서 못 부른다.

또 `ProviderRequest` 의 `KINDS` 가 `("character","tile","rotate","skeleton")` 넷뿐이라
**`background` 도 `ui` 도 표현이 안 된다** (`providers/base.py:14`). 배경에 필요한 이어짐(seamless)·층 수·
화면비 같은 필드도 없다.

### 4-3. 보충 안

- **(ㄱ) `local` provider 에 진짜 호출 붙이기** — `local.py:30 make` 에 HTTP POST + 폴링 + PNG 저장. `KINDS` 에 `background`·`ui` 추가. **12~20시간(추측).** 돈이 안 들고 무제한 재시도가 되지만, 미니PC 사양이 미실측이고 픽셀 품질이 PixelLab 만 못할 가능성이 크다.
- **(ㄴ) 「팔레트 배치」 명령 추가 — 가장 값싸고 확실** — `cli.py` 에 `palette variants`, `palette.py` 에 `build_variants`. 베이스 한 벌 + 램프 12개 → 변종 12벌. **4~6시간(추측).** 24종의 뒤 12종을 AI 없이 0원에 끝낸다. 모양이 같아야만 통한다.
- **(ㄷ) UI 는 AI 없이 「CC0 팩 + 프레임 생성기」로 닫기** — `palettes/ui_panel.json` 색값 채우기 + CC0 픽셀 UI 팩을 `ui icons` 로 자르기 + 한글 픽셀 폰트 ttf 받기. **3~5시간(추측).** 오늘 당장 UI 기반 이미지가 나온다. 팩 톤이 우리 슬라임 톤과 다를 수 있다.
- **(ㄹ) 배경용 층 합성 코드 생성기 — 권하지 않는다.** 공수 20시간 이상인데 결과가 「프로그래머 아트」로 보여 버려질 확률이 높다.

### 4-4. 순서 판단

**「AI 를 더 찾기」와 「툴 보충」은 경쟁이 아니라 분업이다. 다만 지금 순서가 잘못됐다 —
새 AI 를 고르기 전에 `pixellab` 실제 호출부터 붙여야 한다.**

### 짚어 둘 것 셋

- **Pixelorama 는 headless 로 내보내기만 된다.** 공식 CLI 에 그리기·레이어·팔레트 편집 옵션이 아예 없다 (확인함). 편집을 시키려면 커뮤니티 MCP 서버를 따로 얹어야 한다.
- **Aseprite Lua 는 픽셀 단위까지 열려 있다.** `Image:drawPixel`·`getPixel` 부터 `app.command` 로 메뉴 기능 전부까지 닿는다. 그래서 MCP 서버가 여섯 개나 생겼다.
- **`.aseprite` 파일은 Python 에서 바로 읽을 수 있다** (`asepriteio` · `aseprite-reader`). 내보내기 전에 ArtTool 이 검수할 수 있다는 뜻이다.

### 권하는 안 — 규격·검수·굽기는 ArtTool, 모양 손질만 Aseprite MCP

- 팔레트 강제·색 수 축소·여백/앵커 정렬·시트 조립·JSON 메타는 **ArtTool 이 Python 으로** 한다. 결정적이라 검수와 궁합이 좋다.
- 선 정리·프레임 튐 잡기 같은 **모양 손질만 `diivi/aseprite-mcp`** 에 맡긴다.
- **예상 공수 4~8시간 (추측)** — MCP 설치·검증 2h + ArtTool 과의 경계 정하기 2h + 손질 프롬프트 다듬기 2~4h.
- 반대로 **검수·굽기까지 MCP 에 맡기는 것은 위험하다.** LLM 은 매번 조금씩 다르게 굽는다 — 규격 검수가 결정적이지 않게 된다.

### 5-1. Aseprite 스팀판으로도 되나 — **된다**

스팀에서 사도 CLI · Lua · MCP 를 다 쓸 수 있다. 바이너리가 같고 DRM 이 없다.

| 스팀판에서 `--batch`·`--script`·`--version` | **된다.** 같은 `Aseprite.exe` 다 | **공식 CLI 문서가 Windows 스팀 경로 `C:\Program Files (x86)\Steam\steamapps\common\Aseprite\Aseprite.exe` 를 예시로 적어 놓았다** (확인함, aseprite.org/docs/cli) |
| 스팀 클라이언트를 켜 놔야 하나 | **아니다.** exe 를 바로 실행하면 스팀 없이 돈다 | 공식 FAQ 가 「완전 DRM-free」라고 못박았다 (확인함) |
| 배치로 돌릴 때 스팀이 뜨는 문제 | **`--noinapp` 이 막는다** (「게임 중」 표시·플레이타임 안 셈). 1.3.15.5 부터는 `-batch` 만 써도 자동으로 켜진다 | **GitHub 이슈 #5482 — 개발자 dacap 본인이 2025-10-24 개설, closed, 마일스톤 v1.3.15.5, 제목이 「`-batch` 쓰면 `-noinapp` 자동」** (확인함) |
| 권장 인자 | **`-b --noinapp`** 을 항상 같이 쓴다. 옛 판에서도 맞고 새 판에서도 해가 없다 | 추측(안전 쪽 권장) |
| MCP 가 경로를 잡는 법 | Vollkorn-Games = **스팀 위치를 자동 탐색**(손이 제일 덜 간다) · diivi = `.env` 의 `ASEPRITE_PATH` · pixel-mcp = **설정 파일에 절대 경로 필수**(자동 탐색·환경변수 없음) | 각 README (확인함) |
| 어디서 살까 | **공식 직판이 스팀 키를 덤으로 준다.** 스팀에서 사면 itch 키는 없다 | FAQ (확인함) + Steam 토론 (3자) |
| 스팀 구매자가 독립 설치본을 받나 | 스팀 계정으로 aseprite.org 에 로그인해 받는다는 포럼 글이 있으나 **시점이 불확실하다** | Steam 토론 (3자) |
| EULA 가 자동화·CLI 를 막나 | **안 막는다.** 막는 것은 제3자 배포·리버스 엔지니어링뿐이다. **AI 에이전트가 CLI 로 조작하는 것은 그냥 CLI 사용이다** | EULA.txt 전문 (확인함) |
| 소스 빌드 | 라이선스상 가능(개인 목적 컴파일 허용)하나 **할 이유가 없다.** 스팀판이 안 막힌다 | EULA (확인함) + 추측(빌드 난이도) |

## 6. 어긋난 곳 정리

| 무엇 | 어긋남 | 어느 쪽이 맞나 |
| --- | --- | --- |
| **9-slice 패널 생성기** | 오픈소스 조사는 「쓸 만한 오픈소스가 없어 Pillow 로 직접 짜야 한다(30~60줄)」고 했다. ArtTool 조사는 **`ui/frame.py:190 draw` 에 이미 있다**고 코드로 확인했다 | **ArtTool 쪽이 맞다.** 이미 있으니 새로 짜지 않는다. 남은 건 램프 색값뿐 |
| **UI 아이콘을 무엇으로** | AI 조사는 Recraft 유료(벡터)를 권했다. 오픈소스·ArtTool 조사는 CC0 팩을 권했다 | **CC0 팩 우선.** 개수가 많아 톤 흔들림이 제일 큰 위험이다. 벡터가 꼭 필요할 때만 Recraft |
| **PixelLab 에 UI 기능이 있나** | AI 조사는 「랜딩에는 있으나 API 엔드포인트 목록에 UI 전용이 없다」고 했다. ArtTool 조사는 기존 게임 문서에 `create_ui_asset`·`create_font` 가 적혀 있다고 인용했다 | **풀렸다 — 있다.** 공식 MCP 문서를 직접 확인함 : `create_ui_asset`·`get_ui_asset`·`create_font`·`create_map_object`·`create_map`·`create_building_kit`·`create_path_tiles`·`create_image_pixflux`/`pixen`/`pro`·`image_to_pixelart`·`correct_pixelart`·`reduce_colors`·`inpaint_image`. **UI·폰트·맵 오브젝트·배경 이미지·픽셀 보정이 다 있다.** ArtTool 조사 쪽이 맞았다 |
| **CC0 배경 팩을 쓸 수 있나** | AI 조사는 배경을 AI 로 뽑자고 했고, 오픈소스 조사는 CC0 배경 팩을 찾았다 | **둘 다 부분만 맞다.** 찾은 팩이 대부분 가로 플랫포머용 320×180 패럴랙스라 세로 화면 농장엔 안 맞는다 |
| **한글 픽셀 폰트 어느 것** | 오픈소스 조사는 물마루를 1순위로 뒀고, ArtTool 조사는 갈무리 ttf 를 받으려던 상태로 적혀 있다 | **아직 못 정한다.** 둘 다 OFL 계열이라 고르기만 하면 된다 |
