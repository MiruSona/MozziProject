# 그림풍 레퍼런스 조사 — 프로토타입 화면을 「게임처럼」

> 반복 03 피드백 5·6번(정식 UI · 메인 화면 배치)에서 나온 조사다. 사용자가 고른 게임 여섯과
> 「농장 경영 도트 게임」 넷을 훑어 **그림 기준 초안**과 **메인 화면 배치 안**을 냈다.
> 날짜 2026-10-03 · 조사만 했다 · 상태 **제안 단계, 결정은 사용자**

**베끼지 않는다.** 아래 게임들은 **화풍과 수치를 재는 자**로만 쓴다. 그림은 저장소에 한 장도 안 넣었다
(스팀·구글 플레이 공개 스크린샷을 임시 폴더에서 재고 버렸다). 기획서(`Docs/Design/`)로 옮길 때는
게임 이름을 「같은 갈래의 2D 농장 게임」처럼 바꿔 쓴다.

## 1. 결론 먼저

- **그림풍의 중심(숲속의 작은 마녀)은 「작은 픽셀 + 색 외곽선 + 낮은 채도 + 종이·나무 UI」다.**
  화면은 **480×270 을 4배**로 키운 것이고(실측), 주인공은 **모자까지 약 33px**밖에 안 된다(눈대중).
  세밀해 보이는 까닭은 해상도가 아니라 **색 단(3단) · 검정 없는 외곽선 · 풀·나무의 덩어리 무늬**다.
- **우리 게임은 지금 픽셀 굵기가 둘이다.** 농장 월드는 540×960(1080 폰에서 ×2), UI·가판대 화면은 360×640(×3)이다
  (`LayoutConst.cs`). 「주인 128×160 이 배경·손님과 굵기가 안 맞는다」는 고민의 뿌리가 여기다.
- **권하는 안 : 기준을 540×960 하나로 통일한다 (UI 도 같이).** 그러면 주인 128×160(몸 78×125)을 **줄이지 않고 그대로** 쓸 수 있다.
  화면 높이의 13% 라 지금 64×80(몸 77px, 640 의 12%)과 **화면에서 보이는 크기는 거의 같고 픽셀만 잘아진다.**
  값은 치른다 — 손님·화면 배경·UI 를 540 기준으로 다시 뽑아야 한다 (어차피 정식 그림으로 바꿀 것들이다). 4절.
- **메인 화면은 「하늘 띠 → 먼 숲 띠 → 건물 줄 → 농장」 한 화면 고정을 권한다 (가안).** 세로 폰 픽셀 농장 게임이 실제로 이 배치를 쓴다(3절 I).
  하늘은 **남는 세로를 받아 주는 늘어나는 띠**로 둔다 — 피드백 1·2번(아래로 붙이고 위는 하늘)과 같은 답이다. 5절.
- **중심 레퍼런스에는 하늘이 없다.** 탑다운이라 하늘이 안 보인다. 하늘·원경은 옆에서 본 게임(B · E)에서 따로 가져와야 하고,
  **탑다운 농장 위에 하늘을 얹을 때 이음매를 가리는 띠(먼 숲·울타리)가 꼭 필요하다.**
- **메뉴는 오른쪽 가장자리 세로 줄을 권한다.** 조사한 게임 중 오른쪽 세로 메뉴를 쓰는 본보기는 **못 찾았다** — 다들 아래 가운데·위 구석이다.
  그래서 이 자리는 프로토로 손가락에 닿는지 직접 봐야 한다.

### B. Doloc Town

RedSaw Games Studio · 2026-08-05 정식(스팀 표기). **옆에서 본 단면** 농장 게임이다.

- 화면 480×270 ×4 (실측 3장). 캐릭터 약 25px(눈대중). 색은 **녹슨 회색·황토 바탕 + 풀 초록·컨테이너 빨강 포인트**.
- **하늘·원경이 가장 좋은 본보기다.** 하늘은 단색에 가까운 청록, **뭉게구름은 3톤**, 먼 도시는 **하늘색에 가까운 한두 톤 실루엣**이다.
  멀수록 하늘색에 묻히게 칠해 깊이를 낸다.
- 화면 가장자리가 살짝 어둡고 빛 번짐이 있다 — 픽셀 그림 위에 후처리를 얹었다.
- 볼 곳 : [스팀 상점](https://store.steampowered.com/app/2285550/Doloc_Town/) ·
  [하늘·원경](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/2285550/39b48b0d7ceb343c03e3b305918d1a555f563ca7/ss_39b48b0d7ceb343c03e3b305918d1a555f563ca7.1920x1080.jpg) ·
  [쌓아 올린 농장](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/2285550/998d632ad2708a94a108b72eabbdd318c690c28b/ss_998d632ad2708a94a108b72eabbdd318c690c28b.1920x1080.jpg)
- **가져올 점** : 하늘 띠 그리는 법(단색 + 3톤 구름 + 먼 실루엣). **안 맞는 점** : 시점이 달라 건물·농장은 못 쓴다. 폐허 분위기도 우리와 다르다. UI 는 화면에 안 나와 못 봤다.

### C. Stardew Valley

- 타일 16×16 · 캐릭터 16×32 · 실행할 때 ×4 로 키운다 (출처 : 공식 포럼의 모드 제작 글 — 개발자 발표는 아니다).
- UI 는 나무 틀에 누런 종이 패널, 아래 가운데 도구 줄, 오른쪽 위 시계 — **이번에 화면을 다시 보지 않고 기억으로 적었다.**
- 볼 곳 : [포럼 — 스프라이트 크기](https://forums.stardewvalley.net/threads/sprite-sizes-character-sheets-pixel-art.5597/)
- **가져올 점** : 나무·종이 UI 의 대표 격이라 9조각 패널 본보기로 쓴다. **안 맞는 점** : 16px 격자는 우리(타일 32)보다 훨씬 굵다. 색도 A 보다 세다.

### D. 위시 어폰 어 라마 (Wish Upon A Llama)

영문 표기를 찾았다 — **Wish Upon A Llama**, Millionhare Studios 개발 · Whitethorn Games 배급 · 스팀 표기 「2026」(아직 안 나왔다, 체험판 있음). 동물을 기르는 생활 게임이다.

- **픽셀 격자가 하나로 안 잡힌다** (실측 3장 모두). 초상화·UI·월드의 픽셀 굵기가 서로 달라 보인다(눈대중) — **우리가 지금 겪는 문제와 같은 꼴**이라, 섞으면 어떻게 보이는지의 본보기다.
- **가게 정면이 좋은 본보기다.** 건물은 정면으로 세워 **줄무늬 차양 · 큰 유리창 · 간판 글자 · 앞 화단**을 그린다. 색은 분홍·연보라·하늘 파스텔.
- UI 는 분홍 종이 패널에 갈색 나무 테두리, 왼쪽 위 할 일 · 오른쪽 위 날짜와 돈.
- 볼 곳 : [스팀 상점](https://store.steampowered.com/app/2262630/Wish_Upon_A_Llama/) ·
  [가게 정면](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/2262630/ss_c77428d0045d09a0363a75cf73296eba0d4c8f92.1920x1080.jpg)
- **가져올 점** : 현대 카페풍 가판대 바깥 모습(차양·유리창·간판). **안 맞는 점** : 3등신 사실풍 초상화는 우리 SD 와 다르다. 굵기 섞임은 따라 하지 않는다.

### E. Terraria

- 타일 한 칸 16px (출처 : 공식 위키 틀 문서). 「그림을 2×2 로 키워 그린다」는 커뮤니티 글에서만 봤다 — **공식 확인 못 함**. 캐릭터 크기도 못 확인.
- 옆에서 본 단면이고, 하늘은 여러 겹 원경이 따로 움직인다(기억 — 이번에 화면을 안 봤다).
- 볼 곳 : [위키 틀 문서](https://terraria.wiki.gg/wiki/Template:Real-life_size/doc)
- **가져올 점** : 원경을 겹으로 나눠 천천히 움직이는 것(하늘 띠가 살아 보인다). **안 맞는 점** : 시점 · 전투 게임의 센 색.

### F. Discounty

## 4. 그림 기준 초안

지금 규칙은 `Docs/Design/06-아트규칙.md` 다. 아래는 **그 문서를 고치자는 제안**이고, 정해지기 전에는 그 문서가 그대로 기준이다.

### 4-1. 해상도와 픽셀 굵기 — 주인 128×160 고민의 답

**지금** : 1080×1920 폰에서 농장 월드(540×960)는 한 픽셀이 화면 2칸, UI·가판대·합성소(360×640)는 3칸이다.
농장의 건물 그림은 ×1.5 로 늘려 찍어 픽셀이 고르지 않다. **굵기가 둘인 것이 「프로토타입 같다」의 큰 까닭으로 보인다** (추측 — 사용자 판정).

| 안 | 기준 | 주인 | 다시 뽑을 것 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- | --- | --- |
| **가 (권함)** | **540×960 하나** (월드 + UI) | **128×160 그대로** (몸 78×125) | 손님(약 1.5배) · 화면 배경(540×1200) · UI 전부 | 굵기 하나. 세밀한 주인을 줄이지 않는다. 찹쌀이·타일·아이콘은 이미 540 월드용이라 그대로 | 720·1440 폭 폰에서 배율이 정수가 아니다(×1.33 · ×2.67). 손님 겹 46장을 다시 뽑는다 |
| 나 | 360×640 하나 (월드도 되돌림) | 64×80 또는 96×120 판(몸 43×77) | 농장 칸 수가 가로 17 → 11 로 줄어든다 | 720·1080·1440 모두 정수 배율. 지금 가판대 그림 그대로 | 세밀한 주인을 못 쓴다. 반복 01 에서 「칸을 더 보이게」 정한 것을 뒤집는다 |
| 다 | 지금처럼 둘 (월드 540 · UI 360) | 가판대는 64×80 | 없음 | 일이 없다 | 굵기가 안 맞는 문제가 그대로 남는다 |

- **가안에서 주인 크기 셈** : 몸 125px ÷ 960 = 화면 높이의 **13%**. 지금 몸 77px ÷ 640 = **12%**. 화면에서 보이는 키는 같고 픽셀만 1.5배 촘촘해진다.
  A 의 주인공도 33px ÷ 270 = 12% 다 — **화면에서 차지하는 크기는 레퍼런스와 같은 눈금**이다.
- **가안의 숨은 조건** : UI 캔버스 기준을 540×960 으로 올려야 한다. 지금 UI 프리팹은 왼쪽 위 절대 자리라 기준을 올리면 깨진다고 적혀 있다(mem `20261003-1e2259a1`).
  UI 를 정식 그림으로 갈면서 **같이 다시 놓는다**는 전제다. 코드 쪽 공수는 이 조사에서 안 쟀다.
- **세밀함은 해상도만으로 안 나온다.** A 는 33px 캐릭터로도 풍성해 보인다. 가안으로 가도 아래 4-2 의 색·외곽선 규칙을 같이 맞춰야 한 게임처럼 보인다.

## 5. 메인 화면 배치 안

글자 상자 그림은 안 그린다 (그림 규칙). **위에서 아래로 띠를 표로** 적는다. 높이는 540×960 기준이고 **하늘 띠가 남는 세로를 다 받는다.**

### 가안 — 한 화면 고정 (권함)

| 위에서부터 | 높이 | 무엇 |
| --- | --- | --- |
| 하늘 | 약 150 (늘어남) | 단색 하늘 + 3톤 구름. 왼쪽 위에 재화 캡슐(나무) 한 줄 |
| 먼 숲 | 약 50 | 한두 톤 실루엣. **하늘과 탑다운 땅의 이음매를 가린다** |
| 건물 줄 | 약 220 | 왼쪽 합성소 · 가운데 카페(가판대) · 오른쪽 창고 상자. 누르면 그 화면이 열린다 |
| 농장 | 약 540 (가로 17 × 세로 약 17칸) | 풀밭 · 찹쌀이 · 재료 더미. 맨 아래는 울타리나 덤불 띠 |
| 오른쪽 가장자리 | 폭 약 64 · 농장 띠 위에 겹침 | 주요 메뉴 3개는 늘 보임 + 맨 아래 **☰** 를 누르면 위로 목록이 펼쳐진다 |

- 좋은 점 : 한눈에 다 보인다. I(세로 픽셀 목장)가 실제로 쓰는 배치다. 방치형은 켜자마자 전체가 보여야 한다.
- 나쁜 점 : 건물이 작다(주인 키의 1.7배쯤). 오른쪽 메뉴가 농장 2칸 폭을 가린다.

### 나안 — 건물을 크게, 길을 낀 마을

| 위에서부터 | 높이 | 무엇 |
| --- | --- | --- |
| 하늘 + 먼 숲 | 약 120 (늘어남) | 가안과 같다 |
| 건물 줄 | 약 300 | 카페를 **정면 가게**(차양·유리창·간판)로 크게. 합성소는 옆, 창고 상자는 가게 앞 |
| 길 | 약 60 | 손님이 지나다닌다 — 가판대 화면을 안 열어도 장사하는 것이 보인다 |
| 농장 | 약 480 (세로 약 15칸) | 가안보다 2칸 짧다 |
| 오른쪽 가장자리 | 폭 약 56 | **☰** 하나만. 주요 메뉴도 접는다 |

- 좋은 점 : 건물이 주인공이라 「게임 같다」는 느낌이 가장 세다. 손님이 메인 화면에도 보인다. D 의 가게 정면을 본보기로 쓴다.
- 나쁜 점 : 농장이 줄어든다. 정면 가게와 3/4 탑다운 농장이 한 화면에 있어 시점이 섞인다. 길 위 손님은 새 기능이다(기획 판정이 먼저다).

### 다안 — 위아래로 끌어 보는 긴 화면

| 위에서부터 | 높이 | 무엇 |
| --- | --- | --- |
| 하늘 | 약 300 | 처음엔 화면 밖. 위로 끌면 보인다 |
| 건물 줄 | 약 300 | 나안처럼 크게 |
| 농장 | 약 760 (세로 약 24칸) | 기본 자리. 켜면 건물 아랫단과 농장이 보인다 |
| 오른쪽 가장자리 | 폭 약 64 | 화면에 붙어 따라온다. 가안과 같다 |

- 좋은 점 : 건물도 크고 농장도 넓다. 찹쌀이가 늘어도 자리가 남는다.
- 나쁜 점 : 한눈에 안 들어온다 — 방치형에서 「켜고 바로 확인」이 어렵다. 끌기와 찹쌀이 드래그(반복 01)의 손짓이 겹친다.

### 오른쪽 메뉴에 대해

- **본보기를 못 찾았다.** 조사한 세로 게임(I · J)은 메뉴가 아래 가운데·아래 막대다. 오른쪽 세로 줄은 **직접 만들어 봐야 안다.**
- 오른손 엄지는 **오른쪽 가장자리의 가운데~아래**가 편하다고 알려져 있다(일반론 — 이번에 출처를 안 찾았다). 그래서 메뉴 줄은 위가 아니라 **농장 띠 높이**에 두고 ☰ 를 맨 아래에 두자는 제안이다.
- 왼손잡이·건물 누르기와 겹침은 프로토에서 본다.

## 6. PixelLab 프롬프트에 넣을 화풍 낱말 후보

게임 이름은 프롬프트에 넣지 않는다. **써 보고 고른 것이 아니라 후보**다 — 먹히는지는 뽑아 봐야 안다.

| 무엇을 뽑을 때 | 낱말 |
| --- | --- |
| 어디에나 | `cozy pixel art` · `soft muted pastel palette` · `low saturation` · `dark colored outline, no pure black` · `selective outline` · `3-tone cel shading with hue shift` · `light from top-left` · `no anti-aliasing` · `no dithering` · `clean pixel clusters` |
| 캐릭터 | `super-deformed chibi, very big head and tiny body, 2.5 heads tall` · `tiny dot eyes`(손님) 또는 `big sparkling eyes`(주인) · `pink blush cheeks` · `front view, full body` |
| 건물 바깥 | `top-down 3/4 view building exterior` · `large roof, visible front wall and door` · `storybook cottage` · `modern cafe storefront with striped awning, large glass window, signboard` · `cute fusion machine workshop with chimney and pipes` · `wooden crates and barrels beside the wall` |
| 하늘·원경 | `flat pastel sky` · `fluffy cumulus clouds in 3 tones` · `distant forest silhouette in 2 tones, atmospheric perspective` · `side view horizon band` |
| 농장 바닥 | `flat mint green grass with sparse grass tufts` · `sandy dirt path` · `low detail ground, readable` |
| UI | `parchment paper panel with wooden frame` · `9-slice` · `ribbon banner title` · `bookmark tab` · `rounded wooden button` · `storybook game UI` |

- 색을 한 벌로 묶는 데는 PixelLab 의 색 줄이기 도구(`reduce_colors`)나 화풍 그림 넘기기(`style_image`)가 후보다 — **이번에 써 보지 않았다.**
- 540×1200 배경을 한 번에 뽑을 수 있는지(도구별 최대 크기)도 **확인 못 했다.**

| 10 | 가판대 바깥 모습 | 3/4 탑다운 집 · 정면 가게 | 가안이면 3/4, 나안이면 정면 |
| 11 | 쓰는 폰의 가로 해상도 | 1080 이면 가안이 딱 맞는다. 720·1440 이면 다시 본다 | — |

정해지면 다음은 아트규칙 6절 흐름대로 **PIL 프로토 한 장(메인 화면 540×960)** 을 먼저 만들어 눈으로 본다.

## 8. 못 확인한 것

- **A 의 타일 크기 · 색 수 · 개발자가 밝힌 해상도.** 인터뷰에는 그림 수치가 없었다. 480×270 은 스크린샷 실측이다.
- 캐릭터 크기는 전부 스크린샷 한두 장 **눈대중**이다. 스프라이트 시트를 받아 재지 않았다.
- C(스타듀밸리) · E(테라리아)의 UI·색·외곽선은 이번에 화면을 안 보고 **기억으로** 적었다. E 의 「2×2 로 그린다」·캐릭터 크기는 공식 확인이 없다.
- D 는 미출시작이라 정식판 화면이 바뀔 수 있다.
- I · J 의 원본 해상도. 상점 그림은 줄어든 것이라 격자를 못 쟀다.
- 용사식당 · Usagi Shima 는 페이지가 안 열렸다.
- **오른쪽 세로 메뉴를 쓰는 세로 픽셀 게임 본보기** — 못 찾았다.
- PixelLab 이 6절 낱말로 A 풍을 내는지, 540×1200 을 뽑는지 — **안 뽑아 봤다.**
- 사용자 폰의 실제 해상도. 가안으로 갈 때 코드(UI 다시 놓기) 공수.
