# Unity 조작 CLI 두 가지 조사 — Unity 공식 CLI · Unity CLI Loop (uloop)

작성 2026-09-06. Claude Code(터미널)가 Unity 6000.3.23f1 프로젝트(`ProjectMozziUnity/`)를 조작하게 하려고
두 도구를 조사했다. **설치·파일 변경은 하지 않았고**, 이미 깔려 있는 것은 읽기 전용 명령으로만 확인했다.

## 결론 먼저

- **Unity 공식 CLI 는 이미 이 컴퓨터에 깔려 있고 로그인까지 되어 있다.** (`1.0.0-beta.6`, `C:\Users\USER\AppData\Local\Unity\bin\unity.exe`)
  프로젝트에 `com.unity.pipeline 0.6.0-exp.1` 도 이미 들어 있고, 지금 켜져 있는 에디터와 연결이 된다 (`unity command editor_status` 성공).
  남은 것은 **Claude Code 용 스킬 설치 한 줄**뿐이다. MCP 는 **선택**이다.
- **Unity CLI Loop(uloop) 는 V3 부터 MCP 를 완전히 뺐다.** CLI + 스킬만 있다. 그래서 "MCP 없이" 조건은 저절로 맞는다.
  Unity 2022.3 이상 지원이라 Unity 6 도 된다. 아직 안 깔려 있다.
- **둘은 기능이 많이 겹친다.** 굳이 하나만 고른다면 **공식 CLI** 를 기본으로 쓰고,
  uloop 는 **핫리로드·일시정지점·입력 재생** 처럼 공식에 없는 것이 필요할 때 얹는다.

### MCP 가 필수인가 (사용자 조건 표)

| 도구 | MCP 필수? | MCP 없이 되는 범위 | MCP 를 붙이면 |
| --- | --- | --- | --- |
| Unity 공식 CLI | **선택** | 전부 — `unity command …` 로 에디터 명령 100개 넘게 직접 호출. 스킬(`unity skill install claude-code`)이 Claude Code 에 사용법을 알려준다 | 같은 명령이 MCP 도구로도 노출된다 (`unity mcp` 가 stdio 서버). 공식 문서는 **CLI 를 권장**, MCP 는 "옛 방식 호환용" |
| Unity CLI Loop (uloop) | **없음** (V3 에서 제거) | 전부 — `uloop …` 명령 + 18개 스킬 | 붙일 방법 자체가 없다. MCP 가 꼭 필요하면 V2 로 내려야 하는데 권하지 않는다 |

## 1. "유니티 공식 CLI" 후보 셋

| 후보 | 실제로 있나 | 무엇 | MCP 없이 |
| --- | --- | --- | --- |
| (a) 에디터 배치 모드 `Unity.exe -batchmode -executeMethod …` | 있음 (옛날부터) | 에디터를 창 없이 띄워 C# 정적 메서드 하나 돌리고 끝. 켜져 있는 에디터와 대화는 못 한다 | 된다 |
| (b) Unity Hub CLI `"Unity Hub.exe" -- --headless …` | 있음 | 에디터 설치·모듈 추가·설치 경로. 프로젝트 조작은 못 한다 | 된다 |
| (c) **Unity CLI** (`unity` 명령, 2026-07-20 공개) | **있음 — 이게 사용자가 말한 것** | 위 둘을 합치고 + 켜져 있는 에디터에 명령 보내기(`com.unity.pipeline`) + 테스트·빌드 + MCP 모드 | 된다 |

(c) 가 나오면서 Unity 는 (b) 를 대체하려 하고, `com.unity.ai.assistant` 패키지에 들어 있던 옛 "Unity MCP 서버" 도
"CLI 로 옮기라" 고 안내한다. 그러니 **`com.unity.ai.*` 패키지는 이번 목적에 필요 없다.**

### 1-(a) 에디터 배치 모드

- 경로 : `C:\Program Files\Unity\Hub\Editor\6000.3.23f1\Editor\Unity.exe`
- 예 : `& "C:\Program Files\Unity\Hub\Editor\6000.3.23f1\Editor\Unity.exe" -batchmode -nographics -quit -projectPath ProjectMozziUnity -executeMethod Build.Run -logFile -`
- 쓸 자리 : CI 빌드, 한 번 돌리고 끝나는 일. 매번 에디터를 새로 띄우니 느리다(수십 초~분).
- 공식 CLI 의 `unity build` · `unity run` · `unity test` 가 이걸 감싼 것이다.

### 1-(b) Unity Hub CLI

- 경로 : `C:\Program Files\Unity Hub\Unity Hub.exe` (있음 확인)
- 예 : `& "C:\Program Files\Unity Hub\Unity Hub.exe" -- --headless editors --installed`
- 공식 CLI 의 `unity editors` · `unity install` · `unity install-modules` 가 같은 일을 한다. 새로 배울 필요 없다.

### 1-(c) Unity CLI (본명령 `unity`)

**무엇** — 의존성 없는 단일 실행 파일. 에디터 설치·프로젝트 열기·인증부터, 켜져 있는 에디터에 명령을 보내는 것까지 한다.
켜져 있는 에디터와의 대화는 프로젝트에 **`com.unity.pipeline` 패키지(실험 단계)** 가 있어야 한다. 이 패키지가 에디터 안에서
localhost 서버(이 컴퓨터는 7800 포트)를 열고, `[CliCommand]` 를 붙인 정적 메서드를 명령으로 노출한다.

**요구** — Unity 6.0 LTS 이상 (우리 6000.3 OK). 로그인(`unity auth login`, 브라우저) 필요.

**설치 (PowerShell)** — 이미 깔려 있어서 다시 할 필요 없다. 참고로 적어 둔다.

```powershell
$env:UNITY_CLI_CHANNEL='beta'; irm https://public-cdn.cloud.unity3d.com/hub/prod/cli/install.ps1 | iex
```

- 설치 위치 : `C:\Users\USER\AppData\Local\Unity\bin\unity.exe` — **PATH 에 이미 잡혀 있다** (`where.exe unity` 로 확인).
- winget · brew 는 "곧" 이라고만 되어 있다 (2026-07 블로그).
- 자체 갱신 : `unity upgrade`.

**이 컴퓨터에서 확인한 상태 (2026-09-06)**

| 항목 | 값 |
| --- | --- |
| CLI 판 | 1.0.0-beta.6 (.NET 10 런타임 포함) |
| 로그인 | 됨 (oauth, keyring) |
| 에디터 | 2022.3.62f1, 6000.3.23f1 둘 다 인식 |
| `com.unity.pipeline` | `manifest.json` 에 `0.6.0-exp.1` (최신). 2D 템플릿 기본에는 없으니 누군가 `unity pipeline install` 을 이미 돌렸다 |
| 에디터 연결 | `unity status` → 7800 포트 ready, `unity command editor_status` 성공 |
| Claude Code 스킬 | **안 깔림** (`unity skill install --list` → `C:\Users\USER\.claude\skills\unity-cli` 없음) |
| MCP 등록 | 안 됨 (Claude Desktop·Claude Code 모두) |

**자주 쓸 명령**

```powershell
unity status                               # 켜진 에디터 목록 (포트·프로젝트·상태)
unity command                              # 에디터가 노출한 명령 목록 (--query 낱말 로 거르기)
unity command editor_status --json         # 에디터 상태
unity command eval "return 1+1;"           # C# 한 줄 실행 (Roslyn, 재컴파일 없음)
unity command eval_file path/to/x.cs
unity command editor_play / editor_stop    # 플레이 모드
unity command console                      # 콘솔 로그
unity command capture_game_view --save_path shot.png
unity command run_tests                    # 에디터 안에서 테스트
unity test --mode EditMode                 # 배치 모드로 테스트 돌리고 XML 보고서
unity build                                # 배치 빌드
unity open ProjectMozziUnity               # 알맞은 에디터 판으로 프로젝트 열기
unity pipeline list / upgrade              # 파이프라인 패키지 상태·갱신
unity skill install claude-code            # Claude Code 용 스킬 설치
unity mcp                                  # (선택) MCP stdio 서버
```

- 명령 100개 넘게 확인 : 게임오브젝트·컴포넌트·프리팹·씬·애니메이터·타임라인·에셋·빌드·라이트맵·내비메시 등.
  `batch` 로 여러 명령을 한 트랜잭션(Undo 한 단계)으로 묶을 수 있다.
- `--json` 을 붙이면 기계가 읽기 좋은 출력이 나온다. `UNITY_NO_BANNER=1` 로 배너를 끈다.
- 주의(블로그·외부 글) : 플레이 모드 중 도메인 리로드가 나면 연결 토큰이 바뀌어 `401` 이 나던 버그가 있었다(고쳐졌다고 함).
  모달 창(씬 저장 물음)이 뜨면 자동화가 멈춘다. 에디터를 `-automated` 로 띄우면 준다고 한다 — **추측 수준, 안 해봤다.**
- 한 호출에 0.8초쯤 걸린다는 측정 글이 있다. 우리도 나중에 재 본다.

**Claude Code 와 붙이기 (두 길)**

1. **스킬 (권장, MCP 없음)** : `unity skill install claude-code` → `C:\Users\USER\.claude\skills\unity-cli\` 에 SKILL.md 가 들어가고
   Claude Code 가 `unity` 명령 사용법을 안다. 프로젝트 안에 넣으려면 `--local`.
   Unity 가 따로 관리하는 스킬 묶음도 있다 : `npx skills add Unity-Technologies/skills` (14개, MIT, `unity-cli` 스킬 포함).
2. **MCP (선택)** : `unity mcp configure --list` 를 보면 Claude Code 는 "파일 없음 — 수동" 이라 CLI 가 대신 써 주지 않는다. 직접 등록한다.
   ```powershell
   claude mcp add unity -- C:\Users\USER\AppData\Local\Unity\bin\unity.exe mcp --project-path D:\Project\ClaudeProject\ProjectMozzi2\ProjectMozziUnity
   ```
   (`unity mcp configure claude --dry-run` 이 Claude Desktop 용으로 만들어 준 JSON 이 `"command": "...unity.exe", "args": ["mcp"]` 였으니 같은 꼴이다.
   `--project-path` 는 `unity mcp --help` 에 있는 옵션이다. **Claude Code 에서 실제로 돌려보진 않았다.**)

## 2. Unity CLI Loop (hatayama/unity-cli-loop, `uloop`)

| 항목 | 값 (2026-09-06 GitHub API·README 확인) |
| --- | --- |
| 무엇 | "Let AI Drive Unity, from Editor to Play Mode". AI 에이전트가 컴파일·테스트·로그·에디터 조작·플레이모드 입력까지 돌리게 하는 CLI + Unity 패키지 + 스킬 |
| 작성자 · 라이선스 | hatayama (일본), **MIT** |
| 별 · 마지막 갱신 | **549개**, 마지막 push 2026-09-06, 최신 릴리스 **v3.3.0 (2026-09-04)**. 매우 활발 |
| Unity 지원 | **2022.3 이상** (`package.json` `"unity": "2022.3"`). Unity 6 OK |
| uLoopMCP 와 관계 | **같은 저장소다.** 2026-03-16 에 `uLoopMCP` → `unity-cli-loop` 로 이름을 바꿨다. 패키지 id 는 옛 이름 `io.github.hatayama.uloopmcp` 그대로 |
| MCP | **V3(2026-07)에서 제거.** "CLI + 스킬이 유일한 연결 방법". V2 는 npm CLI + MCP 였다 |
| 요구 | Node.js 필요 없음 (V3). Claude Code 나 Codex 처럼 스킬을 읽는 도구 |

**구조** — 셋이 한 벌이다.

1. `uloop` 전역 실행 파일 (PATH) — 명령을 받아 프로젝트별 러너에 넘긴다.
2. `uloop-project-runner` — `.uloop/project-runner-pin.json` 에 적힌 판을 자동으로 받는다.
3. Unity 패키지 (`io.github.hatayama.uloopmcp`) — 에디터 안 IPC 서버. TCP 포트 없이 **Windows 명명 파이프**로 붙는다.

**설치 (PowerShell)** — 세 단계.

```powershell
irm https://raw.githubusercontent.com/hatayama/unity-cli-loop/main/scripts/install.ps1 | iex   # 1. CLI
cd ProjectMozziUnity
uloop package install        # 2. manifest.json 에 OpenUPM scoped registry + 의존성 추가 (--version x.y.z 로 고정 가능)
uloop launch                 # 에디터 띄우기(이미 켜져 있으면 창만 앞으로)
uloop skills install --claude          # 3. 프로젝트 .claude/skills 에 18개 스킬 (--global 이면 사용자 폴더)
```

- 설치 위치 : `install.ps1` 을 읽어보니 기본 `%LOCALAPPDATA%\Programs\uloop\bin` (`ULOOP_INSTALL_DIR` 로 바꿈). PATH 는 스크립트가 잡는다.
- UPM git URL 로 넣는 길 : Package Manager → `https://github.com/hatayama/unity-cli-loop.git?path=/Packages/src`,
  그 다음 `Window > Unity CLI Loop > Settings` 에서 **Install CLI** · **Install Skills** 버튼. (터미널 길과 결과 같음)
- `uloop package install` 이 `manifest.json` 에 쓰는 것 (README 설명 기준, 실제 JSON 꼴은 추측) :
  ```json
  "scopedRegistries": [{ "name": "OpenUPM", "url": "https://package.openupm.com", "scopes": ["io.github.hatayama.uloopmcp"] }],
  "dependencies": { "io.github.hatayama.uloopmcp": "3.3.0", ... }
  ```
  패키지 의존성 : `com.unity.ugui`, `com.unity.nuget.newtonsoft-json 3.2.1`, `com.unity.nuget.mono-cecil 1.11.6` (우리 프로젝트에 이미 있는 것들이라 충돌 없을 것 — 추측).

**Claude Code 붙이기** — 스킬만 깔면 끝. 단 하나 주의 :
Claude Code 샌드박스가 네트워크를 막아 명명 파이프 연결도 막힌다(`UNITY_NOT_REACHABLE`). `~/.claude/settings.json` 에 넣는다.

```json
{ "sandbox": { "excludedCommands": ["uloop *"] } }
```

(공식 CLI 도 localhost 7800 에 붙으니 같은 문제가 날 수 있다 — **추측**. 실제로 위 `unity command editor_status` 는 Bash 도구에서 잘 됐다.)

**명령**

```powershell
uloop list / launch / compile / hot-reload / get-logs --max-count 10 / run-tests --filter-type all
uloop execute-dynamic-code --code 'using UnityEngine; Debug.Log("hi");'
uloop get-hierarchy / find-game-objects / screenshot / control-play-mode / focus-window / set-game-view-size
uloop simulate-mouse-ui / simulate-mouse-input / simulate-keyboard / replay-input
uloop enable-pause-point --file Assets/Scripts/X.cs --line 42 --await
```

**git 에 넣을 것** — README 권장 `.gitignore` :

```gitignore
**/.uloop/*
!**/.uloop/project-runner-pin.json
!**/.uloop/settings.tools.json
```

`UserSettings/UnityCliLoopSettings.json` 은 개인 설정이라 git 에 안 넣는다 (`UserSettings/` 는 Unity 기본 gitignore 에 이미 빠져 있는지 확인 필요).

## 3. 둘을 같이 쓰면

| 하고 싶은 일 | 공식 CLI | uloop | 추천 |
| --- | --- | --- | --- |
| 에디터 설치·판 관리·프로젝트 열기 | O | 열기만 (`launch`) | 공식 |
| 컴파일 오류 보기 | `command recompile` + `console` | `compile` 한 방 | 둘 다 됨 — uloop 가 한 줄 |
| C# 즉석 실행 | `command eval` | `execute-dynamic-code` | 둘 다 |
| 씬·게임오브젝트·프리팹·에셋 만들고 고치기 | **명령 100개+** (전용) | eval 로 코드 써서 | 공식 |
| 테스트 | `command run_tests` · `unity test`(보고서 XML) | `run-tests` | 공식 (CI 보고서) |
| 빌드 | `unity build` · `command build` | 없음 | 공식 |
| 스크린샷 | `capture_game_view` · `capture_scene_view` | `screenshot` | 둘 다 |
| **핫리로드 (재컴파일 없이 메서드 바꿔치기)** | 없음 | `hot-reload` | **uloop 만** |
| **일시정지점 + 변수 읽기** | 없음 | `pause-point` | **uloop 만** |
| **플레이모드 입력 흉내·녹화 재생** | 없음 (확인 못 함) | `simulate-*` · `replay-input` | **uloop 만** |
| 사용자 정의 명령 | `[CliCommand]` | 커스텀 툴 + SKILL.md | 둘 다 |
| MCP | 선택 (`unity mcp`) | 없음 | — |

- **겹치는 부분** : 에디터 접속·eval·로그·테스트·스크린샷·플레이 제어. 둘 다 깔면 스킬이 두 벌이라 Claude 가 헷갈릴 수 있다.
  깔 때 각 스킬 설명에 "언제 무엇을 쓰나" 를 한 줄 적어 두는 게 좋다.
- **충돌 위험** : 공식은 TCP 7800, uloop 는 명명 파이프라 포트는 안 겹친다. 둘 다 에디터 안에서 도메인 리로드 때 서버를 다시 여니
  동시에 쏘면 한쪽이 잠깐 끊길 수 있다 — **추측**.
- **추천** : ① 공식 CLI + 스킬만 먼저 (설치 한 줄로 끝). ② 플레이모드 자동 시험·핫리로드가 필요해지면 uloop 를 얹는다.

## 4. 설치 절차 (우리 환경 · 아직 안 돌림)

### 4-1. Unity 공식 CLI — 남은 것 두 줄

이미 된 것 : CLI 설치, 로그인, `com.unity.pipeline 0.6.0-exp.1`, PATH.

```powershell
# 1) Claude Code 스킬 (사용자 폴더). 프로젝트 안에 두려면 --local (그러면 ProjectMozziUnity/.claude/skills/ 에 생김 — 추측, --dry-run 으로 먼저 본다)
unity skill install claude-code --dry-run
unity skill install claude-code

# 2) (선택) MCP 도 붙일 때
claude mcp add unity -- C:\Users\USER\AppData\Local\Unity\bin\unity.exe mcp --project-path D:\Project\ClaudeProject\ProjectMozzi2\ProjectMozziUnity
claude mcp list

# 3) 첫 확인 (에디터 켜 둔 채)
unity doctor
unity status
unity command editor_status --json
unity command eval "return UnityEngine.Application.unityVersion;"
```

- `manifest.json` 변화 : 없음 (이미 `"com.unity.pipeline": "0.6.0-exp.1"`). 나중에 새 판이 나오면 `unity pipeline upgrade`.
- PATH : 이미 됨.
- 권한 : `.claude/settings.local.json` 의 `permissions.allow` 에 `Bash(unity *)` 를 넣으면 매번 묻지 않는다.
