# 기획·제작 순서 — 이 게임의 값

> **정본은 `Tools/GamedesignTool/Docs/Guide/기획절차.md` 다.**
> 여기에는 이 게임에서 확정한 값과 이 게임 특유의 것만 둔다. 절차 자체는 정본을 본다.

## 이 게임의 확정 값

2026-09-06 에 사용자가 정했다.

| 무엇 | 확정한 값 |
| --- | --- |
| 파일 이름 규칙 | `Docs/Design/` 기획서는 번호 이름, 조사·기록은 날짜 이름 |
| 한 판 길이 | **1주** (주말과 주말 사이) |
| 한 묶음의 프로토타입 개수 | **2~4개** |
| 기둥 개수 | **3~4개** |
| 프로토타입 만드는 방법 | **웹 HTML 한 파일만.** Unity 버릴 씬은 안 쓴다 |
| 툴 | **ProtoTool**(프로토타입) · **GamedesignTool**(단계 관문·대시보드) 둘로 나눈다 |

## 해 보고 고칠 값

지금은 이 값으로 두고, 한두 판 돌려 본 뒤 정한다.

| 무엇 | 지금 값 | 언제 다시 보나 |
| --- | --- | --- |
| 3~6 고리를 몇 판 돌면 컨셉을 의심하나 | 3판 | 실제로 3판을 돌아 본 뒤 |
| 세로 조각 범위 | 「게임 속 하루 한 번」 | 장르가 하루 주기로 굳은 뒤 |
| 프로토타입 두는 자리 | `Prototypes/` | 첫 묶음을 만들어 본 뒤 |
| 한 판 길이 1주 | 1주 | 두세 판 돌려 보고 짧거나 길면 고친다 |
| 검증 기준 숫자 | 「멈춘 횟수 2회 이하」 등 | 판마다 다시 정한다 (원래 그런 값이다) |

## 이 게임의 문서 뼈대

`Docs/Design/` 아래에 **아래 순서대로 한 번에 하나씩** 쓴다. 다 쓰고 시작하지 않는다.

| 순서 | 파일 | 담을 것 | 언제 쓰나 |
| --- | --- | --- | --- |
| 1 | `00-컨셉.md` | 한 줄 컨셉 · 대상 · 기둥 3~4개 · 안 할 것 | 1~2단계 |
| 2 | `01-코어루프.md` | 3층 루프 표 · 원천/변환/배수구 표 · 이번 판 물음 묶음과 판정 기준 | 3~4단계 |
| 3 | `02-기능목록.md` | MoSCoW 표 (Won't 칸 필수) | 7단계 |
| 4 | `03-시스템-<이름>.md` | 시스템 하나당 한 편 (밭 · 합성소 · 가판대 · 도감…) | 그 시스템을 만들기 직전 |
| 5 | `04-수치표.md` | 성장 시간 · 가격 · 뽑기 확률. 표만 | 8단계 |
| 6 | `05-진행과튜토리얼.md` | 첫 10분 순서 · 무엇을 언제 가르치나 · 해금 순서 | 8단계 뒤 |

- **`03-시스템-합성소.md` 는 이미 있다.** 합성 설계를 옮겨 담은 것이다.

## 이 게임에서 만든 툴 결정

툴 저장소는 처음부터 따로 두고 `Tools/` 아래 서브모듈로 붙인다.

| 툴 | 저장소 | 무엇을 갖나 |
| --- | --- | --- |
| **ProtoTool** | `officina-game-prototype-tool` | 프로토타입 뼈대(HTML 템플릿) · 틱 · 기록 · 목록(`Prototypes/index.html`) 생성 |
| **GamedesignTool** | `officina-game-design-tool` | 단계 관문 CLI (`stage show` · `check` · `next`) + 대시보드 (상태 탭 · 나중에 밸런스 탭) |

- **툴 코드에 게임 낱말을 넣지 않는다.** 게임 이름이 툴에 들어가면 다음 게임에서 못 쓴다.
- **프로토타입 파일과 상태 파일은 이 저장소에 남는다.** 툴은 만들고 읽기만 한다.
