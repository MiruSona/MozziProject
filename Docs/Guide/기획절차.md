## 단계를 넘기는 법

**GamedesignTool 의 `stage` 가 있다 (1판, 2026-09-07).** 손으로 관리하지 않는다.
지금 몇 단계인지의 **정본은 `Docs/Todo/기획상태.json`** 하나다. 이 문서와 `진행상황.md` 에 같은 것을 또 적지 않는다.

명령 앞자리는 `.\Tools\GamedesignTool\bin\stage.exe` 다. 아래 표는 짧은 쪽으로 적는다.
**`bin/` 은 git 에 안 올라간다** — 저장소를 새로 받았으면 `cd Tools\GamedesignTool` 하고
`$env:CGO_ENABLED="0"; go build -o bin/stage.exe ./cmd/stage` 를 한 번 친다.

| 이럴 때 | 이렇게 |
| --- | --- |
| 지금 어디쯤인지 볼 때 | `stage show` |
| 이번 판 물음을 적을 때 (4단계) | `stage ask "<물음>" --crit "<기준>" --crit "<기준>"` |
| 통과/불통을 적을 때 (6단계) | `stage check <물음id> pass\|fail --note "…"` |
| 단계를 넘길 때 (**사용자만**) | `stage next` |
| 되돌아갈 때 | `stage back <단계> --why "…"` |
| 상태를 한 장으로 볼 때 | `stage dash` → `Docs/Todo/대시보드.html` (git 에 안 올린다) |

**훅 셋이 `.claude/settings.json` 에 걸려 있다** — 세션을 열 때 `show`, 문서·코드를 쓰기 직전 `lint`,
한 판이 끝날 때 `done`. `lint` 는 어긋나면 **쓰기를 막고**, `done` 은 **경고만** 한다.

- **절차는 정본 문서, 강제는 훅이다.**
- 절차 정본은 `Tools/GamedesignTool/Docs/Guide/기획절차.md`, 이 문서는 **이 게임의 확정 값**만 담는다.

기획 문서가 지켜야 할 마크다운 규약(기둥 표 · `02-기능목록.md` 첫 표의 Won't 칸 · `NN-이름.md` 이름)은
`Tools/GamedesignTool/.claude/skills/gamedesign-usage/SKILL.md` 를 본다. 훅이 그 자리를 세기 때문에 모양이 정해져 있다.

**설정은 `Docs/Todo/기획설정.json` 에 코드폴더 한 칸만 덮었다** (`ProjectMozziUnity/Assets/_Project/Scripts`).
그래서 시스템 문서(`03-시스템-*.md`) 없이 그 폴더에 새 코드를 만들면 훅이 막는다. 나머지는 툴 기본값 그대로다.
