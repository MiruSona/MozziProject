# 기획·제작 순서 틀

> 이 게임과 앞으로의 게임에서 **되풀이해 쓰는 순서**다. **확정 2026-09-06.**
> 이 문서는 **GamedesignTool 저장소로 옮길 예정**이다. 옮긴 뒤 이 저장소에는 경로만 남긴다.
> 근거 조사 : `Docs/Research/2026-09-06-기획순서와기법조사.md`

## 한 줄 요지

**작게 정하고 → 바로 만들어 보고 → 재미없으면 되돌아간다.**
기획서를 다 쓰고 만들기 시작하는 것이 아니라, **한 판(iteration)마다 물음 몇 개를 프로토타입으로 확인**하고
살아남은 것만 문서에 적는다. 그래서 이 틀의 본체는 3~6단계를 도는 고리다.

**프로토타입은 한 번에 여러 개를 만든다.** 사용자가 평일에 자리에 없으니, AI 가 평일에 2~4개를 만들어 두고
사용자가 주말이나 퇴근 뒤에 **몰아서** 확인한다. 물음 하나 = 프로토타입 하나 = 답 하나다.

**프로토타입은 웹(HTML 한 파일)으로만 만든다.** Unity 버릴 씬은 쓰지 않는다.

| 9. 확장 | 콘텐츠 늘리기. **새 시스템은 안 늘린다** | — | — | 나머지 전부 | 둘 |

### 되돌아가는 조건

**3 → 4 → 5 → 6 → (3) 이 고리가 기획의 본체다.** 한 번에 끝나지 않는다.

되돌아가는 판단은 **묶음 전체가 아니라 프로토타입 하나하나에** 한다.
같은 묶음 안에서 하나는 통과하고 하나는 불통일 수 있다.

| 6단계에서 프로토타입 하나가 이렇게 되면 | 어디로 되돌아가나 |
| --- | --- |
| 기준 통과 | 그 물음은 답이 났다. 묶음이 다 통과하면 7단계로 나아간다 |
| 기준 불통이고, 고리의 **모양**이 틀렸다 | **3단계** — 코어 루프를 다시 그린다 |
| 기준 불통이고, 모양은 맞는데 **숫자**가 안 맞는다 | **5단계** — 숫자만 바꿔 다음 묶음에 다시 넣는다 |
| 기준 자체가 잘못 잡혔다 (재 봤더니 답이 안 나온다) | **4단계** — 그 물음의 기준을 다시 적는다 |
| 3~6 을 **3판 돌아도** 통과 못 한다 | **1~2단계** — 컨셉이나 기둥이 틀린 것이다 |
| 8단계 세로 조각이 재미없다 | **3단계** — 본 제작에 그대로 들어가지 않는다 |

## 각 단계 상세

### 1. 컨셉

- **무엇을** : 「누가 · 무엇을 하는 · 왜 재미있는가」 한 문장. 대상과 기분도 한 줄씩.
- **어떻게** : AI 가 질문을 먼저 던지고 사용자가 답한다. AI 가 초안 문장 3개를 쓰고 사용자가 고른다.
- **산출물** : `Docs/Design/00-컨셉.md` (반 쪽)
- **판정** : 20초 안에 남에게 말할 수 있고, 다 듣고 나서 「그래서 뭘 하는 게임인데?」 소리가 안 나온다.
- **함정** : 장르 이름만 나열하는 것(「2D 농장 수집 게임」)은 컨셉이 아니다. **플레이어가 하는 행동**이 들어가야 한다.

### 2. 기둥 3~4개

- **무엇을** : 이 게임이 반드시 지키는 느낌 3~4개.
- **어떻게** : **사용자가 정한다.** AI 는 「이 기둥이 서로 부딪히지 않나」만 되짚는다.
- **산출물** : 컨셉 문서 안 표 (기둥 / 이게 지켜지면 어떤 느낌인가 / 이걸 깨는 예)
- **판정** : 하나를 갈아 끼웠을 때 「그건 다른 게임인데」 소리가 나온다.
- **함정** : **기둥은 할 일이 아니라 느낌으로 쓴다.** 「밭을 넓힌다」는 할 일이라 기둥이 아니다.
  「조금씩 커지는 것이 눈에 보인다」가 기둥이다. 할 일로 쓰면 나중에 아이디어를 거를 때 아무것도 못 거른다.

### 3. 코어 루프

- **무엇을** : 1~3분 고리(코어) · 한 판 고리(하루) · 며칠 고리(메타) 3층. 그리고 자원이 **어디서 생겨 어디로 없어지나**.
- **어떻게** : AI 가 표 뼈대를 채우고, 사용자가 「이거 하고 싶은가」를 본다.
- **산출물** : `Docs/Design/01-코어루프.md` — 3층 루프 표 + 원천/변환/배수구 표.
- **판정** : 고리가 **닫힌다** (마지막 칸이 첫 칸으로 돌아온다). 자원마다 원천과 배수구가 **둘 다** 있다.
- **함정** : 배수구 없이 원천만 만드는 것. 자원이 고여서 30분 뒤에 할 일이 없어진다.
  성격이 같은 원천 둘을 나란히 두는 것도 안 된다 — 효율 좋은 쪽만 쓰이고 나머지는 죽는다.

### 4. 물음 묶음과 판정 기준

- **무엇을** : 이번 판에 시험할 **물음 2~4개**와, 물음마다 살릴지 버릴지의 기준.
  「밭을 3칸으로 시작하는 게 맞나」처럼 **하나만 물어보는 문장**으로 쓴다.
- **어떻게** : **만들기 전에** 적는다. 만든 뒤에 적으면 아까워서 기준이 물러진다.
  물음끼리 **서로 얽히지 않게** 나눈다. 한 물음의 답이 다른 물음의 답을 바꾸면 따로 시험한 뜻이 없다.
- **산출물** : 코어루프 문서 맨 뒤 「이번 판 물음과 판정 기준」. 물음마다 아래 네 칸을 채운다.

| 물음 | 판정 기준 (3~5줄) | 웹으로 답이 나나 | 답이 안 나면 |
| --- | --- | --- | --- |
| 밭을 3칸으로 시작하는 게 맞나 | 「5분 동안 멈추지 않고 돌렸다(예/아니오)」 … | **예** (기본) | — |
| 수확할 때 손맛이 있나 | … | 아니오 | **8단계로 미룸** |

- **「웹으로 답이 나나」 칸의 기본값은 「예」다.** 숫자·규칙·순서·고르기처럼 **세거나 셈할 수 있는** 물음은 다 웹으로 답이 난다.
- **「아니오」는 셋뿐이다** — 손맛(입력이 손에 붙나) · 연출(맞는 느낌이 나나) · 화면 알아보기(무엇인지 눈에 보이나).
  이런 물음은 프로토타입으로 만들지 않고 **8단계 세로 조각에서 실제 화면으로 본다.**
- **판정** : 물음마다 기준이 있고, 각 줄이 **예/아니오나 숫자**로 답할 수 있다. 「웹으로 답이 나나」 칸이 다 채워졌다.
- **함정** : 「재미있으면 통과」는 기준이 아니다. 아래처럼 쓴다.
  「5분 동안 멈추지 않고 돌렸다(예/아니오)」 · 「다음에 뭐 하지? 하고 멈춘 횟수 **2회 이하**」 ·
  「멈춘 뒤 한 판 더 생각이 든다(예/아니오)」
  묶음이 5개를 넘어가는 것도 함정이다 — 확인하는 사람이 지쳐서 뒤쪽을 대충 본다.
  **「아니오」를 남발하는 것**도 함정이다. 웹으로 안 된다고 미룬 물음은 몇 주 뒤에나 답이 나온다.

### 5. 거친 프로토타입 묶음

- **무엇을** : 물음 하나에 프로토타입 하나. 그림 없이 네모와 숫자로 코어 루프만.
- **어떻게** : **AI 가 묶음을 한꺼번에 만든다.** 사용자가 없는 평일에 만들어 둔다.
  **HTML 한 파일**로 만든다. 브라우저로 열면 바로 돌아간다. **버릴 코드다** — 예쁘게 짜지 않는다.
- **왜 Unity 씬을 안 쓰나** : Unity 에디터가 하나뿐이라 여러 개를 동시에 못 만들고, 컴파일과 `.meta` 를 기다리는 시간이 길다.
- **자리와 규약** : `Prototypes/<날짜-물음>/index.html` 한 파일. 파일 맨 위에 `proto-meta` 로 **물음 · 판정 기준 · 만든 날**을 적는다.

```
Prototypes/
  index.html                ← 목록 (자동 생성)
  2026-09-13-합성확률/
    index.html              ← 본체 한 파일 (CSS·JS 인라인)
    결과.md                 ← 사용자가 논 뒤 한 줄씩
```

- **툴** : **ProtoTool** 이 뼈대(HTML 템플릿) · 틱(시간 흐르기) · 기록(무엇을 눌렀나) · 목록(`Prototypes/index.html`) 을 준다.
  프로토타입 파일과 결과 파일은 **이 게임 저장소에** 남는다.
- **산출물** : HTML 한 파일 프로토타입 2~4개. 각각 어느 물음에 답하는 것인지 `proto-meta` 에 적혀 있다.
- **판정** : 각각 브라우저에서 손으로 5분 돌아간다. 그것뿐이다.
- **함정** : **프로토타입 하나는 답을 하나만** 가져온다. 하나에 두 물음을 섞으면 불통일 때 뭐가 잘못인지 모른다.
  **프로토타입끼리도 서로 얽히지 않게** 만든다 — 파일이 따로니 저절로 지켜진다. 공통 코드로 묶지 않는다.
  그림·소리·UI 를 다듬는 것도 함정이다 — 다듬으면 버리기 아까워진다.

### 6. 몰아서 검증

- **무엇을** : 만들어 둔 묶음을 한 자리에서 4단계 기준에 대 본다.
- **어떻게** : **사용자가 직접 논다.** `Prototypes/index.html` 을 열어 차례로 들어간다.
  주말 아침·밤이나 퇴근 뒤에 **몰아서** 한 번에 본다.
  AI 는 옆에서 기록만 한다. 남에게 쥐어 줄 수 있으면 **말없이 본다.**
- **산출물** : 짧은 기록 한 편 + `mem add --type history` 1건. 프로토타입마다 통과/불통을 적는다.
- **판정** : 프로토타입마다, 그 안의 기준 줄마다 통과/불통이 적혔다.
- **왜 몰아서 보나** : 여러 개를 **나란히 놓고 비교하면** 판단이 오히려 쉬워진다.
  하나만 보면 「그냥 그렇다」로 끝나는데, 셋을 이어서 해 보면 어느 쪽이 손이 더 가는지가 바로 보인다.
- **함정** : **「재미있었나」를 묻지 않는다.** 사람은 예의상 재미있다고 한다.
  대신 「어디서 헷갈렸나」 「어디서 지루했나」를 묻는다. 고친 뒤에는 **같은 자리를 다시** 시험한다.
  묶음을 한 덩어리로 「이번 판 별로였다」고 넘기는 것도 함정이다 — **하나씩 따로** 통과/불통을 적는다.

### 7. 기능 자르기

- **무엇을** : MoSCoW — Must(없으면 게임이 아님) / Should / Could / Won't(이번엔 안 함).
- **어떻게** : AI 가 지금까지 나온 아이디어를 다 모아 표로 늘어놓고, 사용자가 칸을 정한다.
- **산출물** : `Docs/Design/02-기능목록.md`
- **판정** : **Won't 칸이 비어 있지 않다.** 비어 있으면 아무것도 안 자른 것이다.
- **함정** : Must 가 열 개를 넘어가면 규모가 큰 것이다. 기둥 3~4개에 안 걸리는 것은 Must 가 될 수 없다.

### 8. 세로 조각

- **무엇을** : 게임의 한 조각을 **마무리 품질로** 한 번. 우리 기준으로는 「게임 속 하루 한 번」.
- **어떻게** : 시스템 문서(`03-시스템-*.md`)는 그 시스템을 만들기 **직전에** 쓴다. 수치는 `04-수치표.md` 를 코드가 읽게 한다.
  4단계에서 **「웹으로 답이 안 난다」고 미뤄 둔 물음들을 여기서 본다** — 손맛 · 연출 · 화면 알아보기.
- **산출물** : 실제 씬 + 시스템 문서들 + 수치표.
- **판정** : 남이 켜서 설명 없이 끝까지 해 본다. 미뤄 둔 물음에도 답이 적힌다.
- **함정** : 여기서 재미없으면 **본 제작으로 넘어가지 않는다.** 되돌아가는 것이 손해가 아니다.

### 9. 확장

- **무엇을** : 콘텐츠 늘리기.
- **함정** : **여기서 새 시스템을 넣지 않는다.** 새 시스템이 필요하면 그건 다음 게임이거나, 3단계로 돌아갈 일이다.

| 3 | `02-기능목록.md` | MoSCoW 표 (Won't 칸 필수) | 7단계 |
| 4 | `03-시스템-<이름>.md` | 시스템 하나당 한 편 (밭 · 합성소 · 가판대 · 도감…) | 그 시스템을 만들기 직전 |
| 5 | `04-수치표.md` | 성장 시간 · 가격 · 뽑기 확률. 표만 | 8단계 |
| 6 | `05-진행과튜토리얼.md` | 첫 10분 순서 · 무엇을 언제 가르치나 · 해금 순서 | 8단계 뒤 |

- **1~3 을 합쳐 A4 두 쪽을 넘기지 않는다.** 넘어가면 규모가 큰 것이다.
- 짧은 결정 하나는 새 문서를 만들지 말고 `mem` 에 남긴다.

### 파일 이름 규칙

**`Docs/Design/` 의 기획서는 날짜 없이 번호 이름**(`00-컨셉.md` · `03-시스템-합성소.md`)을 쓴다.
계속 고쳐 쓰는 문서라 날짜가 금방 낡기 때문이다. **조사·기록은 `YYYY-MM-DD-주제.md` 그대로**다.
이 예외는 `doc-writing` 스킬에도 적어 두었다.

## 되풀이 규칙

### 한 판(iteration)

- **한 판 = 1주** (주말과 주말 사이). 판마다 물음 **2~4개**를 묶어서 답을 가져온다 (프로토타입 하나당 답 하나).
  사용자가 주말에 몰아서 확인하므로 **확인 주기에 맞춘 길이**다. 해 보고 고친다.
- 평일과 확인 때 하는 일이 나뉜다.

| 언제 | 누가 | 무엇을 |
| --- | --- | --- |
| 평일 (사용자 없음) | AI | 묶음 프로토타입 만들기 · 문서 칸 채우기 · 숫자 표 · 조사 |
| 확인 때 (주말 아침·밤, 퇴근 뒤) | **사용자** | 묶음을 몰아서 해 보기 · 통과/불통 적기 · 다음 판 물음 정하기 |

- 판이 끝날 때 하는 것 셋.
  1. 플레이 기록 한 편 — 물음마다 무엇을 재 봤고 통과였나 (짧게, 반 쪽)
  2. `mem add --type history --scope design` 1건 — 결정과 공수 눈금
  3. `Docs/Todo/진행상황.md` 의 「이미 정한 것」 · 「지금 할 일」 표 고치기
- 예상과 실제 공수가 크게 어긋났으면 **왜 어긋났는지 한 줄**을 mem 에 같이 남긴다.

### 새 아이디어가 들어왔을 때

떠오른 것을 바로 넣지 않는다. 두 관문을 지난다.

1. **기둥에 대 본다.** 기둥 중 하나를 **더 세게** 만들지 않으면 넣지 않는다.
   (기둥을 「안 깨뜨린다」가 아니라 「더 세게 만든다」가 기준이다 — 안 깨뜨리는 것은 거의 다 통과한다)
2. **MoSCoW 칸을 정한다.** 통과한 것도 바로 만들지 않고 `02-기능목록.md` 표에 칸을 정해 넣는다.
   Must 가 아니면 이번 판에 안 만든다.

떨어진 아이디어는 지우지 말고 `mem add --type todo` 로 남겨 둔다. 다음 게임에서 쓸 수 있다.

## AI 에게 시키는 것 / 사람이 하는 것

**AI 는 재미를 모른다.** 규칙은 짤 수 있어도 무엇이 재미있는지는 판단하지 못한다.
그래서 AI 에게는 **「무슨 게임을 만들까」가 아니라 「내가 정한 이 규칙의 빈틈이 어디냐」** 를 묻는다.

| AI 에게 시킨다 | 사람이 한다 |
| --- | --- |
| 빈 종이 없애기 — 질문 목록 던지기 | **재미있나 없나 판단** |
| 문서 칸 채우기 · 표 뼈대 만들기 | **기둥 3~4개 정하기** |
| 숫자 표 채우기 · 곡선 계산 | **곡선을 보고 「이 속도가 맞나」 정하기** |
| 규칙의 빈틈·모순 되짚기 | **물음과 판정 기준 정하기** (4단계) |
| 평일에 프로토타입 묶음 만들어 두기 | **묶음을 몰아서 직접 놀아 보기** (6단계) |
| 조사·요약·문서 정리 | **살릴지 버릴지 결정** |
| 아이디어를 여러 개 늘어놓기 | **뻔한 것인지 가려내기** — AI 는 안전한 안을 고른다 |

### 틀을 강제하는 훅

**규칙 문서에 적어 두는 것보다 훅으로 막는 것이 실제로 지켜진다.** 훅은 GamedesignTool 의 단계 관문 CLI 를 불러 쓴다.

원칙 : **훅은 모양을 검사하고, 판단은 스킬과 사람이 한다.**
「재미있나」 「이 기둥이 느낌으로 쓰였나」는 훅이 못 본다. 훅은 「기둥이 3~4개인가」 같은 셀 수 있는 것만 본다.
**단계를 넘기는 것은 사용자만 한다** — 지금 몇 단계인지를 상태 파일에 적어 두고, 훅은 그것을 읽어 막기만 한다.

| 훅 | 언제 | 무엇을 검사하나 |
| --- | --- | --- |
| `SessionStart` | 세션을 열 때 | 지금 몇 단계이고 되돌아가는 조건이 무엇인지 문맥에 넣는다 |
| `PreToolUse` (Write/Edit) | 문서·코드를 쓰기 직전 | **순서** — `01-코어루프.md` 를 쓰려는데 `00-컨셉.md` 가 없으면 막는다. `Assets/Scripts/` 에 새 시스템 코드를 쓰려는데 `03-시스템-*.md` 가 없으면 막는다 |
| `PreToolUse` (Write/Edit) | 같은 자리 | **모양** — 기둥이 3~4개인가 · 컨셉이 반 쪽을 넘는가 · `02-기능목록.md` 의 Won't 칸이 비었나 · 파일 이름 규칙에 맞나 |
| `Stop` | 한 판이 끝날 때 | 판 끝에 할 일 셋(플레이 기록 · `mem history` · `진행상황.md` 고치기)이 빠졌으면 경고한다 |

주의 둘.

- **`Prototypes/` 는 검사에서 뺀다.** 버릴 코드를 훅이 막으면 5단계가 답답해져 아무도 프로토타입을 안 만들게 된다.
- **`AGENTS.md` 에는 「절차는 이 문서, 강제는 훅」 두 줄만 남긴다.** 절차를 두 군데 적어 두면 반드시 어긋난다.
