# 프로젝트 개요

> 이 프로젝트가 무엇을 하려는 것인지 적는다. 지금 할 일은 `Docs/Todo/진행상황.md` 를 본다.

## 목표

**옛 프로젝트의 기획과 리소스를 가져와, 기획부터 다시 쓰고 새 Unity 프로젝트로 프로토타입을 만든다.**

옛 자료는 `Docs/Design/농장기획/` 과 `Docs/Reference/` 에 그대로 있다.
그대로 이어 만드는 것이 아니라 **다시 읽고 무엇을 남길지 고르는 것**이 첫 걸음이다.

## 진행 흐름

| 차례 | 무엇 | 끝났다고 보는 기준 |
| --- | --- | --- |
| 1. 기획 | 옛 기획을 다시 읽고 남길 것·버릴 것을 고른다. 핵심 재미 한 줄을 정한다 | 기획서가 `Docs/Design/` 에 새로 서고 사용자가 승인 |
| 2. 프로토타입 | 핵심 재미만 Unity 로 만들어 본다. 그림·소리는 임시로 | 손으로 해 보고 재미가 있나 판단이 선다 |
| 3. 리소스 만들기 | 그림·소리를 만들며 게임에 넣고 피드백을 받는다 | — |
| 4. 그다음 | 3 번이 돌아간 다음에 정한다 | — |

- **한 차례가 끝날 때마다 사용자에게 확인을 받고 넘어간다.**
- 앞 차례로 되돌아가는 것은 잘못이 아니다. 프로토타입이 재미없으면 기획으로 돌아간다.
- 단계별 자세한 순서는 `Tools/GamedesignTool/Docs/Guide/기획절차.md` (정본) — 개요의 흐름은 큰 차례이고 기획절차는 그 안에서 되풀이하는 순서다.
  이 게임에서 확정한 값은 `Docs/Guide/기획절차.md` 에 있다.

## 게임 내용

**기획 단계에서 채운다.** (장르 · 핵심 재미 · 한 판의 길이 · 목표 플랫폼)

지금 정해진 것은 **2D 라는 것 하나**다.

## 툴과의 관계

`Tools/` 아래 여덟 툴은 다른 저장소에서 만들어 가져다 쓰는 것이다.

| 툴 | 여기서 쓰는 자리 |
| --- | --- |
| `DiagramTool` | 기획·설계 문서에 넣는 그림 |
| `ArtTool` | 스프라이트 · 타일 · UI |
| `SoundTool` | 효과음 · 음악 |
| `CodeTool` | Unity 코드 구조 템플릿 · 코딩 컨벤션 |
| `EffortTool` | 공수 재기 (예상 / 실제) |
| `AIMemoryTool` | 기억 저장소 `mem` |
| `ProtoTool` | 거친 프로토타입 (웹 HTML 뼈대 · 기록 · 목록) |
| `GamedesignTool` | 기획 단계 관문 CLI · 대시보드 |

- **툴이 막히거나 모자라면 그 툴 저장소의 `Docs/Todo/` 에 개선 기록을 남긴다.**
  이 저장소 문서에 적으면 툴 쪽에서 못 본다.
- 툴 자체를 고쳤을 때의 커밋 두 번 규칙은 `AGENTS.md` 11장을 본다.
