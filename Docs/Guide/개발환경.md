## 셸 주의사항

- PowerShell 5.1 기준이라 `&&`, `||`, 삼항 연산자를 쓸 수 없다. `;` 와 `if ($?) { }` 를 대신 쓴다.
- 경로에 공백이 있으면 큰따옴표로 감싼다.
- Bash 를 쓸 때는 Git Bash(POSIX) 문법으로 작성한다.

## Git LFS

그림·소리·영상은 LFS 로 잡는다. 잡는 확장자는 `.gitattributes` 에 있다.

- 저장소를 처음 받으면 **`git lfs install` 을 한 번 돌린다.** 안 하면 파일 대신 짧은 글자만 들어온다.
- 새 종류의 큰 파일(예 `.psd`)을 넣기 전에 `.gitattributes` 에 그 확장자가 있는지 본다. 없으면 먼저 더한다.
- **이미 LFS 없이 커밋한 큰 파일을 뒤늦게 LFS 로 옮기는 것은 이력을 고쳐야 해서 아프다.** 넣기 전에 확인한다.

## Unity 주의사항

- `.meta` 파일은 대상 파일과 **항상 함께** 커밋한다. 빠지면 다른 사람 환경에서 연결이 깨진다.
- `Library/`, `Temp/`, `Logs/`, `Build/` 는 커밋하지 않는다 (`.gitignore` 에 걸어 뒀다).
- 씬(`.unity`)과 프리팹(`.prefab`)은 합칠 때 충돌을 풀기 어렵다. 같은 파일을 동시에 고치지 않는다.
- Unity 조작 도구(배치 모드·CLI)는 프로젝트를 만든 뒤에 필요해지면 그때 검토한다.
- 직렬화는 **Force Text** · 메타는 **Visible Meta Files** 로 되어 있다. 바꾸지 않는다 — 글자 파일이어야 git 에서 합치기·diff 가 된다.
- 트윈은 **LitMotion v2.0.2** 를 쓴다 (UPM git · MIT). `Packages/manifest.json` 의 `com.annulusgames.lit-motion` 줄이다. 근거는 `Docs/Research/2026-10-03-트윈라이브러리조사.md`.

## 툴 exe

툴마다 부르는 길이 다르다. **PATH 에 있는 것은 `mem` 과 `localharness` 둘뿐이다.**

| 툴 | 어떻게 부르나 |
| --- | --- |
| `mem` (AIMemoryTool) | PATH 전역 — `~/.aimemory/bin/mem.exe` |
| `effort` (EffortTool) | **PATH 에 없다.** `Tools\EffortTool\bin\effort.exe` 로 직접 부른다 (`~/.effort/` 에는 cache·rules 만 있다) |
| `stage` (GamedesignTool) | `Tools\GamedesignTool\bin\stage.exe` |
| `datatool` (DataTool) | `Tools\DataTool\bin\datatool.exe` — Unity 메뉴 `Mozzi/Data/…` 가 대신 불러 준다 |
| `arttool` · `soundtool` | 그 툴의 `.venv` 안 — `Tools\ArtTool\.venv\Scripts\arttool.exe` 꼴 |
| DiagramTool | node 로 돈다. 빌드가 없다 |
| `localharness` | PATH 전역 — `~/.localharness/bin/`. 툴 저장소가 없다 (git 밖 개인용, 규칙도 `~/.localharness/`) |

exe 와 `.venv` 는 git 에 안 올라간다. 그래서 **서브모듈을 갱신한 뒤에는 다시 만들어야 한다.**

```
powershell -NoProfile -ExecutionPolicy Bypass -File Tools\setup.ps1
```

- 낡았는지만 보려면 `-Check` 를 붙인다. 아무것도 안 만들고 표만 찍는다.
- **툴 서브모듈이 2026-09-21 이후 커밋이어야 그 툴에 `build.ps1`·`setup.ps1` 이 들어 있다.**
  「스크립트 없음 — 서브모듈이 옛 커밋이다」 가 뜨면 setup 으로는 못 고친다. 서브모듈을 갱신하고 다시 돌린다.
- 전역 `mem` 만은 이 스크립트가 못 바꾼다 — `-Check` 가 옛 판이라고 하면 사용자가 `Tools\AIMemoryTool\build.ps1 -Install` 을 직접 돌린다.

## 게임 데이터 표 (DataTool)

수치 표는 **JSON 원본 → 구운 파일 한 장 → 생성 코드** 로 흐른다. 값을 고칠 때는 원본만 고친다.

| 무엇 | 자리 | 누가 고치나 |
| --- | --- | --- |
| 원본 (표마다 JSON 한 장 + `schema.json`) | `ProjectMozziUnity/GameData/` | **사람 · AI** |
| 구운 파일 | `Assets/_Project/Resources/Data/gamedata.bytes` | `datatool export` 만 |
| 생성 코드 (Row 클래스 · 로더 · asmdef) | `Assets/_Project/Scripts/Data/Generated/` | `datatool gen` 만 — **손대지 않는다** |
| MessagePack dll 여섯 장 (3.1.9) | `Assets/Plugins/MessagePack/` | 안 고친다 |

- **값을 고친 뒤에는 Unity 메뉴 `Mozzi/Data/Validate+Export+Gen` 을 누른다.** 검사 → 굽기 → 코드 생성을 한 번에 한다.
  에디터 밖에서는 `ProjectMozziUnity` 폴더에서 `..\Tools\DataTool\bin\datatool.exe validate` · `export` · `gen` 을 차례로 친다.
- **열을 더하거나 빼면(`schema.json`) 굽기와 코드 생성을 둘 다 다시 한다.** 하나만 하면 게임이 켜질 때 `GameDataException` 으로 바로 멈춘다.
- 표·열 이름은 소문자와 밑줄만 쓴다 (`mozzi_species` · `fence_max`). 코드에서는 `MozziSpeciesRow.FenceMax` 꼴이 된다.
- 원본 JSON 은 **행 하나가 한 줄**이다. 꼴이 흐트러지면 `datatool fmt` 가 맞춰 준다.
- 게임은 `StaticDataManager` 가 `Resources.Load` 로 구운 파일을 읽는다. StreamingAssets 는 안 쓴다 — 안드로이드 · WebGL 에서 파일로 못 읽기 때문이다.
- 툴 설명은 `Tools/DataTool/README.md` · `Tools/DataTool/Unity/README.md` 에 있다.

## 안드로이드 빌드

- 최종 플랫폼은 PC(Windows) + 안드로이드다. WebGL 은 2026-10-03 부터 안 쓴다. 반복 판은 APK 로 낸다 (Windows 빌드는 나중에 본다).
- 스크립트는 `ProjectMozziUnity/Assets/_Project/Scripts/Editor/AndroidBuild.cs` 다. 에디터가 떠 있어야 한다.
- 순서 : `unity command eval_file` 로 `Mozzi.Editor.AndroidBuild.SwitchPlatform();` 을 한 번 부르고, 전환이 끝나면 `Mozzi.Editor.AndroidBuild.Build();` 를 `--detach` 로 부른다.
- 빌드가 도는 동안 다른 Unity 명령을 보내지 않는다. 끝은 Editor.log 의 `[AndroidBuild] 결과` 줄로 본다.
- 나오는 곳 : `Build/android/ProjectMozzi-android-v<판>.apk` (gitignore). 판을 올릴 때는 스크립트의 `Version` 만 고친다.
- 설정은 스크립트가 넣는다 — 패키지 `com.mirusona.projectmozzi` · 세로 고정 · IL2CPP · ARM64 · 최소 API 25 · 디버그 키 서명 · 개발 빌드 끔.
- 디버그 패널(`MOZZI_DEBUG`)은 빌드할 때만 켜고 끝나면 되돌린다.
- 걸린 시간 (2026-10-03, v12) : 플랫폼 전환 1분쯤 · 빌드 404초 · apk 38.1 MB.
- 패키지 이름과 판은 `aapt dump badging <apk>` 로 확인한다. `aapt` 는 Unity 설치 폴더의 `AndroidPlayer/SDK/build-tools/` 아래에 있다.
