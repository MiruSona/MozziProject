## 1. 한 줄 결론

조사 결론은 화면에서도 거의 맞다. 다만 **줄 세움이 조금 바뀐다** —
합성 「받기」 연출의 **단색 초록 네모**와 **찹쌀이 도감의 단색 네모**가 화면에서 가장 크게 튄다(조사에 없던 것).
떡이 접시에서 뜨는 것(약 7~8px)은 그다음이고, 서랍 찹쌀이는 「작다」보다 **「안 보인다」**(받기 전에는 검은 그림자 + 「?」 뿐).

## 6. 설계에 넣을 것

1. **결과 · 도감의 단색 네모를 먼저 도트로 바꾼다** — `SynthesisScreen.PlayResult` 의 `SynthesisResultBox`, `MozziCodexScreen` 의 `ColorBox` 에 찹쌀이 그림(`MozziIconView`)을 쓴다. 화면에서 가장 튄다.
2. **떡 32 캔버스를 아래로 붙여 다시 굽는 쪽(조사 5-1 ①)** 이 낫다 — 진열장 · 말풍선 · 차림표 버튼 셋이 한 번에 고쳐진다.
3. 합성 서랍은 **배율만이 아니라 「다 됨」 표시 방식**을 같이 정한다 — 지금은 검은 그림자 + ? 라 키워도 어둡다. 그림자 자리도 서랍 가운데로(약 12px 오른쪽).
4. 그림체 통일 기준은 선 색보다 **칠 밀도(명암 단 수 · 픽셀 잘기)** 를 먼저 맞춘다 — 주인 대 손님, 찹쌀이 대 건물, 절구 대 마루에서 1배로 보이는 것은 이쪽이다.
5. 옛 360 화면(도감 둘 · 보관함)과 남색 자원바 · 빨간 알림 네모를 개편 목록에 넣는다. 메뉴 세움판은 자리(계산대 위)부터 본다.

## 7. 못 본 것

- 진열장에 떡 **여러 종**을 고르게 깔지 못했다 — 진열은 앞 6칸만 보여서 팥떡이 5칸을 차지했다(콩떡 1칸만 다름).
- 주방 「실험」 탭 · 떡메 치는 동작 중간 장면은 안 찍었다.
- 폰 해상도(1080×2400) 캡처는 안 했다. 540 1배만 봤다.
- 「떠 있는 px」 는 캡처를 키워 눈으로 잰 값이다(±2px). 코드 좌표로 다시 재지 않았다.
