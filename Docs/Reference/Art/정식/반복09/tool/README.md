> **2026-10-18 정리** : 이 문서가 가리키던 그림 중 안 쓰는 시안·견줌판·옛 판은 저장소에서 지웠다 (`(정리함 2026-10-18)` 표시). 다시 보려면 git 기록에서 꺼낸다.

현대 카페 주방(옆으로 세 칸)에 놓일 기구 그림이다. 모두 **화면에 1배로 놓는 크기**이고 투명 배경이다.
한눈에 보려면 `한눈판.png`, 치기 움직임은 `pound.gif` 를 연다.

치기 7장 차례 : 0 들기 → 1 더 들기 → 2 내리기 → 3 침(반죽 납작) → 4 튐(납작) → 5 올리기 → 6 들기.
절구는 모든 장에서 같은 자리에 고정이고 떡메·반죽만 바뀐다.

빚기 판 위에서 반죽을 빚어 둥근 떡이 되는 6장. 반죽만 있다(판·손·배경 없음, 투명).

- 캔버스 128×96 고정. 반죽의 보이는 아래 가운데가 (64, 96) — 여섯 장 모두 바닥선이 같다.
- **판 위 자리 : shape9 캔버스 아래 가운데를 화면 (150, 811) 에 놓는다** (캔버스 왼쪽 위 = (86, 715)).
  `견줌/build_view.py` 가 판 위 떡(`plain_cake` 2배)의 보이는 아래 가운데를 놓는 자리와 같다
  — 판(아래 가운데 (150,822), 높이 86)의 세로 가운데 779 + 떡 높이 64 의 반 = 811.
  그래서 마지막 장 → 진짜 떡으로 바꿔도 바닥이 튀지 않는다.
- 장당 시간 권장 : 0~4 는 90ms, 5 는 400ms 멈춘 뒤 진짜 떡으로 바꾼다. 한 번에 약 0.85초.
- 반죽 색은 치기 반죽(`pound_s3`)과 같은 크림빛 흰색(#fbf3e5 · #f9e7c9 · 그늘 #eec78f), 외곽선 #291911.
  0~4 장은 5 장 팔레트(36색)의 가장 가까운 색으로 맞췄다.
- 다시 만들기 : `python build_shape9.py` — `raw_shape9/` 의 PixelLab 원본(pro_flash 88×64, 5 장을 먼저 뽑고 나머지는 그것을 편집)을 자르고 맞춘다.
  `shape9_한눈판.png`(판 위 6장 + 진짜 떡 2배, 2배 확대), `shape9.gif`(4배, 끝에 진짜 떡 600ms 한 장을 더 붙여 바뀜을 본다)도 같이 만든다.

알려진 흠

- 마지막 장(57×44)은 진짜 떡 2배(64×40)보다 7px 좁고 4px 높다. 반죽은 1배 도트, 떡은 2배 도트라 바뀌는 순간 도트 굵기가 달라진다.
- 반죽은 크림빛, `plain_cake` 는 더 하얀 흰색 + 회색 조각이라 바뀔 때 색이 조금 바뀐다.
- 2 장은 가장자리를 모은 주름이 있어 만두처럼 보일 수 있다.

## 믹서기 내용물 겹 blender9

넣은 재료에 따라 믹서기 통 안 내용물 색이 바뀌게 하려고, 믹서기 네 장을 겹 둘로 나눴다. 새로 그린 곳은 없다 — 원본에서 가려내고 색만 바꿨다.

| 파일 | 크기 | 무엇 |
| --- | --- | --- |
| `blender9_body_0..3.png` | 105×176 | 몸통 겹. 원본에서 내용물 칸만 그 장의 빈 유리 색(가장 흔한 푸른 칸 색)으로 메웠다. 유리 반사 · 하얀 소용돌이 · 칼날 축 · 외곽선은 그대로 있다 |
| `blender9_fill_0..3.png` | 105×176 | 내용물 겹. 내용물 칸만, 밝기만 남긴 회색(가장 밝은 칸 = 흰색 255). 그 밖은 투명 |
| `blender9_색견줌.png`(정리함 2026-10-18) | 4배 | 견줌판 |
| `build_blender9.py` | — | 다시 만들기 : `python build_blender9.py` |

- 번호 : 0 = `blender_idle`, 1 = `blender_run_0`, 2 = `blender_run_1`, 3 = `blender_run_2`.
- **겹 순서 : 몸통(아래) → 내용물(위).** 겹 둘이면 된다. 하얀 반사 칸은 내용물 겹에서 빠져 있어서(투명) 몸통의 반사가 그대로 보인다. 그래서 하이라이트 겹(`glass`)은 따로 안 만들었다.
- 두 겹은 같은 캔버스 · 같은 자리에 겹친다 (피벗도 원본과 같게).
- **물들임 = 곱하기.** 내용물 칸 색 = 회색 × 물들임 색 / 255. Unity 에서는 내용물 겹의 `SpriteRenderer.color`(또는 `Image.color`)에 물들임 색을 넣으면 같다.
- 원래 쌀가루 색으로 되돌리려면 물들임 색 `#fff2d7` (원본과 채널 차이 가운데값 18, 최대 30 — 회색으로 바꾸며 낱알의 색 차이가 없어져서 똑같지는 않다).

재료 색 표 (아이콘에서 투명 · 어두운 외곽선(밝기 60 미만) · 흰 하이라이트(세 채널 모두 225 이상)를 빼고 채널별 가운데값. 물들임용은 밝기가 150 보다 낮으면 흰색 쪽으로 섞어 150 까지 올린 값)

| 재료 id | 이름 | 아이콘 대표색 | 물들임용 색 |
| --- | --- | --- | --- |
| `redbean` | 팥 | #9a3232 | #c28383 |
| `bean` | 콩 | #e6c868 | #e6c868 |
| `mugwort` | 쑥 | #5f9440 | #80aa68 |
| `sesame` | 깨 | #d6b06a | #d6b06a |
| `pinenut` | 잣 | #f4eacc | #f4eacc |
| `jujube` | 대추 | #b0482e | #c98371 |

- **섞는 규칙 : 넣은 재료들의 물들임용 색을 채널별로 평균**한다 (재료 하나면 그 색 그대로). 예 : 팥+쑥 = #a19676, 콩+깨 = #debc69.
- 견줌판 순서 (왼→오, 위→아래, 6칸 × 2줄) : ① 원본 idle ② 겹을 다시 합친 것(내용물 칸에 원본 색) ③ 원래 쌀가루 색(#fff2d7) 물들임 ④ 팥 ⑤ 콩 ⑥ 쑥 / ⑦ 깨 ⑧ 잣 ⑨ 대추 ⑩ 팥+쑥 ⑪ 콩+깨 ⑫ 도는 장(`run_1`)을 쑥으로.

알려진 흠

- 다시 합친 것(②)은 원본과 픽셀 차이 0. 하지만 물들이면 낱알의 붉은기 · 노란기 차이가 사라지고 밝기만 남는다.
- 도는 장의 하얀 소용돌이 · `run_2` 의 떠 있는 하얀 덩어리는 내용물 겹에 안 들어가 물들지 않는다 (흰 반사와 구분이 안 됨). 쑥을 넣어도 하얀 덩어리는 흰색으로 남는다.
- `run_1` 맨 위 소용돌이 끝 몇 줄(통 위 33 줄보다 위)은 뚜껑 테와 붙어 있어 빼 두었다 — 원래 쌀가루 색으로 남는다.
- 콩과 깨, 팥과 대추는 색이 가깝다 (노랑끼리, 붉은끼리). 잣은 원래 쌀가루와 거의 같은 흰색이다.
