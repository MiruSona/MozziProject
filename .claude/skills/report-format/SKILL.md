# 보고 양식

무엇을 담나만 정한다. 문서를 **어디에 두고 어떤 문체로 쓰나**는 `doc-writing` 스킬을 본다.

## 공수 표

작업을 **시작하기 전에** 소단계로 쪼개고 각 소단계의 예상 시간을 적는다.
소단계 하나가 끝날 때마다 표를 보여준다. 열은 넷이다.

| 소단계 | 예상 | 실제 | 상태 |
| --- | --- | --- | --- |
| 1. 밭 타일 규칙 정하기 | 10분 | 8분 | 끝 |
| 2. 심기·수확 만들기 | 40분 | — | 하는 중 |

- 예상보다 크게 어긋났으면 **왜 어긋났는지 한 줄** 적는다.
- 끝난 소단계의 **어긋난 까닭·다음에 쓸 눈금은 `mem` 에 남긴다** (`mem-usage` 스킬 — `--type history`, 눈금이면 `howto`).
- **숫자는 `Tools/EffortTool/.claude/skills/effort-usage/SKILL.md` 대로 EffortTool 로 잰다**
  (스킬 이름 `EffortTool:effort-usage` — `Tools/EffortTool/README.md` 를 읽어야 뜬다) —
  예상은 `effort estimate`, 「실제」는 `effort list`·`show` 값.

### 눈금 규칙

- **「값을 재서 정한다」가 들어간 소단계는 눈금 ×2.**
- **「동결 → 재측정 → 고침 → 재동결」은 두 번 돌 것으로 잡는다.**
- **오래 걸리는 측정은 먼저 걸어 두고 다른 일을 한다.**

## 완료 보고 다섯

1. **만든 것** — 파일과 무엇을 하는지
2. **이번에 정한 것 한 표** — 흩어진 결정을 모아서 한 번에 보여준다
3. **공수 표**
4. **못 한 것과 남은 것**
5. **신뢰도 %와 근거**

보고를 쓰기 **전에** `mem-usage` 스킬대로 남길 것이 있나 본다 (history 1건 · 남은 todo).

## 신뢰도

| 무엇을 했나 | 신뢰도 |
| --- | --- |
| 실제로 돌려서 결과를 눈으로 봤다 | **95% 이상** |
| 돌려봤지만 일부 경우만 봤다 | 70~90% |
| 코드는 맞는데 안 돌려봤다 | 50~70% |
| 문서만 고쳤다 · 사람이 봐야 안다 | **숫자 대신 "확인 못 함"** |

- 근거는 **무엇을 확인했나**로 쓴다. 「잘 됐을 것 같다」는 근거가 아니다.
- 한 덩어리로 뭉개지 말고 **확인한 것과 못 한 것을 나눠서** 매긴다.
- **낮게 쓰는 것은 잘못이 아니다. 높게 써 놓고 틀리는 것이 잘못이다.**
- 게임은 **재미가 되는지 사람이 봐야 안다.** 그림·소리·손맛은 숫자 대신 "사람이 봐야 안다" 로 쓴다.

## 서브에이전트가 돌려줄 것 여섯

1. **바꾼 파일** 목록과 한 줄 설명
2. **넘긴 것** — 다른 갈래·뒷정리가 해야 할 것 (파일과 이유)
3. **안 건드린 자리** — 내 범위 안인데 그대로 둔 것 (합칠 사람이 본다)
4. **잰 값**과 근거
5. **빌드·시험 결과** (통과 여부·시험 수). **깨진 채 넘기는 것이 있으면 숨기지 않는다**
6. **공수(예상/실제)와 신뢰도**

## 측정값을 보고할 때

1. **무엇으로 쟀는지 못 박는다** — 동결한 산출물의 **크기와 SHA-256**, 저장소·설정·자료를 명령 한 줄로.
2. **전/후를 같은 절차로 다시 재서 나란히 두 줄**로 둔다.
3. **예측값에는 무엇을 고정한 값인지 같이 적는다.**
4. 시간 절대값은 **기계·환경 한 줄**을 같이 적고, 임시 폴더·백신 켜짐이면 비관적임을 밝힌다.
5. 재현 절차는 **차례를 못 박는다.**
6. 긴 실행은 **쪼개고 중간 결과를 파일로** 남긴다.
7. 표 모양은 **지난 판 문서를 그대로 재사용**한다. 처음 짜면 몇 배 걸린다.

## 원칙 한 줄

**합격선을 맞추려고 자를 옮기지 않는다.** 자는 그대로 두고 물건을 고친다.
못 고치면 숨기지 말고 「못 한 것」에 적는다.
