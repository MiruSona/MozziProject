# 문서 쓰기

어디에 · 어떤 이름으로 · 어떤 문체로 쓰고, 그림 검사를 어떻게 도는지를 정한다.
보고서에 **무엇을 담나**는 `report-format` 스킬을 본다.

## 어디에 두나

- **게임 이야기는 이 저장소 `Docs/{Research,Design,Todo,History,Guide}/`.**
  기획서는 `Docs/Design/`, 참고 자료는 `Docs/Reference/`.
- **툴 이야기는 그 툴 서브모듈 안** : `Tools/<툴>/Docs/…`. 툴 개선 요청은 `Tools/<툴>/Docs/Todo/`.
- 파일 이름은 **`YYYY-MM-DD-주제.md`**. (예: `2026-09-06-밭시스템설계.md`)
  `Docs/Guide/` 와 `Docs/Todo/진행상황.md` 처럼 계속 고쳐 쓰는 문서는 날짜를 안 붙인다.
- **`Docs/Design/` 의 기획서는 계속 고쳐 쓰므로 날짜 없이 번호 이름**(`00-컨셉.md` · `03-시스템-<이름>.md`)**을 쓴다.**
  조사·기록은 날짜 이름 그대로다.
- 환경이나 컨벤션이 바뀌면 `Docs/Guide/` 의 해당 문서를 고친다.

## 어떻게 쓰나

- **결론을 먼저 쓰고 근거를 뒤에 붙인다.**
- 기획·설계 설명은 **게임 개발 1년차**가, 코드·코드 설계 설명은 **3년차**가 알아듣게 쓴다.
- **짧게 쓴다.** 다 아는 내용을 다시 풀어 쓰지 않는다.
- 어려운 한자말 대신 쉬운 우리말을 쓴다. (갱신 → 고치기, 상이하다 → 다르다)
- **규칙 문서는 짧게 쓰고 상세는 다른 문서로 빼서 경로만 가리킨다.**

## 내보내기 전 검사 둘

**(가) 남의 작품 이름이 그대로 남아 있지 않은지 본다.**
`Docs/Reference/` 의 자료는 **참고일 뿐**이다. 참고한 게임·작가 이름을 기획 문서에 그대로 옮겨 적지 않는다.
가리켜야 하면 「같은 갈래의 2D 농장 게임」처럼 쓴다.

**(나) 도면을 넣었으면 검사를 돌리고 오류 0 을 확인한다.** 확인 안 했으면 안 했다고 쓴다.

## 그림이 필요하면

글로 풀지 말고 DiagramTool 을 쓴다. 규칙·검사 명령은
`Tools/DiagramTool/.claude/skills/diagram-usage/SKILL.md` (스킬 이름 `diagram-usage`).
**세션 시작 때는 목록에 안 뜬다** — `Tools/DiagramTool/README.md` 를 한 번 읽으면 그때 뜬다.
도면을 넣었으면 검사를 돌리고 오류 0 을 확인한 뒤에 보고한다.
